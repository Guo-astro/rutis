# Test certificates

Certificates the `wss://` tests in `../test_websocket.py` serve (risk E6).
Python has no certificate generator without a new dependency, so they are
generated by the Rust tests and committed. They are for tests only; the keys
protect nothing.

| File | What it is |
| --- | --- |
| `ca.pem` | the test CA (not in any system store) |
| `localhost.pem` / `.key` | for `localhost`, valid 1975–4096 |
| `expired.pem` / `.key` | for `localhost`, valid 2000-01-01 to 2001-01-01 |
| `not-yet-valid.pem` / `.key` | for `localhost`, valid 2100-01-01 to 2101-01-01 |
| `other-name.pem` / `.key` | for `other.example`, valid 1975–4096 |

The validity periods are fixed dates far from any real clock, so the tests do
not depend on when they run. Regenerate with:

```sh
cargo test -p rutis-bridge --all-features --test websocket -- --ignored regenerate_python_tls_fixtures
```

Keys change on every run, so a regenerated set never equals the committed
one byte for byte; the Python tests check what matters (each certificate is
refused with the expected OpenSSL verification code, and the valid one is
accepted).
