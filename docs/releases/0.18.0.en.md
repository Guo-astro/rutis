# rutis 0.18.0

[中文](0.18.0.md) · [0.17.2 release notes](0.17.2.en.md)

The theme of 0.18.0 is "errors you can understand" ([#694](https://github.com/arcships/rutis/issues/694), [diagnostics design](../design-diagnostics-2026-10-26.en.md)): an error says which row, what it was doing and which file and line, without rutis's internal names; a running host can be asked what it is doing; configuration is checked against its Schema and gets its defaults. This release has breaking changes: read [migrating to 0.18](../migration-0.18.en.md) before upgrading.

Upgrade in this order: run `rutis-host check` with 0.17.2 first, since the warnings it gives are errors in 0.18; after upgrading, run `rutis-host check` with 0.18, which lists every row whose configuration does not pass.

## Breaking changes

Each item says what to change; details and examples are in [migrating to 0.18](../migration-0.18.en.md).

- **Error texts change; decide by error code instead** ([#677](https://github.com/arcships/rutis/issues/677), [#711](https://github.com/arcships/rutis/pull/711), [#737](https://github.com/arcships/rutis/pull/737)). Error type names stay the same (`BindingError`, `AggregateError`, `SyncWaitCycle` and so on); the text only uses what the developer wrote: row names, service names, method names, which argument, files and lines. rutis's own `BindingError`s carry a code: `not-declared`, `unavailable`, `no-method`, `bad-argument`, `bad-value`, `peer-gone`, `bad-config`, with details in `data`.
  - To change: code that matches error texts reads the code instead (`error.code` in JavaScript and Python, `Code` of `*rutis.RemoteError` in Go, `code` in Swift and Kotlin, `session::Error::code()` in Rust); scripts that parse the errors `rutis-host` prints follow the new format.
  - Node, Bun: on an error received from another language, `error.stack` is the caller's own stack; rutis prints the far end's stack.
  - Python: an error while importing a plugin module raises the new `LoadError`; `str(SyncWaitCycle)` is just the message.
  - Kotlin: a service not in `inject`, a service not there and the host gone raise the new `NotDeclaredException`, `UnavailableException` and `HostGoneException`. They are subclasses of the types raised before, so code catching those still works.
- **Rust hosts read plugin errors differently** ([#677](https://github.com/arcships/rutis/issues/677)). A plugin's error is no longer a string: read its structure with `rutis_bridge::thrown(&error)` and print it with `rutis_bridge::report::report(&error)`. `rutis_bridge::session::Error` has a new variant `Binding { code, message, data }`; code that matches every variant adds it. `ErrorKind::PluginFailed` is displayed without the `plugin failed: ` prefix.
- **Rust embedding writes errors to standard error by default** ([#678](https://github.com/arcships/rutis/issues/678), [#741](https://github.com/arcships/rutis/pull/741)). A plugin start failure nobody waited for, or a runtime process ending, used to be only in return values nobody read; now the default error sink writes them, each line starting with the plugin, row or runtime name instead of `[rutis]`. New `ErrorKind::StartFailed`, `RuntimeDown`, `NotServedByName`; `DisposeWaitError::TimedOut` has a new field `stuck`.
  - To change: replace the sink if you do not want this output; scripts matching `[rutis]` on standard error change; code destructuring `TimedOut` with every field listed adds `..`.
- **Rust embedding: `reconcile` no longer waits for a runtime still starting** ([#743](https://github.com/arcships/rutis/pull/743)). When one runtime is stuck, the other rows start as usual and its rows wait for it. To get the full report as before, await the runtimes' `ready()` before calling `reconcile`.
- **`rutis-host` writes status lines to standard error, and under `dev` each plugin line carries its row name** ([#746](https://github.com/arcships/rutis/pull/746)). `weather: running`, `runtime py: down (…)`, `rutis-host: listening on …` and the like used to go to standard output. Under `dev`, plugin output starts with `[weather] `.
  - To change: scripts reading status lines from standard output read standard error; scripts comparing whole plugin lines add `--no-prefix-output` under `dev`. `run` has no prefix by default; `--prefix-output` turns it on.
- **`rutis-host check`: dependency cycles and services provided twice are errors** ([#676](https://github.com/arcships/rutis/issues/676), [#725](https://github.com/arcships/rutis/pull/725)). In 0.17.2 they were warnings; now `check` exits with 1.
  - To change: for rows that `inject` each other, drop the service one does not need, or move the shared part into a third row; for rows providing one service, keep one, or separate them with `isolate`.
- **Two entries accepting one token are an error at start** ([#702](https://github.com/arcships/rutis/issues/702), [#726](https://github.com/arcships/rutis/issues/726), [#724](https://github.com/arcships/rutis/pull/724), [#756](https://github.com/arcships/rutis/pull/756)). When any two entries on one listener, or two listening link rows on different listeners (disabled rows included), would accept the same token, `run`, `check` and reloading the configuration fail before starting. In 0.17 such a configuration already left one side unable to connect.
  - To change: as the message says, give one of them its own `RUTIS_TOKEN_<name>`, and have the other end present that new token.
- **An unhandled error counts only against the row that made it** ([#688](https://github.com/arcships/rutis/issues/688), [#729](https://github.com/arcships/rutis/pull/729)). An unhandled promise rejection in a Node or Bun plugin no longer ends the runtime process: when its source can be traced, that row fails; when not, one line says `an unhandled error from an unknown row`. An exception nobody retrieved from a Python task used to be only logged; now it fails the row.
  - To change: in Python, handle or retrieve the exceptions of tasks you start; Node and Bun projects that recovered by letting the runtime exit and the host restart it handle the error in the plugin instead, and call `process.exit` explicitly when the process really should end.
- **Objects with methods go to every language** ([#687](https://github.com/arcships/rutis/issues/687), [#738](https://github.com/arcships/rutis/pull/738), [#751](https://github.com/arcships/rutis/pull/751), [#753](https://github.com/arcships/rutis/pull/753), [design](../design-object-refs-2026-10-27.en.md)). They used to go only to Rust, and the call failed for other languages; now they go by reference: the receiver gets a proxy whose methods call the original object.
  - To change: code that passed data after the call failed no longer reaches its `catch`; if the receiver wants data, pass data. Both ends must be on 0.18: runtimes before 0.18 take no objects, and such a call fails with `bad-value`, saying to upgrade.
  - In Go, Swift and Kotlin, a parameter of a data type that receives an object fails with `bad-argument`. In Kotlin, a parameter of type `Any?` may receive the new `RemoteObject`. Swift code implementing `RutisProxy` by hand adds `rutisClient`.
  - `undefined` inside arrays, objects and other values is always `null` (`None` in Python). Before, `undefined` in an array passed as an argument was kept.
- **Configuration is checked against its Schema and gets its defaults** ([#669](https://github.com/arcships/rutis/issues/669), [design](../design-config-schema-2026-10-27.en.md); [#727](https://github.com/arcships/rutis/pull/727), [#740](https://github.com/arcships/rutis/pull/740), [#742](https://github.com/arcships/rutis/pull/742), [#747](https://github.com/arcships/rutis/pull/747), [#748](https://github.com/arcships/rutis/pull/748), [#750](https://github.com/arcships/rutis/pull/750)). The plugin API guide always said the host checks configuration against the Schema; this release makes it true. Rust rows, Node, Bun, Python, Swift and Kotlin fill in the Schema's defaults before `apply`; when the configuration does not pass, the row fails with the code `bad-config`, and the host prints `weather: config: city should be a string, got 42`, one line per problem. Extra keys are only a warning, and an error under `check --strict`.
  - To change: configuration that ran despite mistakes (wrong types, missing `required` fields, extra keys under `additionalProperties: false`) now fails the row, in the test tools too; fix the configuration or the Schema by what `rutis-host check` prints. Code that tests whether a key is in the configuration now sees the defaults.
  - Node, Bun: `definePlugin` throws at once when `config` is a Standard Schema object (such a Schema never took effect).
  - Swift: a `var` field with a literal initial value is no longer required; when missing, it takes the initial value.
  - Rust: loader rows' configuration errors read `config: …` instead of `config validation failed: [...]`.
  - Go fills in defaults and checks before decoding, and generated Schemas no longer have `required` ([#752](https://github.com/arcships/rutis/pull/752)).
  - Configuration docs, the Python and Go guides, the configuration section of migrating to 0.18, templates keeping defaults only in the Schema ([#754](https://github.com/arcships/rutis/pull/754)).

## New features

- **`rutis-host status`** ([#678](https://github.com/arcships/rutis/issues/678), [#739](https://github.com/arcships/rutis/pull/739)): from another terminal, ask a running `run` or `dev` what it is doing: each row's state and reason, who provides each service, the runtimes, calls not yet returned and how long they have waited. It answers while start-up is stuck too. Not available on Windows. Rust embedders get the same snapshot from `Loader::status()`.
- **Errors say where** ([#677](https://github.com/arcships/rutis/issues/677)): a failure printed by `run` or `dev` first says in which step it failed, then the row, the file and line from the plugin's language, and across languages the caller's location. Stacks sent across processes have only the plugin's own frames.
- **`rutis-host dev --debug`** ([#679](https://github.com/arcships/rutis/issues/679), [#728](https://github.com/arcships/rutis/pull/728)): Python stops at `breakpoint()` (pdb), Node and Bun open an inspector port, Go runs under Delve; `dev` first prints how to attach. Each language's guide has a new "Debugging" section. Swift is not supported yet.
- **A hint when a call blocks** ([#746](https://github.com/arcships/rutis/pull/746)): when a Node, Bun or Python service method holds the runtime synchronously for 5 seconds, the runtime prints once which row and method, and suggests making it asynchronous. It only prints; the method is not interrupted.
- **Rust embedding you can read** ([#741](https://github.com/arcships/rutis/pull/741)): `root.diagnostics()` prints directly (one item per line, by name); when `shutdown_with_timeout` runs out, it names the plugins not finished and the file and line where the stuck cleanup was registered.
- **One runtime not ready no longer holds up other runtimes' rows** ([#743](https://github.com/arcships/rutis/pull/743)): for example, while one runtime sits under a debugger without greeting, rows of the other runtimes start as usual.
- **Readable compile errors for mistakes in Rust plugins** ([#677](https://github.com/arcships/rutis/issues/677)): an argument that cannot cross languages, an error type without `Display`, a service type that is not `Send + Sync` and the like say on the first line what is wrong and how to fix it.
- **`rutis-host check` checks each row's configuration** ([#727](https://github.com/arcships/rutis/pull/727)): it gives the path and the reason and exits with 1 when a configuration does not pass; rows whose Schema is known only when they run say `config not checked`.
- **Developer-experience checks in the release gate** ([#690](https://github.com/arcships/rutis/issues/690), [#744](https://github.com/arcships/rutis/pull/744), [#758](https://github.com/arcships/rutis/pull/758)): writing a plugin in each language, assembling plugins, and the host owner's scenario, plus acceptance tests of 14 faults in each language, run in the release gate and nightly; nothing is released unless they pass ([fault acceptance table](../faults.en.md)).

## Fixes

- Waiting for a runtime's state no longer misses a change between looking and starting to wait ([#759](https://github.com/arcships/rutis/pull/759)). Under load, a runtime that became ready in that gap was taken as failing to start; `rutis-host`'s restart supervision drops its workaround of looking again every 500 ms.
- A runtime connection that dials in and drops while its rows are loading now ends its instance at once ([#779](https://github.com/arcships/rutis/pull/779)). It used to take the full 30 seconds.
- Security updates of dependencies ([#755](https://github.com/arcships/rutis/pull/755)): rustls 0.23.46, rustls-webpki 0.103.16, webpki-roots 1.0.11, tokio 1.54.1. They affect the `rutis-host` binaries this repository builds (including the ones in npm and PyPI); projects using the crates as libraries take versions from their own lock files.
- When objects with methods are forwarded between sessions, the numbers in the call chain are rebased to the receiving session's ([#760](https://github.com/arcships/rutis/pull/760)). Before, a future the host created while handling one session's call and sent to another, or a session awaiting a future that then called another session's object, sent the numbers unchanged and the other side took them as its own calls.
- Kotlin's `HostGoneException` moved to the public `arcships.rutis`, next to `NotDeclaredException` and `UnavailableException` ([#761](https://github.com/arcships/rutis/pull/761)). It used to live in the internal package `arcships.rutis.internal.peer`; code importing it from there imports it from `arcships.rutis` instead.

## Compatibility

- The formats of `rutis.json` and `rutis.dev.json` are unchanged. Configuration contents may no longer pass because of the Schema check; see "Configuration is checked against its Schema" above.
- The protocol adds the capability `objects` (objects with methods), used only when both ends declare it; error nodes gain two optional fields, `site` and `rethrown`, which older ends ignore. The protocol version is unchanged: 0.18.0 and 0.17.2 connect as usual, but objects cannot be passed to the older end.
- A 0.17.2 host does not know that 0.18 runtimes take objects: objects passed between runtimes under it still fail with 0.17.2's text; upgrade the host.
- Dylib plugins are rebuilt with the 0.18 SDK, as at every release.
- Error type names are unchanged; `rutis::Error` is still thrown as `CordisError` in other languages.
