# rutis 0.19.2

[English](0.19.2.en.md) · [0.19.1 发布说明](0.19.1.md)

0.19.2 修复 bug：会让结果出错、卡住或内存暴涨的地方。插件代码与 `rutis.json` 都不用改；下面「行为变化」一节列出所有看得到的不同，其中三处会影响现有的写法，写在最前面。

## 先看这三处

- **TypeScript / Bun 测试结束时自动卸载**（[#933](https://github.com/arcships/rutis/issues/933)、[#971](https://github.com/arcships/rutis/pull/971)）。`load` 的插件在它所在的测试结束时卸载，给的假服务撤下，失败的测试不再把服务留给下一个测试（以前下一个测试报 `llm is already provided by rutis-test`）。在一个测试里装载、留到下一个测试接着用的写法，现在第二个测试得到 `PluginTestError: the plugin is unloaded`：每个测试自己 `load`。
- **Python 测试工具的调用 30 秒时限**（#971）。被测服务的异步调用 30 秒不返回，以 `PluginTestError: greeter.hello() did not return within 30 s` 失败；以前测试一直挂着、没有输出。
- **写了不存在的运行时路径就报错**（[#935](https://github.com/arcships/rutis/issues/935)、[#974](https://github.com/arcships/rutis/pull/974)）。`runtimes.node.runtime`、`runtimes.bun.runtime` 写了不存在的路径，以前悄悄改用别处的运行时；现在 `check`、`run`、`dev`、`add` 都报 `runtimes.node.runtime names <路径>, which does not exist`（有目录没有 package.json 时报 `…, which is no npm package (it has no package.json)`）。`runtimes.py.project` 不存在时，以前报的是解释器的错，现在说是这个路径不存在。

## 内存

- **大量实例一起关闭时的内存峰值**（[#977](https://github.com/arcships/rutis/issues/977)、[#978](https://github.com/arcships/rutis/pull/978)）。每次 emit 都把这个事件的全部监听者复制一份，排队的事件各持一份；监听者随实例数增长时，峰值随实例数的平方增长。现在不带过滤器的 emit 共用按事件名缓存的一份监听者列表，没有监听者时不分配；带过滤器的 emit 与 `parallel` / `serial` / `waterfall` / `bail` 照旧每次选一遍。Dim 的测量（0.17.1，N=1000 个会话依次关闭）：关闭峰值 3.43 GB → 444 MB（等于会话运行时的活跃量）。事件的顺序、过滤、`once` / `prepend` 都不变。

## 宿主

- **装载中被驱逐的插件，`build` / `validate` / `apply` 返回错误后回到 Pending**（[#968](https://github.com/arcships/rutis/issues/968)、[#969](https://github.com/arcships/rutis/pull/969)）。插件装载时它用的服务被撤下，内核先取消这一代；以前它随后进 `Failed`，同一服务回来后也不再重试，只有 `restart()` 能救回来；现在回到 `Pending`，服务回来时重新装载一次。装载中 restart、update、dispose、关闭时，以前状态先经过一次 `Failed`（最终状态是对的），现在不再经过。取消后的 panic 仍报给错误汇集一次；插件自己取消自己的令牌、驱动没有取消时的真正失败，照旧是 `Failed`。
- **放弃的 `reconcile` 不再挡住后来的操作**（[#934](https://github.com/arcships/rutis/issues/934)、[#972](https://github.com/arcships/rutis/pull/972)）。宿主用 `timeout` 放弃一次 `reconcile`（一行的 `apply` 不返回）后，以前对别的行的 `reload`、再一次 `reconcile`、运行时重启后的重新装载都一直不返回；现在照常返回，卡住的那一行仍是 `starting`。`Loader::settled()` 仍然等每一行。

## rutis-host

- **`check --strict` 下行字段拼错、行 id 重复是错误**（#974），退出码 1；不加 `--strict` 照旧只警告。拼错的行字段给出 `did you mean`。
- **`status` / `call` 找不到宿主时写明在哪里找过**（#974）：`no rutis-host answers for <配置> at <socket 路径> (XDG_RUNTIME_DIR=<值>)`，并提示宿主作为服务运行时要在它的环境下运行这条命令。部署一节补了完整的 systemd unit 与 launchd plist。

## `rutis-host dev`

（[#938](https://github.com/arcships/rutis/issues/938)、[#976](https://github.com/arcships/rutis/pull/976)）

- Python：改了插件包里的辅助模块，现在连同包里其他模块一起重新导入（以前打印 `reloaded`，跑的仍是旧代码）；插件包以外的模块仍要重启 `dev`。
- Python：不加 `--debug` 遇到 `breakpoint()`，调用以 `RuntimeError: breakpoint() needs a terminal, and this Python runtime has none: run rutis-host dev --debug` 失败（以前是 `BdbQuit` 或 `SystemExit: 1`）；`--debug` 下用过断点后 Ctrl-C 立即退出，退出码 0（以前等满 10 秒、退出码 2）。
- Go：一个二进制里放几个插件时，项目自己是 `rutis.dev.json` 写出的那几行（横幅 `running weather, llm`）；同 id 行的 `name` 被忽略时给出警告。
- Python 项目根目录有 `package.json` 时，只有它写的入口文件真的存在才算 Node 项目。
- 重载失败、仍在运行旧版本的行，`status` 写 `running (the previous version: its last reload failed)`。
- 随一次变化重启的行，原因每行只写一次：`caller: restarted (weather reloaded)`（以前几个文件一起改时是 `restarted (weather reloaded, weather restarted)`）。

## 测试工具

- TypeScript / Bun：等插件交来的函数的结果时，进程不再被 `node --test` 当成没事可做而取消测试（[#932](https://github.com/arcships/rutis/issues/932)、[#967](https://github.com/arcships/rutis/pull/967)）。[做一个开放插件的宿主](../guide/open-host.md) 第 5 节的例子在 Linux 上因此每次失败。

## 出错信息与偶发失败

（[#965](https://github.com/arcships/rutis/issues/965)、[#975](https://github.com/arcships/rutis/pull/975)；[#922](https://github.com/arcships/rutis/issues/922)、[#970](https://github.com/arcships/rutis/pull/970)）

- 等运行时问候失败时写明原因：`the runtime's channel failed: the read of its greeting was cancelled` / `… panicked: <内容>`。
- 运行时进程退出时，对它的对象的调用总是说 `runtime <名字> exited`（以前有时说 `disconnected`）。
- 两个偶发失败的测试按根因修好（`test_command` 的 fd 接手、`waits.rs` 按耗时判断复杂度）。

## 文档

（[#939](https://github.com/arcships/rutis/issues/939)、[#973](https://github.com/arcships/rutis/pull/973)）

0.19.0 评估里要猜或与实际不符的地方：Go 的调试器版本（`dlv@v1.26.3`，Go 1.24 能装）与用 Go 写只在 dev 用的假服务；Python 项目在 `dev` 里的行 id；Rust 插件按名字使用别的语言的服务、没有配置的插件怎样注册；宿主拿到状态文字、`processes()` 的类型；rutis-host 的行字段、输出格式与哪些语言检查参数类型。

## 行为变化

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| TS / Bun 测试结束 | `load` 的插件留到 `unload` | 测试结束时自动卸载 |
| Python 测试工具的异步调用 | 不返回就一直挂着 | 30 秒后 `PluginTestError: … did not return within 30 s` |
| `runtimes.node.runtime` / `runtimes.bun.runtime` 路径不存在 | 悄悄用别处的运行时 | 报错，写明路径 |
| `check --strict`：行字段拼错、行 id 重复 | 警告，退出码 0 | 错误，退出码 1 |
| `status` / `call` 找不到宿主 | `no rutis-host runs …`（`status`）、`no rutis-host run or dev is running for …`（`call`） | 写明 socket 路径与 `XDG_RUNTIME_DIR` |
| 装载中被驱逐，`build` / `validate` / `apply` 返回错误 | `Failed`，不再重试 | 回到 `Pending`，服务回来时重新装载 |
| 装载中 restart / update / dispose / 关闭 | 先经过一次 `Failed` | 不经过 `Failed` |
| 放弃一次 `reconcile` 后的操作 | 一直不返回 | 照常返回 |
| 大量实例一起关闭（监听者随实例数增长） | 峰值随实例数的平方增长 | 随实例数线性 |
| `dev`：Python 辅助模块改了 | 打印 `reloaded`，仍是旧代码 | 重新导入 |
| `dev`：不加 `--debug` 的 `breakpoint()` | `BdbQuit` / `SystemExit: 1` | `RuntimeError: … run rutis-host dev --debug` |
| `dev --debug`：用过断点后 Ctrl-C | 等 10 秒，退出码 2 | 立即退出，退出码 0 |
| `dev`：Go 多插件二进制 | 按字母排第一的算项目自己，`name` 静默丢掉 | `rutis.dev.json` 写出的行算项目自己，丢 `name` 时警告 |
| `dev`：随一次变化重启的行 | 原因可能重复（`weather reloaded, weather restarted`） | 每行写一次 |
| 等运行时问候失败 | `the runtime's channel failed` | 后面写明取消或 panic |
| 运行时退出时对象调用的错误 | 有时 `disconnected` | 总是 `exited` |

## 兼容

- 协议不变，与 0.19.0、0.19.1 照常连接。`rutis.json`、`rutis.dev.json` 的格式不变。
- 没有新增或删除公开 API。
