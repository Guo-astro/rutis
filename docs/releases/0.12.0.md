# rutis 0.12.0（草稿）

[English](0.12.0.en.md) · [0.11.0 发布说明](0.11.0.md)

> 草稿：0.12 还没有发布，这里随合入 main 的改动逐条补充，发布前定稿。

## 新增

- **运行时状态行**（[#274](https://github.com/arcships/rutis/issues/274)，[rutis-host](../guide/rutis-host.md#run-打印什么)）：`rutis-host run`、`dev` 在本机运行时（`node`、`py`、`bun`、Go 的 `go-<二进制>`）的进程自己结束或起不来时打印 `runtime <名字>: down (<原因>)`，原因写进程怎样结束，例如 `runtime py: down (exited with signal: 9 (SIGKILL))`；它重新运行时打印 `runtime <名字>: running`。过去只能看到它的行变成 `waiting for its services`。宿主停止运行时（停止宿主、Go 运行时空闲停下）不打印。Rust 库：`rutis-loader` 新增 `GoRuntimesHandle::states`（各 Go 运行时的状态，不读二进制）。
- **运行中改配置**（[#274](https://github.com/arcships/rutis/issues/274)，[rutis-host](../guide/rutis-host.md#运行中改配置)）：`rutis-host run` 在 Unix 上收到 SIGUSR1 时重新读 `rutis.json`（systemd：`ExecReload=/bin/kill -USR1 $MAINPID`）；加 `--watch-config`（默认关闭）时文件内容变化、稳定 500 毫秒后重新读，Windows 和 Kubernetes ConfigMap 用这种方式。全有或全无：新的行先检查，替换后有新失败的行就换回旧的行；配置写错时旧配置继续运行，打印 `rutis-host: reload rejected: <原因>; nothing changed`，成功时打印 `rutis-host: reloaded <文件> (<n> rows changed)`。行的增删改直接生效，`instanced` 分组里的行对每个已有实例生效；删掉的本地运行时在它的行卸载后停止。`format`、`id`、`listen`、`runtimes.go`、`runtimes.remote`（含 `listen`、`instances`）和新增或改了设置的本地运行时改不了，拒绝并提示重启宿主。SIGHUP 仍是终止信号。凭据改为在拨号和对端连进来时从环境变量读，重新读配置新增的节点行也能连上。
- **运行时崩溃后重启**（[#274](https://github.com/arcships/rutis/issues/274)，[rutis-host](../guide/rutis-host.md#运行时结束时)）：`runtimes.node`、`runtimes.py`、`runtimes.bun` 新增可选字段 `restart`，决定运行时进程自己结束时怎么办：`"no"`（默认，和以前一样，它的行等待）、`"on-failure"`（等待后重新启动，它的行随之恢复；等待 1 秒起每次翻倍、最多 30 秒，运行满 60 秒后从 1 秒重来，5 分钟内重启 5 次后再结束就放弃并打印 `runtime <名字>: gave up after 5 restarts within 5 minutes`；数值固定，不能配置）、`"exit"`（卸载其他行后以新的退出码 3 退出，由进程管理器重启整个宿主）。`dev` 用同样的规则和默认值，`restart` 写在 `rutis.dev.json`。Go 运行时还没有这个设置。
- **运行中吊销身份**（[#273](https://github.com/arcships/rutis/issues/273)，[设计](../design-remote-runtime-dial-2026-10-14.md#五身份层)）：只在 Rust 库里，是将来的管理服务要调用的钩子。`rutis-bridge` 的 `Revocable::new(内层, revocations)` 包住一个 `Identity`（静态 link）或 `Admission`（接入点），`Revocations::revoke(&id)` / `revoke_all()` 在一切照常运行时吊销：只关闭以这个 id 接受的连接（其上进行中的调用失败一次，与断网相同），吊销前已路由的握手不再移交，之后的连接与 token 错误时一样被拒（403，接入点的 id 为关闭码 4003），拨号方按 `AuthRejected` 每 30 秒重试。其他对端、同一监听器上的其他连接、本机运行时不受影响。共享 token 的接入点吊销一个 id 只关这条连接，`revoke_all()` 等于收回 token。`Identity`、`Admission` 新增 `revocations()`，默认 `None`。rutis-host 没有对应的命令：它的 token 来自环境变量，运行中不能吊销（[连接节点](../guide/nodes.md#安全)）。

## 修复

- **监听的 link 应用后即已注册**（[#411](https://github.com/arcships/rutis/issues/411)）：`rutis-bridge` 的监听 link 过去在应用后另起的任务里才注册到监听器。同一监听器上已有接入点时，在这之前连进来的静态对端被当作不认识的凭据拒绝（403），拨号方按 `AuthRejected` 等 30 秒才重试；现在 `LinkPlugin` 应用完成时注册已在，注册失败（名字已被占用）仍是 `Stopped`。接入点按连接送达的顺序计先后：同一 id 的两个连接几乎同时送达时，过去可能把后到的算成先到。
- **Python 运行时在宿主被 `kill -9` 后一直不退出**（[#192](https://github.com/arcships/rutis/issues/192)）：宿主被强制结束、插件的清理一直不返回时，Python 运行时到截止时间（`RUTIS_SHUTDOWN_TIMEOUT`）要在 stderr 写一行再以 1 退出；stderr 是通到宿主的管道，宿主没了这一行写不出去（BrokenPipeError），进程就留了下来。现在写不出也照样退出。Unix 才有这个问题，Windows 上运行时随宿主的 Job Object 结束。

## 兼容

- **`rutis.json`**：格式仍是 1。`runtimes.node`、`runtimes.py`、`runtimes.bun` 新增可选字段 `restart`，以前的文件不用改、含义不变；用了它的文件 0.11 的 rutis-host 读不了。这三个运行时里写错字段时，错误列出的可用字段多了 `restart`。
- **退出码**：新增 3（`restart` 为 `"exit"` 的运行时结束，宿主已停止）。0、1、2 的含义不变。
- **凭据**：`rutis-host` 改为拨号和对端连进来时才读 `RUTIS_TOKEN_<节点>` / `RUTIS_TOKEN`；读到的值和以前相同（环境变量在进程内不变），只是节点行不必在启动时就存在。
