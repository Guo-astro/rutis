# rutis 0.12.0

[English](0.12.0.en.md) · [0.11.0 发布说明](0.11.0.md)

0.12.0 最主要的是服务自动跨语言对外：Node、Bun、Python、Go 插件用 `ctx.provide` 提供的服务，以及已发布的 Cordis 插件提供的服务，不用声明就能被别的语言、别的节点和 Rust 按名字使用，`provides` 变为可选；同一个 Node 运行时里的 Cordis 插件按 Cordis 自己的规则互用服务。其次，嵌入 rutis 的 Rust 应用在 `build.rs` 里列出已有的 Rust 类型，叶子插件就能直接调用它们的方法，不用手写 `HostDispatch`；Rust 服务也能知道是哪一行在调用它。第三是 `rutis-host` 的运维：运行中重新读 `rutis.json`、本机运行时崩溃后按 `restart` 重启、`run` 打印运行时的结束与恢复。另有身份层的运行中吊销钩子（Rust 库）。质量方面完成了计划的第三步：长时间浸泡、真实网络、模糊测试与并发模型、跨版本组合、两个 TLA+ 模型，以及由它们发现的一批修复。0.11 时期的插件有一处行为变化（没有声明的服务现在会对外，重名时后提供的一行失败），见下文的"兼容"。

## 新增

- **叶子插件提供的服务自动对外，`provides` 声明变为可选**（[#442](https://github.com/arcships/rutis/issues/442)，[插件 API](../guide/plugin-api.md#ctx)）：Node、Bun、Python、Go 四种 SDK 的 `ctx.provide(name, impl)` 提供的服务不用声明就投到 rutis，别的语言的插件按名字使用。方法取实现对象上的公开方法——JavaScript：自身和原型链上的函数（不含 `constructor`）；Python：不以 `_` 开头的可调用属性；Go：导出方法——都按 `async` 调用，字段不算方法。`provides` 写了仍然生效：把方法标成 `sync`、让 `rutis-host check` 在运行前知道谁提供什么；已有插件不用改。没有声明的服务在插件运行后出现，依赖它的行照常等它出现；`check` 对这类依赖写告警，不算失败（`--strict` 时算）。重名时后提供的插件失败（装载后才提供的也一样），错误写明双方：`service <名字> is already provided by <已有的一方>: row <行> cannot provide it too`。`apply` 返回前从别的线程或 goroutine 提供的服务，宿主在装载完成前就处理完，重名时装载失败。`rutis-host new` 的四种模板不再声明 `provides`，只留一句注释说明何时需要写。拨入实例（`runtimes.remote` 的 `instances`）里的行没有声明的服务只在该实例内可见（[连接节点](../guide/nodes.md#连进来的运行时)）。测试工具（`@arcships/rutis/testing`，Bun 下同一个；`rutis.testing`；Go 的 `rutistest`）同样不再要求声明，`service(name)` 按推断的方法调用，新增 `methods(name)`（Go：`Service.Methods()`）返回 rutis 看到的方法。
- **已发布的 Cordis 插件按原生规则互用服务，提供的服务自动投到 rutis**（[#428](https://github.com/arcships/rutis/issues/428)，[Cordis](../guide/cordis.md)）：`rutis.json` 里挂载的 Cordis 包（已发布、没有 `rutis.provides` 的也一样）在同一个 Node 运行时里按 Cordis 的规则互相使用服务，拿到对象本身；过去依赖别的行的行一直停在 `waiting for its services`。它们提供的服务不用声明就投到 rutis，别的运行时、节点和 Rust 按名字使用，方法取服务对象上的函数（自身和原型链上的，不含 `constructor`），按 `async` 调用；包里写了 `rutis.provides` 时按声明。重名的规则与叶子插件相同。`rutis-host check` 对只可能由这类行提供的服务写告警 `warning: <行>: nothing declares <服务>; it may be provided at runtime by <行>, …`，不再报 `cannot run: nothing provides …`；这一行和可能提供它的行里有 Cordis 行时再补 `; between Cordis rows of one runtime it resolves in Cordis`。Rust 库：`rutis-bridge` 新增 `row_projection_of`、`ServiceEvents::announced`、`Projection::on_announced` / `service_keyed_occupied` / `take_refused` / `on_refused`、`HostDispatch::provider`、`RowService::provided_by`、`RowSchema::announces` / `cordis`；`rutis-loader` 新增 `Declared::announces`、`Supply::Announced`。
- **行直接使用已有的 Rust 服务，不写绑定**（[#440](https://github.com/arcships/rutis/issues/440)，[在 Rust 应用里嵌入](../guide/rust-host.md#导出已有的-rust-服务)，[导出服务参考](../guide/rust-host.md#导出服务参考)）：应用在 `build.rs` 里写出要导出的类型，`rutis_bridge::build::Exports::new().service("calendar", "calendar_services::Calendar").service_in("notes", "calendar_services::Notes", "session").generate()`，可以是依赖 crate 的类型（用 `cargo metadata` 找到源码，用 syn 读，跟随再导出、别名和 `#[cfg]`；稳定版 Rust）。构建时为每个类型的公开 `&self` 方法生成 dispatcher，并从 Rust 定义生成 TypeScript 声明（serde 结构体和枚举按 serde 写出的样子，`Services`、`RustError`、每个错误类型一个 `<Name>Thrown`；能通过 `tsc --strict`）；`rutis_bridge::include_exports!()` 声明模块，`ServiceCatalog::export_all(exports::all())` 登记：TypeScript、Python 或 Go 的行在 `inject` 里写这个名字就能调用方法，都是 `async`。参数和返回值可以是任意 serde 类型（超出 ±(2^53−1) 的整数为 bigint）；函数参数（`impl Fn(..) -> BoxFuture<'static, Result<..>>`、`Arc<dyn Fn ..>`）按引用接收调用方的函数，它的 Promise settle 之后原生一侧才继续，它抛错即原生失败；`&Ctx` 参数是调用方那一行的上下文，方法在上面登记的东西随该行移除；`.service_in` 导出在实例组的每个实例里。`Err(e)` 在调用方语言里作为带 `name`（类型）、`code`（变体）、`message`（`Display`）和 `data`（serde 值）的错误抛出，不是未分类的调用错误。绑定不了的方法被跳过，构建警告写明原因。示例：`examples/rust-services`。Rust 库：`rutis-bridge` 新增模块 `exports`（`Export`、`ExportPlugin`、`include_exports!`），以及新 feature `exports`（`cordis` 会开启它）下的 `build::Exports`；`rutis-loader` 新增 `ServiceCatalog::export`、`export_all`、`share_registered_only`。
- **错误带 `code` 和 `data`**（[#440](https://github.com/arcships/rutis/issues/440)，[插件 API](../guide/plugin-api.md#值怎样传递)）：任何语言抛出的错误都能带上代码和数据，放在错误图里，与 `name`、`message` 并列：JavaScript 错误的字符串属性 `code` 和属性 `data`、Python 异常的字符串属性 `code` 和属性 `data`、Go 错误的 `Code() string` 和 `Data() any`、Rust 的 `exports::failure`。接收方读到的是 `code`、`data`（Go：`Code`、`Data`；Rust：`Error::code()`、`Error::data()`），再抛出时随之传下去；传不过去的 data 被略去，错误的其余部分照常传。Python 的 `RemoteError` 新增属性 `code`、`data`（没有时为 `None`），Go 的 `RemoteError` 新增字段 `Code`、`Data`；Rust 的 `session::Error` 新增 `code()`、`data()`。
- **Rust 服务能知道是哪一行在调用它**（[#441](https://github.com/arcships/rutis/issues/441)，[在 Rust 应用里嵌入](../guide/rust-host.md#调用方的行)）：只在 Rust 库里。`HostDispatch::invoke` 期间，`rutis_bridge::session::caller_row()` 返回调用方的行 `CallerRow`：`id()`（loader 的行 id）、`key()`（在运行时里的 key）、`scope()`（这一行隔离该服务所用的标签，在实例里是实例的）、`instance()` 和 `ctx()`。同一个运行时的两行是两个调用方；注册在 `ctx()` 上的效应在这一行卸载或重启时撤掉，运行时照常运行。来自 Rust、来自对端节点、或运行时里不属于任何行的调用返回 `None`。Node、Bun、Python、Go 的行都可以用，0.11 的运行时也可以：线上格式没变，每一行租用的服务注册在它自己的作用域里。`rutis-bridge` 新增 `Process::lease_host_for` 和 `HostLease::label`。
- **运行中改配置**（[#274](https://github.com/arcships/rutis/issues/274)，[rutis-host](../guide/rutis-host.md#运行中改配置)）：`rutis-host run` 在 Unix 上收到 SIGUSR1 时重新读 `rutis.json`（systemd：`ExecReload=/bin/kill -USR1 $MAINPID`）；加 `--watch-config`（默认关闭）时文件内容变化、稳定 500 毫秒后重新读，Windows 和 Kubernetes ConfigMap 用这种方式。全有或全无：新的行先检查，替换后有新失败的行就换回旧的行；配置写错时旧配置继续运行，打印 `rutis-host: reload rejected: <原因>; nothing changed`，成功时打印 `rutis-host: reloaded <文件> (<n> rows changed)`。行的增删改直接生效，`instanced` 分组里的行对每个已有实例生效；删掉的本地运行时在它的行卸载后停止。`format`、`id`、`listen`、`runtimes.go`、`runtimes.remote`（含 `listen`、`instances`）和新增或改了设置的本地运行时改不了，拒绝并提示重启宿主。SIGHUP 仍是终止信号。凭据改为在拨号和对端连进来时从环境变量读，重新读配置新增的节点行也能连上。
- **运行时崩溃后重启**（[#274](https://github.com/arcships/rutis/issues/274)，[rutis-host](../guide/rutis-host.md#运行时结束时)）：`runtimes.node`、`runtimes.py`、`runtimes.bun` 新增可选字段 `restart`，决定运行时进程自己结束时怎么办：`"no"`（默认，和以前一样，它的行等待）、`"on-failure"`（等待后重新启动，它的行随之恢复；等待 1 秒起每次翻倍、最多 30 秒，运行满 60 秒后从 1 秒重来，5 分钟内重启 5 次后再结束就放弃并打印 `runtime <名字>: gave up after 5 restarts within 5 minutes`；数值固定，不能配置）、`"exit"`（卸载其他行后以新的退出码 3 退出，由进程管理器重启整个宿主）。`dev` 用同样的规则和默认值，`restart` 写在 `rutis.dev.json`。Go 运行时还没有这个设置。
- **运行时状态行**（[#274](https://github.com/arcships/rutis/issues/274)，[rutis-host](../guide/rutis-host.md#run-打印什么)）：`rutis-host run`、`dev` 在本机运行时（`node`、`py`、`bun`、Go 的 `go-<二进制>`）的进程自己结束或起不来时打印 `runtime <名字>: down (<原因>)`，原因写进程怎样结束，例如 `runtime py: down (exited with signal: 9 (SIGKILL))`；它重新运行时打印 `runtime <名字>: running`。过去只能看到它的行变成 `waiting for its services`。宿主停止运行时（停止宿主、Go 运行时空闲停下）不打印。Rust 库：`rutis-loader` 新增 `GoRuntimesHandle::states`（各 Go 运行时的状态，不读二进制）。
- **运行中吊销身份**（[#273](https://github.com/arcships/rutis/issues/273)，[设计](../design-remote-runtime-dial-2026-10-14.md#五身份层)）：只在 Rust 库里，是将来的管理服务要调用的钩子。`rutis-bridge` 的 `Revocable::new(内层, revocations)` 包住一个 `Identity`（静态 link）或 `Admission`（接入点），`Revocations::revoke(&id)` / `revoke_all()` 在一切照常运行时吊销：只关闭以这个 id 接受的连接（其上进行中的调用失败一次，与断网相同），吊销前已路由的握手不再移交，之后的连接与 token 错误时一样被拒（403，接入点的 id 为关闭码 4003），拨号方按 `AuthRejected` 每 30 秒重试。其他对端、同一监听器上的其他连接、本机运行时不受影响。共享 token 的接入点吊销一个 id 只关这条连接，`revoke_all()` 等于收回 token。`Identity`、`Admission` 新增 `revocations()`，默认 `None`。rutis-host 没有对应的命令：它的 token 来自环境变量，运行中不能吊销（[连接节点](../guide/nodes.md#安全)）。

## 修复

- **被拒的调用没有占用调用号**（[#407](https://github.com/arcships/rutis/issues/407)）：对端的调用在解码参数时被拒（只让这次调用失败、会话继续）时，过去没有记下它的调用号，对端之后用同一个 id 重发会被当作新调用执行。现在被拒的调用和完成的调用一样占用调用号，同 id 重发按 `invalid or repeated invocation identity` 关闭会话。
- **原生生成器把插件自己的同名类型当成值类型**（[#408](https://github.com/arcships/rutis/issues/408)）：`rutis_plugin` 生成器过去按短名认 `Instant`、`BigInt`、`Bytes`、`ValueMap`、`ValueSet`，插件自己的 `type Instant = String` 会被声明成 `Date`。现在按源文件的 `use` 和完整路径还原类型，只认 rutis-bridge 导出的那些；插件自己的同名类型、`std::time::Instant` 按 `type binding not implemented` 报错，不再声明成错的类型。能编译的写法（`use` 后写短名、glob、模块前缀、完整路径）照常识别。
- **Map、Set 里的 NaN 和 ±Inf 变成 `null`**（[#409](https://github.com/arcships/rutis/issues/409)）：生成器的检查过去只看 `f64` 字段和 `Vec`，`ValueMap<String, f64>` 里的 NaN / ±Inf 经 serde 静默变成 `null`。现在 Map 的键和值、Set 的元素在任意嵌套下都检查，报与结构体字段相同的 `non-finite number`。
- **监听的 link 应用后即已注册**（[#411](https://github.com/arcships/rutis/issues/411)）：`rutis-bridge` 的监听 link 过去在应用后另起的任务里才注册到监听器。同一监听器上已有接入点时，在这之前连进来的静态对端被当作不认识的凭据拒绝（403），拨号方按 `AuthRejected` 等 30 秒才重试；现在 `LinkPlugin` 应用完成时注册已在，注册失败（名字已被占用）仍是 `Stopped`。接入点按连接送达的顺序计先后：同一 id 的两个连接几乎同时送达时，过去可能把后到的算成先到。
- **同时登记的功能族被宣告成两次提供**（[#435](https://github.com/arcships/rutis/issues/435)）：`rutis-bridge` 的 `Peer::register` 先放入族的处理者、再另取一把锁记下这次提供的编号（`since`）；别的功能（另一线程）恰在两步之间登记时，它的宣告里这个族已经在、编号却还没有，按 0 发出，随后才是真正的编号。对端看来这个族被重新提供了一次：`peer:` 行随之重启，正在应用的行可能读不到刚撤下的 `PeerRows` 而停在失败。只在一端同时登记两个以上的族时出现（如同一个 link 既开宿主又导入服务）。现在编号和处理者一起放入，宣告里的族总带着自己的编号。
- **依赖在应用前被撤下的插件停在失败**（[#438](https://github.com/arcships/rutis/issues/438)）：插件的依赖已就绪、`apply` 已排上，运行前依赖被撤下时，`apply` 用 `require` / `require_as` 读它、原样返回读取的错误（`require(..)?`）会让插件停在 Failed；同一个提供者再提供时依赖没有换代，插件也不重试。宿主真的关闭或重开的那一刻，`peer:` 行读 `PeerRows` 会遇到这种情况，Node、Python、Bun、Go 的行读各自运行时的服务也一样。现在内核把这个错误与 `InjectUnsatisfied` 同样对待：这一代读取依赖确实失败过时插件回到等待，依赖回来后照常装载。
- **反复创建、关闭实例时嵌入应用的内存增长**（[#430](https://github.com/arcships/rutis/pull/430)，S7 发现）：`rutis-bridge` 的 `Projection::attach` 为每个语言行起一个等运行时会话结束的任务，活到会话结束，每加载一次行留一个；`Process` 的导出槽表在行卸载后留着撤销记录，实例作用域每个实例留一条。多租户应用反复创建、关闭租户时每轮多约 1.4 KiB。现在任务在投影关闭或被丢弃时结束，撤销记录随行删除。
- **Python 运行时在宿主被 `kill -9` 后一直不退出**（[#431](https://github.com/arcships/rutis/pull/431)，S8 发现）：宿主被强制结束、插件的清理一直不返回时，Python 运行时到截止时间（`RUTIS_SHUTDOWN_TIMEOUT`）要在 stderr 写一行再以 1 退出；stderr 是通到宿主的管道，宿主没了这一行写不出去（BrokenPipeError），进程就留了下来。现在写不出也照样退出。Unix 才有这个问题，Windows 上运行时随宿主的 Job Object 结束。
- **Python `listen:` 运行时连着控制方时 Ctrl-C 不退出、SIGTERM 不清理**（[#433](https://github.com/arcships/rutis/pull/433)，S5 发现）：`python -m rutis listen:…` 在控制方连着时收到 Ctrl-C，事件循环关闭时等着阻塞在 accept 和连接上的线程，进程不退出；SIGTERM 直接杀死进程，行的清理不运行。现在和 `dial:` 一样：卸载全部行、关闭连接和监听，以 0 退出。
- **Python 运行时 `listen:` 的会话因断网结束时打印 traceback**（[#434](https://github.com/arcships/rutis/issues/434)，[连接节点](../guide/nodes.md#别的机器上的语言运行时)）：控制方因断网心跳超时、连接被重置时，节点的 stderr 上过去是 websockets 库的日志和完整 traceback。现在打印一行 `rutis: session ended (<原因>); waiting for a controller`，例如 `rutis: session ended (heartbeat timeout); waiting for a controller`；被新连接接替时打印 `rutis: session ended (replaced by a new connection)`。断网、心跳超时、对端关闭不再打印 websockets 的日志，其他意外错误仍带 traceback 打印（以 `rutis: websockets:` 开头）。`dial:` 的状态行里，心跳超时的原因也从 `closed (1011): keepalive ping timeout` 改为 `heartbeat timeout`。
- **握手期间被吊销的对端仍建立了会话**（[#432](https://github.com/arcships/rutis/pull/432)，TLA+ 模型发现）：两处。link 握手期间远端被吊销时，过去先提供 Peer、报告 Ready 再切断，依赖 Peer 的插件可能已开始装载行；接入点上同一 id 的新连接已通过准入、等待接管时 id 被吊销，过去仍先接受再切断。现在 link 在提供 Peer 前检查吊销（监听一侧以关闭码 4003 拒绝），接入点在接受前检查。
- **重新读配置删掉运行时时等错了进程**（[#450](https://github.com/arcships/rutis/pull/450)，[rutis-host](../guide/rutis-host.md#运行中改配置)）：删掉的本地运行时停下后，等的是它自己的进程（监护在这时重启出的也算），不再是停之前任意一个进程：已经停掉的运行时不再空等 15 秒并误报没有结束，别的运行时恰好结束也不会让它提前说已停。Rust 库：`rutis-bridge` 新增 `transport::local::Processes`、`LocalTransport::sharing` / `processes`、`LocalRuntime::processes`。
- **过期的重名拒绝让之后的重启失败**（[#450](https://github.com/arcships/rutis/pull/450)）：装载后才提供、因重名被拒的行，只在这次拒绝引起的那次重启里失败；之后的重启（重名早已不在时）照常运行。
- **Python 线程里提供的服务漏过重新读配置**（[#450](https://github.com/arcships/rutis/pull/450)，[插件 API](../guide/plugin-api.md#ctx)）：`apply` 返回前从别的线程 `ctx.provide` 的未声明服务，现在也等宿主处理完才回复装载；重名时装载失败，重新读配置因而整体拒绝、旧的行照常运行。Go 原本如此，Node、Bun 是单线程。
- **TypeScript SDK 的声明在不开 `skipLibCheck` 时通不过 `tsc --strict`**（[#440](https://github.com/arcships/rutis/issues/440)）：`@arcships/rutis` 的 `Plugin` 继承了两个对 `inject`、`provides` 声明不同的类型（TS2320）。现在只从其中一个取，类型不变。

## 兼容

- **插件 API 与协议**：插件 API 版本仍是 2，协议版本不变（本地会话协议 2，带 endpoint 身份的会话协议 3）。新增的都经过协商，两端都是 0.12 时才启用：`mount` 参数的 `announce` 和回复 `features` 里的 `rows.announce`，`service` 通知对没有声明的服务带第四个参数 `{ row, methods }`，`rows.schema` 回复和 Go 清单的插件条目新增 `announces`，Cordis 插件另有 `cordis`。按行租用（Rust 服务看到调用方的行）只用作用域标签，线上格式没变，0.11 的运行时也可以。错误的 `code`、`data` 放在错误图里，0.11 的运行时和宿主照旧只拿到名字和消息。
- **0.11 时期插件的行为变化**：没有声明的 `ctx.provide` 过去在 Go 里 panic（`Provides does not declare it`）、在别的运行时只在本进程可见、在测试工具里 `service(name)` 报 "not declared in provides"；现在都投到 rutis。所以一个插件在本进程里提供的名字与别的提供者（任何语言、任何节点）重名时，后提供的一行现在会失败：改名，或在这一行的 `isolate` 里写这个名字，让它留在这一行的作用域里。
- **`check` 的告警与 `--strict`**（[rutis-host](../guide/rutis-host.md#检查配置)）：0.12 的四种 SDK 写的插件一律报 `announces: true`（声明了 `provides` 也一样，声明的名字仍算作提供者），Python、Bun 的模块式插件没有写 `provides` 时也是，没有声明 `rutis.provides` 的 Cordis 行也是。一个依赖没有行声明、但有这样的行时，过去是 `cannot run: nothing provides …` 并以 1 退出，现在在 stderr 写 `rutis-host: warning: <行>: nothing declares <服务>; it may be provided at runtime by <行>, …`，以 0 退出。因此在有这类行的项目里，`inject` 里写错的名字也只是告警；CI 里请用新增的 `check --strict`，它把这些告警当作错误、以 1 退出。没有任何行可能提供时仍是错误。0.11 的 SDK 写的插件没有 `announces` 标记，`check` 把它的声明当作它提供的全部。
- **运行时包与 rutis-host 一起升级**：0.11 的运行时在 0.12 的宿主下仍按声明，没有声明的服务只在本进程可见；0.12 的运行时在 0.11 的宿主下也不投出没有声明的服务，插件提供这样的服务时，运行时（Node、Bun、Python、Go）按名字在 stderr 提示一次 `rutis: service <名字> is not declared in provides, and this host (older than 0.12) does not take undeclared services; declare it or upgrade rutis-host`。
- **推断的方法因语言而异**：没有声明时 rutis 看到的方法按各语言的规则推断（JavaScript 含原型链上的函数，所以继承 `EventEmitter` 的类也会带上 `on`、`emit` 等；Python 是公开的可调用属性；Go 是导出方法），同一个服务用两种语言写时方法可能不同，要固定就在 `provides` 里列出。Python 用类声明 `provides`（`provides={"weather": Weather}`）时方法照旧只有 `async def` 是 `async`、其余是 `sync`，而没有声明、推断出的方法都是 `async`；为了兼容 0.11 的写法没有改。
- **错误带 `code`、`data`**：JavaScript 错误的字符串属性 `code` 和属性 `data` 过去不跨进程，现在随错误传到对端；接收方的错误对象上会出现这两个属性（Python 的 `RemoteError` 上它们没有时为 `None`）。
- **`rutis.json`**：格式仍是 1。`runtimes.node`、`runtimes.py`、`runtimes.bun` 新增可选字段 `restart`，以前的文件不用改、含义不变；用了它的文件 0.11 的 rutis-host 读不了（报未知字段）。这三个运行时里写错字段时，错误列出的可用字段多了 `restart`。
- **退出码**：新增 3（`restart` 为 `"exit"` 的运行时结束，宿主已停止）。0、1、2 的含义不变。
- **凭据**：`rutis-host` 改为拨号和对端连进来时才读 `RUTIS_TOKEN_<节点>` / `RUTIS_TOKEN`；读到的值和以前相同（环境变量在进程内不变），只是节点行不必在启动时就存在。
- **Rust API**（`cargo semver-checks` 对 v0.11.0）：
  - `rutis-loader`：`ServiceCatalog::new()` / `default()` 现在按名字共享所有没有另行登记的名字，与 rutis-host 的 catalog（`share_by_name`）一直以来的做法相同。有了 #428，只有 rutis 一侧有提供者的名字才由 rutis 门控行，Cordis 行不会因此互相等待。嵌入应用可能看到的不同：行 `inject` 一个谁都没登记的名字时会等它（原来是 `UnknownService`），Cordis 行 `inject` 的名字和叶子行一样由 rutis 门控。要原来的行为用 `ServiceCatalog::share_registered_only()`；`share_by_name()` 保留（现在就是默认）。
  - `rutis-loader`：`Declared` 新增公开字段 `announces`；`rutis-bridge`：`runtime::RowSchema` 新增公开字段 `announces`、`cordis`；`rutis-host`：`config::NodeRuntime`、`BunRuntime`、`PythonRuntime` 新增公开字段 `restart`。用结构体字面量构造它们的代码要补上这些字段（或用 `..Default::default()`）。
  - `rutis-host`：`status::follow` 改为接收一个 `status::Followed`，`Shown::changes` 改为接收 `&Followed`（过去都是 loader 和 `PeerResolver` 两个参数）。
  - `rutis` 没有变化；其余是新增，见上文各条。
- **dylib**：dylib 插件要用 0.12.0 的 SDK 重新编译。
- **最低版本不变**：Rust 1.88，Node 22，Python 3.10，Bun 1.4，Go 1.24。

## 已知问题

- Go 运行时还没有 `restart` 设置：崩溃的 Go 运行时停在 `down`，它的二进制改变后有行用到它时才重新启动。
- 与 0.11 相同：Bun 分不清"服务端证书不受信任"和其他 TLS 握手失败，Bun 拨出时 TLS 握手失败一律按认证失败处理，每 30 秒重试；Windows 上的 Node 拨出靠控制台把 Ctrl-C 一并发给子进程来停止，没有在 Windows 上实测。
