# rutis 0.15.1

[中文](0.15.1.md) · [0.15.0 release notes](0.15.0.en.md)

0.15.1 makes events one flat bus again, as in Cordis ([#604](https://github.com/arcships/rutis/issues/604), [#605](https://github.com/arcships/rutis/issues/605)): every listener of a name on a root's bus receives the event, whatever its instance, runtime or linked node. Scopes, runtimes and nodes remain descriptors for `filter`, not delivery rules. `Process::emit` → `parallel` now has the meaning the 0.13 migration guide states.

## Fixes

- **Events are delivered by name everywhere.** A parent row's emission reaches a child row's listener; a sibling instance's listener receives it too. The Rust kernel, the Node, Bun, Python, Go, Swift and Kotlin fast paths, the testing tools, the node links and the conformance expectations follow the same rule. A row that relied on scope isolation uses `ctx.events().filter(..)` on `ListenerInfo::scope`, or a distinct event name.
- **Node links carry only their own entries, gated by `export` / `import`.** A link inside an instance announces the root's entries and the root hears what it accepts. Imported entries are not relayed, so events still travel one hop.
- **Order and failures:** listeners run in registration order; `parallel` aggregates failures in registration order, and `emit` reports them where they run and returns at once.

## Deprecated, kept for source compatibility

- `rutis::events::Dispatch::scope` is still there and ignored: delivery is by name, and the dispatch names the row it is for.
- The scope helpers `scope_contains` (Rust), `inScope` (Node/Bun), `within` (Python, Kotlin, Swift) and `events.Within` (Go) remain: they are descriptor predicates for filters, not a delivery rule.
- The testing tools' emitter scope stays accepted and is ignored: Node's `h.at(scope)` and Python's `Bus.emitter(scope)`. A row's `scope` argument to `load` still sets its listeners' descriptors.

## Compatibility

- The event wire format is unchanged: 0.15.0 and 0.15.1 hosts and runtimes connect and exchange events. An end still on 0.15.0 keeps its scope filtering on its own side, so upgrade every end to get flat delivery everywhere.
- The `events/scope` and `events/hub-scope` guarantees are withdrawn; `events/flat` and `events/hub-flat` replace them.
- See [migrating to 0.15.1](../migration-0.15.1.en.md).
