# rutis 0.13.0

[English](0.13.0.en.md) · [0.12.1 发布说明](0.12.1.md)

0.13.0 最主要的是统一的事件（[#464](https://github.com/arcships/rutis/issues/464)）：一个宿主上的全部监听器——Rust 插件的、Node / Bun / Python / Go 叶子插件的、Cordis 插件的、远程运行时和相连节点上的——组成一个逻辑总线，`emit`、`parallel`、`serial`、`waterfall`、同步 `bail` 五种方式处处同义，事件在哪里发出、监听器在哪里，结果都和所有监听器在同一个进程里一样。这一版不保留旧的事件行为，也不与 0.12 及更早的运行时、节点混用，见下文的"兼容"与 [迁移到 0.13](../migration-0.13.md)。

## 新增

- **统一的事件：一个逻辑总线**（[#464](https://github.com/arcships/rutis/issues/464)，[设计](../design-events-2026-10-18.md)，[协议规格](../design-events-protocol-2026-10-18.md)，[插件 API](../guide/plugin-api.md#事件)）：插件照常写 `ctx.on(name, listener)`，监听器自动登记给宿主，什么都不用声明；任何语言、任何进程、任何相连节点发出的事件都按同一套规则到达它。一个名字的监听器都在发出方的进程里时在本进程分发，不经过宿主，结果相同。取代 #340、#358、#359 的草稿与 `requirements-protocol-plugins` §5 的事件边界规则 2–5。
- **五种方式，各语言都有**：`emit`（立即返回；监听器出错只在它所在的一侧报告一行，不影响发出方和其他监听器）、`parallel`（等全部；失败为 `AggregateError`，按登记顺序）、`serial`（第一个结果）、`waterfall`（中间件：每个监听器的最后一个参数是 `next`，`next` 可以是另一个进程里的函数）、同步的 `bail`（别处的监听器作为同步调用执行，参加等待环检测；遇到异步监听器以 `AsyncListener` 失败）。Rust 另有 `waterfall_sync`。写法是各语言自己的：Node / Bun 叶子插件 `ctx.emit` / `await ctx.parallel` / `await ctx.serial` / `ctx.waterfall` / `ctx.bail`，Cordis 插件就是 Cordis 自己的 API，Python `ctx.emit` / `await ctx.parallel` / `await ctx.serial` / `await ctx.waterfall` / `ctx.bail`，Go `ctx.Emit` / `Parallel` / `Serial` / `Waterfall` / `Bail`，Rust `ctx.events()` 上的同名方法。
- **作用域**：事件的作用域是发出方所在的加载器实例；监听器收到自己作用域及其内发出的事件，收不到旁边实例的（修掉了实例之间串台）。Rust 新增 `Ctx::scope()`、`Ctx::mark_scope`、`Ctx::mark_row`；Go 新增 `ctx.Scope()`。
- **过滤**：`filter(keep)`（Rust `ctx.events().filter`、Node / Bun / Python `ctx.filter`、Go `ctx.Filter`）在发出方的进程里、任何监听器开始之前，对每个候选监听器的描述（插件、行、运行时、节点、作用域链）求一次；Cordis 的 `Context.filter` 接到同一个机制，每个 Context 新增只读的 `ctx.rutis`。监听器选项 `prepend` 与 `global`（不受过滤）所有语言都有。
- **生命周期一致**：卸载时这一行的监听器先撤下，正在运行的收到取消信号（Go context、Python 任务取消、JavaScript `ctx.signal`、Rust `ctx.cancelled()`）并被等待，最多 `RUTIS_SHUTDOWN_TIMEOUT`。运行时进程或节点断开时它的监听器离开总线，进行中的调用失败一次（`BindingError`）。
- **框架事件 `rutis/*`**：宿主发布 `rutis/service`（服务出现、替换、撤下）、`rutis/row`（行的状态）、`rutis/runtime`（运行时运行或结束），各语言的插件都可以监听；插件发出 `rutis/*` 以 `ReservedEvent` 失败。Rust 类型：`rutis_loader::RowEvent`、`rutis_bridge::events::{ServiceEvent, RuntimeEvent}`。
- **节点之间的事件与本机相同**（[连接节点](../guide/nodes.md#节点之间的事件)）：节点行的 `export` / `import` 同时选择事件，一项可以是以 `*` 结尾的前缀；对端的监听器是本节点总线上的条目，五种方式、作用域、过滤与全部值类型都可用（以前一律当作 `parallel`、只能 JSON）。事件只走一跳。
- **值**：事件的参数与结果按调用的规则跨边界：十种值、函数与对象的引用、64 层上限。Rust 的类型化事件以 `Event::NAME` 作为跨语言的名字，参数按 serde 编解码（元组结构体的每个字段一个参数）；按名字带任意参数用 `rutis_bridge::events::Args`。
- **测试工具**：`@arcships/rutis/testing`（`load`，以及几个插件共享一条总线的 `host()`）、`rutis.testing`（`load(..., bus=, scope=)`、`Bus`）、Go 的 `rutistest`（`loaded.On`、`rutistest.InScope`）提供同样的五种方式、过滤、作用域、卸载等待与取消；真实运行时与测试工具对同一份事件期望文件（`events.expected.json`）比对。
- **插件 API 3**：多了 `parallel`、`serial`、`waterfall`、`bail` 与 `filter`。

## 测试与质量

- **跨版本相遇改为验证拒绝**（`events/old-peer-refused`）：发布门的跨版本测试（`tests/e2e/tests/cross_version.rs`）与 0.12.1 相遇，当前宿主下的旧 Node、Bun、Python 运行时与旧 Go SDK 构建的二进制、当前宿主拨号的旧 Python 远程运行时、旧宿主下的当前运行时、新旧节点任一方拨号，都在握手之后、加载之前被拒绝，说明升级哪一端，不重试、不挂起。从 0.13.1 起上一版本也声明 `events-v2`，相遇恢复为正常工作（`bridge/cross-version-meetings`）。
- **发布后验证等全部 npm 包**（[#457](https://github.com/arcships/rutis/issues/457)）：等注册表能取到这个版本时，等 `node scripts/train.mjs --npm` 列出的每个 npm 包，`@arcships/rutis-bun`、`@arcships/rutis`、`@arcships/rutis-runtime` 也在内（0.12.0 的发布后验证曾因 `@arcships/rutis-bun` 还取不到而失败一次）。

## 兼容

不保留旧行为，也没有向后兼容的路径。逐项的改写见 [迁移到 0.13](../migration-0.13.md)。

- **与 0.12 及更早的端混用被拒绝**：每个 0.13 端在握手里声明必需的能力 `events-v2`；0.12 及更早的运行时、远程运行时、接入的运行时或节点在加载任何东西之前被拒绝：`incompatible session: the far end (<name> <version>) does not declare events-v2 (the event protocol of rutis 0.13): upgrade it to rutis 0.13 or later`。节点连接停在 `incompatible`，不重试。0.13 的运行时遇到旧宿主以状态 1 退出：`rutis: refused: incompatible (this host does not declare events-v2 (the event protocol of rutis 0.13): upgrade rutis-host to 0.13 or later); stopping`。rutis-host、各运行时包和每个相连节点要一起升级。会话协议版本不变（compat 2、endpoint 3、`rutis.3`）。
- **插件 API 3**：0.13 的运行时仍加载 API 2 的插件；API 3 的插件被旧运行时以现有的信息拒绝。
- **删除的配置与 API**（写了就报错，错误给出替代写法）：
  - Rust（`rutis-bridge`）：`RuntimePlugin::emits`、`LocalRuntime::emits`、`Mount.emits`、`Mount.events`（`EventSink`）、`Process::emit`、`runtime::events::{Events, EmitToCordis}`、节点的 `EventsPlugin`、`NodeEvent`、`node_event`、`Features { outbound, inbound }`；`cordis::build` 的 `.event` / `.emit`；`runtime::testing::weather_emits`。签名变了的：`Mount` 新增 `ctx`（不设时运行时的事件只留在它的进程里）与 `runtime`，`Process::load_row` / `load_row_exporting` 末尾新增 `scope`，`runtime::testing::runtime` 开头新增 `ctx`。
  - Rust 内核（`rutis`）：`on_waterfall*`、`on_waterfall_sync*`、`WaterfallListener`、`SyncWaterfallListener`、`PatternWaterfallListener`、`SyncPatternWaterfallListener`、`Next`、`SyncNext`、`SyncEvent`、`EventKey::instance`、所有 `*_instance` 与 `*_keyed` 方法、`EventPattern::any_prefix`、`EventPattern::prefixes`、`EventKey::instance_id`、`ListenerKind::{AsyncWaterfall, SyncWaterfall}`、`CordisError::ReentrantEvent`（同名的同步分发可以重入）。监听器 trait 的 `call` 末尾多了 `Call` / `SyncCall`；`EventSubscription` 的字段改为按名字（见迁移说明）。`Event` 要求 `Serialize + DeserializeOwned`；监听器统一为 `on(ctx, key, |ctx, e, call| ..)` / `on_sync`；`serial` 取 `Arc<E>`；`waterfall` 与 `Terminal` 返回 `Option`。
  - Cordis 挂载清单与生成器的 `events`、`emits`：`the config field <events|emits> was removed in rutis 0.13: listeners register themselves; emit with ctx.emit / parallel / serial / waterfall / bail (https://github.com/arcships/rutis/blob/main/docs/migration-0.13.md)`。
  - 节点行的 `events: { out, in }`：`the peer config field events was removed in rutis 0.13: list events: { out } in export and events: { in } in import (https://github.com/arcships/rutis/blob/main/docs/migration-0.13.md)`。`rutis.json` 里还写着它的旧文件，`rutis-host check` 与启动都拒绝，信息就是这一条；`format` 仍是 1，没写它的旧文件照常读出（持久化样本 `rejected/peer-events/` 记下这个拒绝）。Cordis 应用作为节点时，`Events` 写着 `out` / `in` 报 `the Events options out / in were removed in rutis 0.13: use export / import (https://github.com/arcships/rutis/blob/main/docs/migration-0.13.md)`。
  - 测试工具在加载时声明事件的 `emits`（Node / Bun `load(plugin, { emits })`、Python `load(plugin, emits=…)`、Go `rutistest.Load` 结尾的事件名）。
  - 协议：`mount` 参数 `events` / `emits`、`mount` 特性 `events`、运行时 → 宿主的 `event`、宿主 → 运行时的 `emit`、节点的 `events.forward`。
- **行为变化**：
  - `emit` 的监听器出错不再结束进程、不再中断其他监听器、不再抛给发出方，在监听器所在处报告一行 `rutis: listener of <name> in row <row> failed: <ErrorName>: <message>`。
  - Go 的 `Emit` 不再等待监听器，返回的错误只报拒绝；监听器签名改为 `func(ctx, args ...any) (any, error)`。
  - `parallel` 的失败总是 `AggregateError`，子错误按登记顺序，只有一个失败也如此（Rust 以前单个错误原样、多个按完成顺序）。
  - `false` 是没有结果，Rust 的 `Some(false)` 也是。
  - 同步 `bail` 遇到异步监听器以 `AsyncListener` 失败，各语言相同（Cordis 以前把 Promise 当作结果）。
  - Rust 监听器以登记它的 `ctx` 被调用，不再是发出方的；所有 Rust 监听器按存活过滤，卸载时等待。
  - 卸载等待正在运行的监听器，各语言相同。
  - `rutis/*` 成为保留名字。
- **事件边界规则**：`requirements-protocol-plugins` §5 的规则 2–5 删除，由[统一事件](../design-events-2026-10-18.md)第三节取代。
