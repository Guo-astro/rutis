# rutis 0.17.1

[中文](0.17.1.md) · [0.17.0 release notes](0.17.0.en.md)

0.17.1 makes plugin definitions work in every language: 0.17.0 had Rust, Node and Bun; this release adds Python, Go, Swift and Kotlin (phases P2 and P3 of [#642](https://github.com/arcships/rutis/issues/642)). It also fixes three problems in the kernel and the session layer. Plugin code in every language stays as it is.

## Plugin definitions: Python, Go, Swift, Kotlin

([#654](https://github.com/arcships/rutis/pull/654), [#653](https://github.com/arcships/rutis/pull/653), [design](../design-plugin-values-2026-10-25.en.md))

- **All four languages can hand a plugin to a service.** The result of Python's `define_plugin`, Go's `rutis.Define`, and Swift's and Kotlin's `Rutis.define` can be an argument or return value of a service in another language. The receiver gets a `rutis::Definition` and mounts it with `ctx.plugin(def.at(&ctx, config)?)`. The rules are the same as for Node and Bun in 0.17.0: each copy runs in the runtime that handed it over and ends with the row that handed it over.
- **Clients are written as usual.** Go function fields take `*rutis.Definition` directly (in 0.17.0 it crossed as data and arrived as `{}`); Swift `@RutisClient` parameters are typed `Rutis.Definition`; Kotlin KSP client interfaces use `Plugin`. Python needs no declaration. A plugin definition can only be a direct argument or return value; definitions inside arrays or lists are not supported.
- **Go's `Name` is optional for a definition that is only handed over.** A definition served with `rutis.Serve` still needs a `Name`.
- **Testing tools match the real host.** A definition a test double receives can go straight to the testing tool's `load` (Python `rutis.testing`, Go `rutistest.Load`, Swift `RutisTest.load`, Kotlin `RutisTest`); when the double hands a definition back, the plugin gets the original one.
- **Apps that connect in.** A definition handed over by a Swift `RutisApp` or a Kotlin app can only be mounted in the instance the app's connection belongs to; when the app disconnects, the copies mounted from it end.
- See [plugin API](../guide/plugin-api.en.md#plugin-definitions) and the [Python](../guide/python-plugin.en.md), [Go](../guide/go-plugin.en.md), [Swift](../guide/swift-plugin.en.md) and [Kotlin](../guide/kotlin-app.en.md) guides.

## Fixes

- **Disposing right after mounting, or while a restart unloads the old generation, no longer hangs** ([#619](https://github.com/arcships/rutis/issues/619), [#652](https://github.com/arcships/rutis/pull/652)). The new generation used to start anyway with a token that was not cancelled, so a plugin waiting on `ctx.cancelled()` never ended. Now a registered dispose stops the new generation from starting (`core/D6`, `core/D7`).
- **Withdrawing a service also stops a consumer that has just passed its dependency check** ([#620](https://github.com/arcships/rutis/issues/620), [#652](https://github.com/arcships/rutis/pull/652)). A consumer that had passed the check but not yet recorded its dependencies was not stopped and stayed in Loading (`core/D14`).
- **A far-end reference of the wrong kind closes the session with a transport error instead of deadlocking** ([#621](https://github.com/arcships/rutis/issues/621), [#651](https://github.com/arcships/rutis/pull/651)).

## Compatibility

- No API is removed or renamed and the `rutis.json` format is unchanged; nothing to migrate.
- The protocol is unchanged: plugin definitions still use 0.17.0's capability `plugins`, used only when both ends declare it. 0.17.1 connects to 0.17.0 and 0.16.0 as usual; when the far end does not declare `plugins`, the call that hands over a plugin definition fails and the session continues.
