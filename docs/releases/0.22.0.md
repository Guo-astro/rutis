# rutis 0.22.0

[English](0.22.0.en.md) · [0.21.0 发布说明](0.21.0.md)

**发布准备中：0.22.0 还没发布。** 版本号、持久化样本与更新记录已在发布 PR 里就绪（2026-11-17）。本稿仍只写 `origin/main` `b8fb89ba`（2026-11-16）上已合并的改动，文末「发布前还要做」列出还没做的发布门与仍开着的 issue。不要把本稿当成已发布。

0.22 把 0.23 的形式化覆盖并入本版：会话协议有了现行规格，1368 条规则进了追踪表，7 个 TLA+ 模型目录（17 个模块、220 个配置）与 16 个内核 shuttle 模型按 0.22 对账并补齐；事件监听者的关闭接纳改成在子树关闭时发布永久 marker，`Entry::live` 不再每次调用遍历祖先链。插件看得到的 API 没有删除或改名，线上格式不变；行为上修了一批关闭、撤下、心跳与未知字段的边界。升级前看[迁移到 0.22](../migration-0.22.md)。

## 行为变化

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| 已接纳的 `emit` 分发遇到 `cancel` | `cancel` 把它从队列删掉，监听器一次都不跑 | 照常分发；调用方已经放弃这次调用，迟到回复由调用方丢弃，会话不受影响（[#1121](https://github.com/arcships/rutis/issues/1121)、[#1129](https://github.com/arcships/rutis/pull/1129)） |
| 宿主调用一个运行时刚自己撤下的监听器 | Node、Bun 抛 `BindingError: listener <id> of <name> is withdrawn`；其他运行时也失败一次 | 这次调用回「没有结果」（各语言按自己的空值回应）；`waterfall` 调 `next` 并返回它的值。未知 id 与宿主自己撤下的行仍报 `listener <id> of <name> is withdrawn`（[#1135](https://github.com/arcships/rutis/issues/1135)、[#1138](https://github.com/arcships/rutis/issues/1138)，[#1137](https://github.com/arcships/rutis/pull/1137)、[#1189](https://github.com/arcships/rutis/pull/1189)） |
| 行开始卸载后调 `ctx.provide` | Python、Bun 接受；服务留在表里但没有行，Python 在卸载没走完时还会向宿主宣告 | 与 Rust、Go、Kotlin、Swift 一致拒绝：Python `RuntimeError: row <row> is not active`，Bun `Error: row <row> is not active`；不登记撤回、不发 `service` 帧（[#1143](https://github.com/arcships/rutis/issues/1143)、[#1149](https://github.com/arcships/rutis/pull/1149)、[#1189](https://github.com/arcships/rutis/pull/1189)） |
| 监听端心跳从什么时候起算 | accept 或构造连接时；旧租约清理超过心跳超时，新连接在 hello 前被 1001 关掉 | hello 成功发出后；Go、Swift、Node、Bun、Kotlin 一致，慢清理不再误关新连接（[#1102](https://github.com/arcships/rutis/issues/1102)、[#1182](https://github.com/arcships/rutis/issues/1182)，[#1181](https://github.com/arcships/rutis/pull/1181)、[#1183](https://github.com/arcships/rutis/pull/1183)） |
| Kotlin、Swift 收到带未知字段的帧 | 静默忽略 | 调用级拒绝：`unknown field "x" in invoke`，`code` 是 `bad-frame`，`data` 是 `{op, fields}`；`hello` 失败握手（`incompatible session: unknown field "x" in hello`）；`release`/`cancel` 仍忽略（[#635](https://github.com/arcships/rutis/issues/635)、[#1156](https://github.com/arcships/rutis/pull/1156)） |
| `filter(predicate)` 返回 Promise / thenable / 协程 | 恒真，全部监听器放行 | 这次分发失败：Node、Bun `TypeError: a filter predicate must answer with a boolean, not a Promise`；Python `TypeError: a filter predicate must return a boolean, not an awaitable`，协程会先关掉（[#637](https://github.com/arcships/rutis/issues/637)、[#1156](https://github.com/arcships/rutis/pull/1156)） |
| 收到的引用 `origin` 条目不是 `<endpoint>:<n>` 或 `s<n>/<endpoint>:<n>` | Rust 只当普通调用号处理 | 以 `invalid reference` 结束会话，与 Node、Python、Go 一致（[#637](https://github.com/arcships/rutis/issues/637)、[#1156](https://github.com/arcships/rutis/pull/1156)） |
| `isolate` 标签含 U+0001 | 接受；和 loader 给按行租用服务造的标签共用命名空间 | 配置被拒：`isolate.<name> of "<id>" must not contain U+0001: it is reserved for the loader's row labels`（[#637](https://github.com/arcships/rutis/issues/637)、[#1156](https://github.com/arcships/rutis/pull/1156)） |
| 节点导入的服务宣告 `services.announce` | `row` 是 `null`，导入侧不知道提供方是哪一行 | 带提供方的行 id；没有行时不带。旧对端不认这个可选字段会忽略，新对端读旧宣告得到 `None`（[#1171](https://github.com/arcships/rutis/issues/1171)、[#1173](https://github.com/arcships/rutis/pull/1173)） |
| 宿主先收到一行的 `rows.unload`、后收到同一 key 的 `rows.load` | 后到的装载照常装行，留下没有卸载的孤儿行 | 后到的装载被拒：`<key> was unloaded`。墓碑按会话存放；卸载一张已装载的行不记墓碑，同一 key 在新会话里照常装载（[#1101](https://github.com/arcships/rutis/issues/1101)、[#1185](https://github.com/arcships/rutis/pull/1185)） |
| Node、Bun 判断同步等待成环 | 回复已读的同步调用仍算在等待链里，偶发误报 `SyncWaitCycle` | 只看未回复的同步调用；真正的环仍拒绝（[#639](https://github.com/arcships/rutis/issues/639)、[#1178](https://github.com/arcships/rutis/pull/1178)） |
| 对端以 4003 拒绝连接时本端读到的失败 | `peer disconnected`（transport） | `endpoint mismatch: <原因>`；一对通道的两个方向现在拿到同一个关闭原因（[#1130](https://github.com/arcships/rutis/pull/1130)） |

其余修复：

- **Python 首次导入插件**：Windows 上目录 mtime 落在同一刻度时，新文件可能不在 `FileFinder` 的缓存列表里，报 `ModuleNotFoundError`；现在首次 `import_module` 前调用 `importlib.invalidate_caches()`，reload 路径不变（[#1139](https://github.com/arcships/rutis/issues/1139)、[#1140](https://github.com/arcships/rutis/pull/1140)）。
- **Kotlin 应用托管与 Node、Bun 强杀**：`stop()` 返回后不再拨号或绑定；接管时强杀旧运行时等 `RUTIS_SHUTDOWN_TIMEOUT + 2s`，不再写死 5 秒（[#1096](https://github.com/arcships/rutis/pull/1096)）。
- **Go 在 Windows 上读 token 行**：`bufio` 会把紧跟其后的问候一起吞掉，每个测试工具用例都报 `peer disconnected`；现在逐个字节读到行尾，问候留给后续读取（[#1087](https://github.com/arcships/rutis/pull/1087)）。
- **旧提供撤下后的迟到条目**：`events` 提供被撤下后，窗口期内登记的条目不会再插回表里（[#1096](https://github.com/arcships/rutis/pull/1096)）。

## 验证与模型

- **现行规格**：`docs/protocol-session.md` 有 83 条 `SESS-*` 规则；共享畸形帧矩阵 25 个用例，Rust、Node、Bun、Python、Go、Swift、Kotlin 都有入口。Swift 的用例只在 macOS 上编译，由 CI 的 `runtimes-swift` 作业运行。
- **规则追踪**：1825 行（登记表 219、手写 54、协议 1552）；1368 条现行协议规则按 0.22 来源重抽，状态见上表。`node tools/formal-trace.mjs` 报告 0 problem，追踪表检查已进 CI。登记表的 219 行与手写 `ECA` 10 行还没有逐条重抽（`TRC` 44 行与六个协议分区已重抽）。
- **TLA+**：7 个目录、17 个模块、220 个配置，全部有 `expected.txt`；`event-close` 的 7 个配置里，4 个变异分别违反 `ClosingImpliesMarked`、`CommittedStaysOut`（两次）和 `CleanupOnce`，证明模型不是空的。CI 的 `specs` 任务在改了 `specs/**` 的 PR 与每晚的完整运行里跑每个模型的全部配置。
- **shuttle**：内核 16 个模型，`stress.yml` 每晚每个 100 万次迭代，失败打印可重放的调度；`#1025` 的 marker 发布顺序写错时模型立即失败（`this node is closing while its lineage marker is clear`）。
- **trace 与一致性**：通道/帧验证器 23 个用例；等待图 trace 记录 `waits.rs` 的六个操作，按 `RustSucc` 重放，改坏同一份日志必须报出。租约套件有 Python、Go、Bun 三列；`sync_cycles` 缺 Kotlin，`host_gone` 缺 Swift、Kotlin（Swift 插件只在 macOS 上构建，Kotlin 要 JDK 17 与 `:rutis-conformance:fatJar`）。
- **属性、模糊、Miri、Kani**：引用授予回滚 6 个属性、值/帧/坏帧 5 个属性、监听器表模型属性；4 个 fuzz 目标实跑无 crash；Miri 按固定输入跑了 30 个（13 帧、1 个超深嵌套、9 个分帧种子、7 个错误图），无 UB。Kani 的 6 个 harness 不收敛，没有结论，不写成通过。
- **发布检查的数字**：`node tools/check-guarantees.mjs` 219 行、1162 个标记，0 problem；登记表的 40 条核心承诺 0 条未验证（33 已验证、7 部分验证）；追踪表里另有 1 条未验证的核心承诺，是登记表之外的 `ECA-7`。

## 已知不保证

- **信任边界不在这一版**（[#1040](https://github.com/arcships/rutis/issues/1040)）：运行时行可以对外宣告任意服务名，宿主没有按行限制或拒绝的策略。0.22 不新增 `rutis.json` 字段、全局 allowlist、服务 namespace 或动态名称 `isolate`。
- **子树的关闭后投递**：设计里「`Ctx::emit()` 本身不会仅因子树关闭而失败，也不会触达该子树的 live listener」仍是提案；现有 service-after-stop 测试明确把停止后的 delivery 留作未承诺（`crates/rutis/src/events/api.rs:453-480`、`crates/rutis/tests/service_emits.rs:70-83`）。这一版只固定「提交后不再开始新的 listener 调用，已接纳的照常 drain」。
- **取消后的回复**：`SESS-61` 仍是明确不保证，各实现尚未统一。Rust 对排队中的调用和 `await` 不回复，对已接纳的 `emit` 分发照常执行、回复由调用方丢弃；其他语言由方法和信号决定。取消表清理与取消确认规则见 [#1099](https://github.com/arcships/rutis/issues/1099)。
- **未知字段不是扩展机制**：`SESS-69` 明确不保证不改含义的新可选字段能静默到达旧接收方；旧实现会按 `SESS-66` 失败该调用。新增帧或改变已有字段含义要提升协议版本，新增能力要按声明使用。
- **关闭接纳的实现层规则**：`ECA-7`（registration 与 marker pass 的竞态）未验证；`Loading` owner、`once` 不被消耗、remote-entry、多代 reload 的专项用例仍缺。设计 §3 的规则 3、6、7、8、9 仍写「提案，尚未验证」。
- **形式化覆盖还没到发布门**：追踪表里 537 条协议规则未验证；[#613](https://github.com/arcships/rutis/issues/613)、[#622](https://github.com/arcships/rutis/issues/622)、[#624](https://github.com/arcships/rutis/issues/624)、[#630](https://github.com/arcships/rutis/issues/630)、[#631](https://github.com/arcships/rutis/issues/631)、[#634](https://github.com/arcships/rutis/issues/634)、[#635](https://github.com/arcships/rutis/issues/635)、[#776](https://github.com/arcships/rutis/issues/776) 仍开着。Kani 没有结论；Swift/Kotlin 的 trace 列、会话层/事件宿主/运行时监督/宿主重载的 shuttle 模型、`interleave.rs` 的顺序参考模型（[#1190](https://github.com/arcships/rutis/pull/1190)）都还没做。
- **仍开着的协议/实现缺口**：异步调用「发出即不管」与「之后 await」的协议信号（[#1098](https://github.com/arcships/rutis/issues/1098)）、取消表清理与取消后的回复（[#1099](https://github.com/arcships/rutis/issues/1099)）、宿主单 worker 下策略 B 的等待图盲区（[#1103](https://github.com/arcships/rutis/issues/1103)）。#1125 的进一步性能优化也不阻塞 0.22。

## 兼容

- 会话协议仍是 4（`crates/rutis-bridge/src/session/mod.rs` 的 `ENDPOINT_PROTOCOL`），`rutis.json` 的 `format` 仍是 1，插件 API 仍是 3；能力声明与握手没有新增要求，线上帧没有新增必需字段。
- 新旧版本可以混用：旧运行时包在它那一侧保持旧行为（例如旧 Kotlin/Swift 仍忽略未知字段），不会因此断会话；`services.announce` 的 `row` 是可选字段，旧对端忽略，新对端读旧宣告得到 `None`。
- Rust 没有删除或改名公开 API；内核的公开 API 快照 `crates/rutis/public-api.txt` 没有变化。`rutis-bridge` 只新增追踪与测试支持用的类型和函数，没有删除或改名。
- dylib 插件照每次发布一样用 0.22.0 的 SDK 重新构建。
- `rutis.json` 与 dsh 用户层没有格式变化：持久化样本在 `tests/fixtures/persisted/0.22.0/`，从 0.21.0 复制，期望不变。发布门还没做，见下节。

## 升级

大多数插件与宿主不用改代码。会碰到行为变化的三处：`filter(predicate)` 必须同步回答；行开始卸载后不能再 `ctx.provide`；自己撤下的监听器不再以 `withdrawn` 失败，而是回「没有结果」。另外 Kotlin、Swift 不再忽略未知字段，`isolate` 标签不能含 U+0001。逐条改法见[迁移到 0.22](../migration-0.22.md)。
