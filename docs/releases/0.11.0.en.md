# rutis 0.11.0 (draft)

[中文](0.11.0.md) · [0.10.0 release notes](0.10.0.en.md)

> Draft: filled in by the 0.11 pull requests, finished before the release ([release process](../release.en.md)).

## New

- **Cross-language value types** ([#308](https://github.com/arcships/rutis/issues/308), [#355](https://github.com/arcships/rutis/issues/355), [#360](https://github.com/arcships/rutis/issues/360), [design](../design-value-types-2026-10-15.en.md)): the session protocol gains ten tagged values: points in time (`instant`), local dates and times (`datetime`), dates (`date`), times of day (`time`), binary data (`bytes`), maps (`map`), sets (`set`), big integers (`bigint`), decimals (`decimal`) and UUIDs (`uuid`). Wire formats and capabilities: [protocol design](../design-protocol-plugins-2026-09-25.en.md) §6.1. Each value has a capability `value-<tag>` and is sent only to a far end that declared it; to one that did not, only that call fails, the session goes on, and the protocol version does not change.
  - Rust (`rutis-bridge`): `session::Value` gains ten variants, with the types `Instant`, `DateTime`, `Date`, `TimeOfDay`, `BigInt`, `Decimal` and `Uuid` (small types of rutis-bridge's own, no chrono, num-bigint or uuid), and `Bytes`, `ValueMap` and `ValueSet` for generated code. `Value::json()` fails on the new values (as on references). A host forwarding a call checks again against the downstream far end's capabilities; `Process::emit` checks its arguments against the runtime's; an event forwarded between nodes (`NodeEvent`) holding a new value is refused.
  - Cordis generator: `Date` → `Instant`, `Uint8Array` → `Bytes`, `bigint` → `BigInt`, `Map<K, V>` → `ValueMap<K, V>`, `Set<T>` → `ValueSet<T>` (keys limited to strings, numbers, booleans and bigints); `ArrayBuffer`, `Buffer` and `DataView` are still not bound.
  - Node, Bun, Python, Go: (to come, #308 phase 3)

## Compatibility

- **Rust API**:
  - `rutis-bridge`'s `session::Value` gains ten variants and is marked `#[non_exhaustive]`: code matching `Value` exhaustively needs a `_ =>` arm. Later variants will not be breaking changes. `Value` now implements `PartialEq`.
  - The Rust side declares the `value-*` capabilities in its handshake (in both formats).
- **Wire**: the frame depth limit goes from 144 to 208 levels (one `map` level takes three JSON levels on the wire); values still nest at most 64 levels.
- With runtimes of 0.10 and earlier, calls carrying a new value fail as before (the far end declares no capability); other calls are unaffected. Both ends must be on 0.11 to pass the new values.
- **Plugin code that may need changes** (lands with #308 phase 3; [design](../design-value-types-2026-10-15.en.md) §8):
  - Python: `datetime`, `Decimal` and `UUID` used to cross by object reference (the peer got a proxy); they now cross by value.
  - Go: `time.Time`, `[]byte` and integers beyond ±(2^53−1) inside structs used to go through `encoding/json` (becoming strings, base64, or unchecked); they are now encoded as value types, and out-of-range integers are refused.
  - Python: a dict key whose value is `undefined` used to be dropped; it is now `null`, as in the other languages.
  - Big integers are explicit: Python `rutis.BigInt(n)`, Go `*big.Int`, JS `bigint`; a plain integer beyond ±(2^53−1) is still refused.
  - In JS, local date-times, dates, times of day, Decimals and UUIDs arrive as strings; send them as their type with `rutis.datetime(…)`, `rutis.date(…)`, `rutis.time(…)`, `rutis.decimal(…)`, `rutis.uuid(…)`.
