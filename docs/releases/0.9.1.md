# rutis 0.9.1

[English](0.9.1.en.md) · [0.9.0 发布说明](0.9.0.md)

0.9.1 修复 npm 包 `@arcships/rutis-host` 的启动器：在终端里按一次 Ctrl-C，`rutis-host` 会跳过清理直接退出（[#267](https://github.com/arcships/rutis/issues/267)）。其余包没有改动，只为与列车对齐升到 0.9.1。

## 修复

- **npm 启动器不再转发 Ctrl-C**：`npx rutis-host …` 或项目里的 `node_modules/.bin/rutis-host` 是一个 Node 启动器，它把收到的信号全部转发给 `rutis-host`。终端的 Ctrl-C 本来就发给整个进程组，`rutis-host` 于是收到两次，把第二次当成“立即退出”：插件的清理没有运行，运行时进程被直接结束，退出码为 2。现在启动器不再转发 SIGINT 和 SIGHUP（`rutis-host` 自己会收到），只转发 SIGTERM（服务管理器、`docker stop` 只发给主进程）。在 Windows 上，启动器以前转发 Ctrl-C 会强制结束 `rutis-host`，现在不再转发，控制台事件由 `rutis-host` 自己处理。
- 只对启动器进程号单独发送的 SIGINT / SIGHUP（`kill -INT <pid>`）不再传到 `rutis-host`；这种情况请发 SIGTERM。

`uvx rutis-host`、PyPI 安装的 `rutis-host` 和 GitHub 发布页的二进制不受影响。

## 发布包

以下包版本均为 **0.9.1**：crates.io 的 `rutis`、`rutis-bridge`、`rutis-loader`、`rutis-host`、`rutis-sdk`、`rutis-dylib`、`rutis-dylib-meta`、`rutis-dylib-launcher`；npm 的 `@arcships/rutis`、`@arcships/rutis-runtime`、`@arcships/rutis-bun`、`@arcships/rutis-host` 及五个平台包；PyPI 的 `rutis`、`rutis-host`；Go 模块 `github.com/arcships/rutis/go/rutis`（tag `go/rutis/v0.9.1`）；GitHub 发布页的 `rutis-host` 二进制。

## 兼容

- 与 0.9.0 完全兼容：没有 API、协议或配置变化，0.9.0 与 0.9.1 的宿主和运行时可以混用。
- 用 npm 安装 `rutis-host` 的项目建议升级；其他用法可以留在 0.9.0。
- dylib：SDK 身份包含依赖树里的包版本。用 0.9.1 重新构建 SDK 和宿主后，0.9.0 时期编译的 dylib 插件要用新的 SDK 重新编译；继续使用原来的 SDK 构建包则不受影响。
