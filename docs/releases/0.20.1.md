# rutis 0.20.1

[English](0.20.1.en.md) · [0.20.0 发布说明](0.20.0.md)

0.20.1 是补丁版本：修 0.20.0 之后发现的几个 bug，并补上 0.20.0 发布门里两处与装载相关的偶发失败。**插件代码不用改，`rutis.json`、`rutis.dev.json` 也不用改，没有要迁移的写法**：各包升到同一个版本即可。下面「行为变化」一节列出所有看得到的不同。

## `rutis-host dev`

- **只对插件会加载的文件重新加载**（[#1046](https://github.com/arcships/rutis/issues/1046)、[#1047](https://github.com/arcships/rutis/pull/1047)）。`dev` 以前把项目里所有文件的变化都算作项目自己的那一行变了：跑一遍测试、改一个 `README`、换一张图，也重启这一行和用到它的行。现在只认插件会加载的东西：源码模块（`.ts`、`.tsx`、`.mts`、`.cts`、`.js`、`.jsx`、`.mjs`、`.cjs`、`.py`、`.pyi`）、清单与配置（`.json`、`.yaml`、`.yml`、`.toml`）和 `.env`。测试文件（`*.test.*`、`*.spec.*`、`*.bench.*`、`test_*.py`、`*_test.py`、`*_test.go`，以及项目里 `test`、`tests`、`__tests__`、`__mocks__`、`coverage`、`htmlcov` 目录下的）、文档、图片、锁文件（`package-lock.json`、`pnpm-lock.yaml`、`uv.lock`、`Cargo.lock` 等）变了什么都不做，测试跑一遍写出的 `coverage/` 报告也不再重启行。目录只从项目这一层算起，所以放在 `tests/` 目录下的项目照常工作，不会因为整个项目都在 `tests` 下就什么都不加载。别的扩展名的文件（插件读的模板等）同样不重新加载：改它加载的一个模块即可。见 [rutis-host：用 dev 开发插件](../guide/rutis-host.md#用-dev-开发插件)。
- **Node 检查器的地址可以用 `RUTIS_NODE_INSPECT` 换**（[#1046](https://github.com/arcships/rutis/issues/1046)、[#1048](https://github.com/arcships/rutis/pull/1048)）。`dev --debug` 的 Node 检查器以前钉在 `127.0.0.1:9229`，端口被占时只能先去结束占用它的进程。现在 `RUTIS_NODE_INSPECT=host:port`（或只写一个端口，落在 `127.0.0.1`）换一个地址，`rutis-host dev: debugging: …` 打印的和 Node 进程用的是同一个。写错的地址在启动前就被拒绝，不再打印一个没人听的地址：`RUTIS_NODE_INSPECT=<值> is not an address: set it to <host>:<port>, such as 127.0.0.1:9230, or to a port`。
- **不再打印 `services: none`**（[#1046](https://github.com/arcships/rutis/issues/1046)、[#1049](https://github.com/arcships/rutis/pull/1049)）。启动时和每次重建后都会先打一行 `rutis-host dev: services: none`：行还没跑起来、或重载期间这一行的服务短暂不在时，那行说的就是这个，`dev` 的例子里没有它。现在没有行提供服务时什么都不打印（`rutis-host status` 里看得到），服务出现或变化时照旧打印 `rutis-host dev: services: <名字> (<提供方>), …`。

## 行的卸载

- **一行的清理仍能发出事件**（[#1041](https://github.com/arcships/rutis/issues/1041)、[#1050](https://github.com/arcships/rutis/pull/1050)）。以前这一行在 `rows.unload` 发出的那一刻就被撤下，清理里 `ctx.emit` 报 `row <行> is not loaded in this runtime`，清理剩下的部分不再执行；Cordis 把这条错交给 logger，没装 logger 时什么都看不到。现在撤下的是这一行的**监听器**：卸载一开始它的条目离开监听器表，而这一行仍算加载着，清理里发出的事件照常分发，别的行的监听器听得到，这一行自己的听不到，所以不会重入。这只持续到运行时回答 `rows.unload`：回答之后它的发出按原样被拒绝（`BindingError`，`row <行> is not loaded in this runtime`），它留下的排队 emit 被丢弃。清理里只发出、不等结果的 `emit` 在这个回答发出时仍可能被丢掉，要确定送到就等它（`parallel`、`serial` 等）。在 dispose 里补 `turn/end`、`session/flush` 的 Cordis 插件（DSH 等）因此与原生 Cordis 一样。六种语言（Node、Bun、Python、Go、Kotlin、Swift）都是这个行为，一致性清单加了用例 `unload/cleanup-emits`；卸载栈里这一行登记的监听器照旧不保留（Go、Swift 报 `row <行> is not active`，Node 的 Cordis fiber 报 `INACTIVE_EFFECT`）。见 [插件 API：事件](../guide/plugin-api.md#事件)。

## 0.20.0 发布门里的两处

- **`dev` 不再把还在回来的路上的行说成 `stopped`**（[#1044](https://github.com/arcships/rutis/issues/1044)、[#1051](https://github.com/arcships/rutis/pull/1051)）。重载之后，用到被重载行的行在这段时间里是 `Pending` / `Loading`；`dev` 以前只取一次快照，于是把「在回来」说成 `stopped`，之后再没有一行说它回来了。现在重启了、还在回来的路上（正在加载新版本，或还在等一个同样在回来的行）写 `restarted`，这段时间它的状态行写 `waiting for …`（如 `caller: waiting for weather (row weather has not provided it)`），运行起来后照旧写 `running`；`stopped` 只写不会回来的行（`failed`、已经没了，或者在等没人再提供的服务）。
- **远程运行时的测试等 hello 帧**（同 #1044、[#1051](https://github.com/arcships/rutis/pull/1051)）。心跳定时器会把 ping 写到等待的消息前面，而测试以前假定 hello 是第一帧，于是偶尔读错、在发布门里偶发失败；现在等到 `"op":"hello"` 为止，失败时打印之前读到的帧。只是测试，没有行为变化。

## 行为变化

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| `dev`：测试文件、文档、图片、锁文件变了 | 重启项目自己的行和用到它的行 | 什么都不做 |
| `dev`：测试跑出的 `coverage/` 报告写出来 | 重启同上 | 什么都不做 |
| `dev`：项目放在 `tests/` 目录下 | 整个项目都当测试文件 | 照常按插件会加载的文件重新加载 |
| `dev --debug`：Node 检查器 | 固定在 `127.0.0.1:9229` | 不设仍是它；`RUTIS_NODE_INSPECT` 换地址，写错的在启动前被拒 |
| `dev`：没有行提供服务 | 每次启动与重建后打印 `services: none` | 什么都不打印 |
| 一行卸载时，清理里 `ctx.emit` | `row <行> is not loaded in this runtime`，清理后面的部分不跑 | 分发出去，别的行听得到；`rows.unload` 回答后拒绝（`BindingError`） |
| `dev`：重启了、还在回来的行 | 说成 `stopped` | `restarted`，状态行 `waiting for …` |

## 兼容

- 插件代码、`rutis.json`、`rutis.dev.json` 都不用改。会话协议仍是 4，`rutis.json` 的 `format` 仍是 1，插件 API 版本不变：宿主、运行时与 SDK 之间没有新的握手限制。
- `rutis.json` 与 dsh 的用户层没有变化：持久化样本从 0.20.0 复制，这一版没有给它们加字段，期望不变。
- `RUTIS_NODE_INSPECT` 只用于 `dev --debug` 的 Node 检查器；不设时仍是 `127.0.0.1:9229`。
- dylib 插件照每次发布一样用 0.20.1 的 SDK 重新构建。
