# rutis 0.15.1

[English](0.15.1.en.md) · [0.15.0 发布说明](0.15.0.md)

0.15.1 把事件恢复成一条平总线（与 Cordis 相同，[#604](https://github.com/arcships/rutis/issues/604)、[#605](https://github.com/arcships/rutis/issues/605)）：一个 root 总线上同名事件的所有监听器都收到，无论在哪个实例、运行时或相连的节点。作用域、运行时与节点仍是 `filter` 的描述，不是送达规则。0.13 迁移文档里 `Process::emit` → `parallel` 的说明现在成立。

## 修复

- **事件处处按名字送达。** 父级行发出的事件到达子级行的监听器，兄弟实例的监听器也收到。Rust 内核、Node、Bun、Python、Go、Swift、Kotlin 的快速路径、测试工具、节点连接与一致性期望都遵循同一规则。原来依赖作用域隔离的行，用 `ctx.events().filter(..)` 按 `ListenerInfo::scope` 筛，或用不同的事件名。
- **节点连接只通告自己的条目，由 `export` / `import` 控制。** 实例内的连接会通告 root 的条目，root 也听得到它接受的条目。引进的条目不再转发，事件仍只走一跳。
- **顺序与失败：** 监听器按登记顺序运行；`parallel` 的失败按登记顺序聚合，`emit` 在监听器运行处报告并立即返回。

## 删除

- `rutis::events::Dispatch::scope`：送达改为按名字后它只写不读；分发现在指明所属的行。
- 作用域辅助函数 `scope_contains`（Rust）、`inScope`（Node/Bun）、`within`（Python、Kotlin、Swift）与 `events.Within`（Go）：已无调用者。
- 测试工具的发出方作用域：Node 的 `h.at(scope)` 与 Python 的 `Bus.emitter(scope)`。`load` 的 `scope` 参数仍设置该行监听器的描述。

## 兼容

- 事件线上格式不变：0.15.0 与 0.15.1 的宿主和运行时可以连接并交换事件。仍留在 0.15.0 的一端会在自己这一侧继续按作用域过滤，所以要让各处都按平总线送达，所有端都要升级。
- `events/scope` 与 `events/hub-scope` 两条保证撤回，由 `events/flat` 与 `events/hub-flat` 取代。
- 见[迁移到 0.15.1](../migration-0.15.1.md)。
