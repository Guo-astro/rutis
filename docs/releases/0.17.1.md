# rutis 0.17.1

[English](0.17.1.en.md) · [0.17.0 发布说明](0.17.0.md)

0.17.1 让插件定义在所有语言里都能用：0.17.0 只有 Rust、Node、Bun，这一版补上 Python、Go、Swift、Kotlin（[#642](https://github.com/arcships/rutis/issues/642) 的 P2、P3）。另外修复内核和会话层的三个问题。所有语言的插件代码都不用改。

## 插件定义：Python、Go、Swift、Kotlin

（[#654](https://github.com/arcships/rutis/pull/654)、[#653](https://github.com/arcships/rutis/pull/653)，[设计](../design-plugin-values-2026-10-25.md)）

- **四种语言都能把插件交给服务。** Python 的 `define_plugin`、Go 的 `rutis.Define`、Swift 和 Kotlin 的 `Rutis.define` 的结果，可以作为参数或返回值交给别的语言的服务。收的一方拿到 `rutis::Definition`，用 `ctx.plugin(def.at(&ctx, config)?)` 挂载；规则和 0.17.0 的 Node、Bun 相同：每一份在交出它的运行时里运行，跟着交出它的那一行结束。
- **客户端照常写。** Go 的函数字段直接传 `*rutis.Definition`（0.17.0 里它按数据传，到对面变成 `{}`）；Swift 的 `@RutisClient` 参数类型写 `Rutis.Definition`；Kotlin 的 KSP 客户端接口参数类型写 `Plugin`。Python 不用声明。插件定义只能直接作为参数或返回值，放在数组、列表里不支持。
- **Go 的 `Name` 对只交出、不服务的定义可以不写。** `rutis.Serve` 服务的定义仍要写 `Name`。
- **测试工具和真实宿主一致。** 测试替身收到的定义可以直接交给测试工具的 `load` 装上（Python `rutis.testing`、Go `rutistest.Load`、Swift `RutisTest.load`、Kotlin `RutisTest`）；替身把定义交回插件时，插件拿到的是原来那个。
- **连进来的应用。** Swift 的 `RutisApp` 和 Kotlin 应用交出的定义，只能挂在应用的连接所在的实例里；应用断开时，挂出的副本结束。
- 用法见[插件 API](../guide/plugin-api.md#插件定义)，以及 [Python](../guide/python-plugin.md)、[Go](../guide/go-plugin.md)、[Swift](../guide/swift-plugin.md)、[Kotlin](../guide/kotlin-app.md) 指南。

## 修复

- **刚挂上就 dispose，或重启卸载期间 dispose，不再卡住**（[#619](https://github.com/arcships/rutis/issues/619)、[#652](https://github.com/arcships/rutis/pull/652)）。原来新的一代仍会开始，拿到没被取消的令牌，等 `ctx.cancelled()` 的插件永远不结束。现在已经登记了 dispose，就不开始新的一代（`core/D6`、`core/D7`）。
- **服务撤下时，刚过依赖检查的消费者也会被停下**（[#620](https://github.com/arcships/rutis/issues/620)、[#652](https://github.com/arcships/rutis/pull/652)）。原来消费者过了检查、还没记下依赖时撤下服务，消费者不被停，留在 Loading（`core/D14`）。
- **对端发来类型不符的引用时，会话以传输错误关闭，不会死锁**（[#621](https://github.com/arcships/rutis/issues/621)、[#651](https://github.com/arcships/rutis/pull/651)）。

## 兼容

- 没有 API 删除或改名，`rutis.json` 的格式不变，不需要迁移。
- 协议不变：插件定义仍用 0.17.0 的能力 `plugins`，两端都声明才用。0.17.1 与 0.17.0、0.16.0 照常连接；对面不声明 `plugins` 时，交出插件定义的那次调用失败，会话继续。
