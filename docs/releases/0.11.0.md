# rutis 0.11.0

[English](0.11.0.en.md) · [0.10.0 发布说明](0.10.0.md)

0.11.0 提前发布，内容是 main 上已有的功能。最主要的是叶子插件事件：Node、Bun、Python、Go 插件可以用 `ctx.on` / `ctx.emit` 在运行时进程里收发事件，也能收到宿主发来的事件（插件 API 2）。其次是跨语言值类型：日期时间、二进制、Map、Set、大整数、Decimal、UUID 现在可以在 Rust、Node、Bun、Python、Go 之间传递，各语言收到本语言的原生类型。第三是远程运行时：运行时可以主动连到 rutis，一个监听器接受多条连接，每条连接是一个实例；Bun 运行时也可以远程运行。有几处值的传递方式变了，见下文的"兼容"。

## 新增

- **叶子插件事件**（[#366](https://github.com/arcships/rutis/issues/366)，[插件 API](../guide/plugin-api.md#ctx)）：Node、Bun、Python、Go 插件新增 `ctx.on(name, listener)` 和 `ctx.emit(name, ...args)`（Go 是 `ctx.On`、`ctx.Emit`）。事件在一个运行时进程里分发：插件自己发的、同进程其他插件发的，以及宿主发进来的。监听随插件卸载注销。`ctx.emit` 按注册顺序同步调用监听器，不等待它们返回的 Promise / 协程。宿主一侧用 Rust API 声明会向运行时发哪些事件（`RuntimePlugin::emits`、`LocalRuntime::emits`），用 `Process::emit` 发出：它等全部监听器结束，错误汇总为 `AggregateError`；没有声明的名字被拒绝。Node 和 Bun 用 Cordis 自己的事件服务，和同进程的 Cordis 插件共用一条总线；Python 和 Go 按同一套语义实现。`internal/*` 属于运行时，不能监听、发出或声明。事件不跨进程：运行时 → 宿主的方向暂不可用，`rutis.json` 也还没有声明 `emits` 的入口。测试工具在加载时声明事件，用 `t.emit`（Node、Python）或 `loaded.Emit`（Go 的 `rutistest`）发入。
- **跨语言值类型**（[#308](https://github.com/arcships/rutis/issues/308)、[#355](https://github.com/arcships/rutis/issues/355)、[#360](https://github.com/arcships/rutis/issues/360)，[设计](../design-value-types-2026-10-15.md)，[插件 API](../guide/plugin-api.md#值怎样传递)）：会话协议新增十种带标记的值：时间点（`instant`）、本地日期时间（`datetime`）、日期（`date`）、时刻（`time`）、二进制（`bytes`）、Map（`map`）、Set（`set`）、大整数（`bigint`）、Decimal（`decimal`）、UUID（`uuid`）。线上格式与能力见[协议设计](../design-protocol-plugins-2026-09-25.md) §6.1。每种值一个能力 `value-<标记>`，只发给声明了它的对端；对端没有声明时只让这次调用失败，会话继续，协议版本号不变。插件只写本语言原生的代码，转换由 rutis 做；整数超出 ±(2^53−1) 时在每种语言里都自动按大整数传。
  - Rust（`rutis-bridge`）：`session::Value` 新增十个变体，以及类型 `Instant`、`DateTime`、`Date`、`TimeOfDay`、`BigInt`、`Decimal`、`Uuid`（rutis-bridge 自己的小类型，不引入 chrono、num-bigint、uuid），生成代码用的 `Bytes`、`ValueMap`、`ValueSet`。整数超出 ±(2^53−1) 时自动按 `bigint` 发出（`Value::Data` 里的 JSON 数字，经 `arg` 的 `i64`、`u64`、`i128`、`u128` 字段；设计 V6），过去按 JSON 数字发出（JS 收到近似值），现在发给没有声明 `value-bigint` 的对端（0.10 及更早）时这次调用失败；收到的 `bigint` 放得下时解码进整数字段。`Value::json()` 遇到新值时报错（同引用），放得下 64 位的 `bigint` 除外（得到数字）。宿主转发调用时按下游对端的能力再检查；`Process::emit` 的参数按运行时的能力检查；节点之间转发的事件（`NodeEvent`）带新值时拒绝。
  - Cordis 生成器：`Date` → `Instant`，`Uint8Array` → `Bytes`，`bigint` → `BigInt`，`Map<K, V>` → `ValueMap<K, V>`，`Set<T>` → `ValueSet<T>`（键限于字符串、数字、布尔、bigint）；`ArrayBuffer`、`Buffer`、`DataView` 仍不绑定。
  - Node、Bun（[#410](https://github.com/arcships/rutis/pull/410)）：`Date` 按时间点传，`Uint8Array`（含 `Buffer`）、`ArrayBuffer`、`DataView` 按二进制传，`Map`、`Set`、`bigint` 按各自的类型传。收到的时间点是 `Date`（截断到毫秒），二进制是 `Uint8Array`，Map、Set、大整数是 `Map`、`Set`、`bigint`；本地日期时间、日期、时刻、Decimal、UUID 在 JS 里没有对应的类型，收到的是普通字符串，内容完整。从别的语言收到的整数，范围内是 `number`，超出 ±(2^53−1) 是 `bigint`。`@arcships/rutis` 导出构造函数 `rutis.datetime(…)`、`rutis.date(…)`、`rutis.time(…)`、`rutis.decimal(…)`、`rutis.uuid(…)`，只在要凭空创建这五种值、或要以原类型转发时用；普通字符串照旧是字符串。其他类型化数组（如 `Int16Array`）不能跨进程，因为元素类型会丢。
  - Python（[#412](https://github.com/arcships/rutis/pull/412)）：带时区的 `datetime` 按时间点传（收到时是 UTC），无时区的 `datetime` 按本地日期时间传，`date`、`time`（不能带时区）、`bytes`（含 `bytearray`、`memoryview`）、`set`（含 `frozenset`）、`Decimal`、`UUID` 按各自的类型传，键不是字符串的 `dict` 按 Map 传；收到的是同样的 Python 类型。`datetime`、`Decimal`、`UUID` 按值传，不再按对象引用传。超出 ±(2^53−1) 的 `int` 自动按大整数传。收到的大整数和 Map 是 `int`、`dict` 的子类，照常当 `int`、`dict` 用；原样转发时仍是大整数、Map，所以 JS 发来的 `5n` 经 Python 转发回 JS 仍是 `5n`。时间值保留到微秒，更细的部分截断。
  - Go（[#413](https://github.com/arcships/rutis/pull/413)）：`time.Time` 按时间点传（UTC，纳秒），`[]byte` 按二进制传，键不是字符串的 map 按 Map 传，`map[K]struct{}` 按 Set 传，`*big.Int` 和超出 ±(2^53−1) 的整数按大整数传；新类型 `rutis.DateTime`、`rutis.Date`、`rutis.TimeOfDay`、`rutis.Decimal`、`rutis.UUID` 对应其余五种值。结构体字段、切片和 map 的元素逐个按这些规则编码（字段名仍按 `json` 标签），不再经过 `encoding/json`。收到的值按声明的 Go 类型解码；解码到 `any` 时 Map 是 `map[any]any`，Set 是去重后的切片，大整数是 `*big.Int`。
  - 测试工具（`@arcships/rutis/testing`、`rutis.testing`、Go 的 `rutistest`）按同样的规则传值，与真实运行时对同一份期望文件比对；`rutistest` 从这一版起加入比对。
- **运行时连进来**（[#382](https://github.com/arcships/rutis/issues/382)、[#383](https://github.com/arcships/rutis/issues/383)、[#384](https://github.com/arcships/rutis/issues/384)，[设计](../design-remote-runtime-dial-2026-10-14.md)，[连接节点](../guide/nodes.md#连进来的运行时)）：远程机器上的运行时可以主动连到 rutis，适合在 NAT 后、地址会变或数量会变（多台设备、扩缩容的 worker）的机器。
  - 运行时一侧：Python、Node、Bun 运行时和 Go 插件二进制都接受 `dial:wss://… --id <id> --peer <rutis 的 id> <项目>`，token 放在 `RUTIS_TOKEN`，rutis 用自签证书时把 CA 给 `RUTIS_CA`。`--id` 每个进程唯一：两个进程用同一个 id 会互相接管。断开后自己重连：间隔从 0.5 秒起翻倍到 30 秒；token 或 id 被拒时每 30 秒重试；协议不兼容时以 1 退出；SIGTERM / Ctrl-C 卸载各行后以 0 退出。每次断开都卸载各行，重连是新的会话。状态行写在 stderr：`connected to …`、`connection lost (…); retrying in …`、`refused: auth-rejected (…)`、`refused: incompatible (…); stopping`。Python 拨出在 CPython 3.13.6 上也能用（监听仍不能）。
  - rutis 一侧：`rutis.json` 的 `runtimes.remote[]` 新增 `listen`（顶层 `listen` 里的监听器名）和 `instances`（一个 `instanced` 分组），两者一起写，不需要 link 行。一个监听器接受多条连接，所有连接出示同一个 token（`RUTIS_TOKEN_<名字>`，或 `RUTIS_TOKEN`），各自报一个 id。每条连接是分组的一个实例：连进来时创建，断开时关闭，同一 id 的新连接接管旧连接。分组里的行在每个实例中运行在这条连接上，它们提供的服务只在本实例里可见；连接里没有某个插件时，那一行只在这个实例里失败。只写了两者之一、监听器或分组不存在、缺 token 时，rutis-host 启动报错。
  - Rust 库：`rutis-bridge` 新增 `AccessPointPlugin`（一个监听器接受多条运行时连接）和身份层 `Admission`、`SharedToken`；`rutis-loader` 新增 `RuntimeInstances`（每条连接一个实例）。
- **Bun 运行时可以远程运行**（[#384](https://github.com/arcships/rutis/issues/384)）：Bun 运行时可以监听（`listen:wss://…`，证书用 `RUTIS_CERT`、`RUTIS_KEY`），也可以拨出；`runtimes.remote[]` 的 `language` 接受 `"bun"`，行名 `<运行时名>:<模块>`。
- **Go 运行时纳入等待环检测**（[#385](https://github.com/arcships/rutis/issues/385)）：Go 运行时声明 `sync-wait`。经 Go 插件的同步调用形成等待环时，调用方得到 `SyncWaitCycle`，不再可能卡死。现在 Node、Python、Bun、Go 四个运行时都在检测范围内。
- **文档**：应用集成的设计（[#381](https://github.com/arcships/rutis/pull/381)）；给编码 agent 的任务指南放在 `.agents/skills/`（远程插件、新增运行时；[#393](https://github.com/arcships/rutis/pull/393)）。

## 修复

- 行卸载后紧接着关闭运行时、或撤下运行时的全部服务时，如果另一个服务正在发布，被撤下的服务可能一直留在 rutis 里（[#372](https://github.com/arcships/rutis/issues/372)）。现在撤下总会做完。所有运行时都受影响，在 Bun 的测试里先发现。
- 0.10 的已知问题：各语言之间三处值的不一致（[#355](https://github.com/arcships/rutis/issues/355)）已随值类型一起处理：Python 的 `datetime`、`Decimal`、`UUID` 按值传；Go 结构体字段里的 `time.Time`、`[]byte` 和大整数逐个检查；Python dict 里值为 undefined 的键变成 `None`，与其他语言的 `null` 一致。

## 测试与质量

- 新增各语言拨出的一致性测试（`dial_conformance`）：Python、Node、Bun、Go 对同一个接入点跑同一组用例。
- CI 重新设计（每晚运行、发布门、自托管 runner）和几处偶发失败的修复，没有用户可见变化。

## 兼容

- **插件 API 2**：`definePlugin` / `define_plugin` / `rutis.Define` 标记的插件 API 版本改为 2（叶子事件）。0.11 的运行时继续接受 API 1 的插件。用 0.11 SDK 写的插件要在 0.11 的运行时上运行，旧运行时加载它时失败并说明要升级什么；Go 插件二进制还需要 0.11 的宿主。协议版本不变：本地会话仍是协议 2，带 endpoint 身份的会话是协议 3；Go manifest 格式不变。
- **SDK 的依赖**：`@arcships/rutis` 和 `@arcships/rutis-bun` 现在依赖 `@deepseek-ai/cordis` 4.0.4（一个包，没有传递依赖）。`@arcships/rutis` 过去没有依赖，它的测试工具现在在 Cordis 的事件服务上运行插件；插件运行时不加载测试工具。
- **`rutis.json`**：格式仍是 1。`runtimes.remote[]` 新增可选字段 `listen`、`instances`，`language` 新增 `"bun"`。以前的文件不用改；用了它们的文件 0.10 的 rutis-host 读不了。
- **值的传递方式有变化**（[设计](../design-value-types-2026-10-15.md) §八），插件代码可能要改：
  - Python：`datetime`、`Decimal`、`UUID` 过去按对象引用传（对端拿到代理），现在按值传。
  - Go：结构体里的 `time.Time`、`[]byte`、超出 ±(2^53−1) 的整数过去经 `encoding/json` 变成字符串、base64 或不检查，现在按各自的值类型传。
  - Go：`map[string]struct{}` 过去按对象传，现在按 Set 传。
  - Python：dict 里值为 `undefined` 的键过去被删掉，现在为 `None`，与其他语言一致。
  - 整数超出 ±(2^53−1) 过去由 Python、Go 发出时报错，由 Rust 发出时 JS 收到近似值，现在自动按大整数传，不用改写法；JS 收到它时是 `bigint`（范围内仍是 `number`）。JS 自己的 `number` 超出范围时照旧不精确，要精确用 `bigint`。
  - JS 收到的本地日期时间、日期、时刻、Decimal、UUID 是字符串；经 JS 原样转发时类型不保留；要以原类型发出或转发用 `rutis.datetime(…)`、`rutis.date(…)`、`rutis.time(…)`、`rutis.decimal(…)`、`rutis.uuid(…)`。
  - 0.10 里被拒绝的值（JS 的 `Date`、`Map`、`Set`、`Uint8Array`、`bigint`，Python 的 `set`、`bytes` 等）现在可以传，测试工具也不再拒绝它们。
- **与旧版本混用**：新值只发给 0.11 的对端。与 0.10 及更早的运行时之间，带新值的调用照旧失败（包括超出 ±(2^53−1) 的整数），其余调用不受影响。两端都升级到 0.11 才能传新值。
- **线上**：帧的深度上限从 144 层改为 208 层（一层 `map` 在线上占三层 JSON）；值的嵌套上限仍是 64 层。
- **Rust API**：
  - `rutis-bridge` 的 `session::Value` 加了十个变体，并标 `#[non_exhaustive]`：穷尽匹配 `Value` 的代码要加一支 `_ =>`。以后再加变体不再是不兼容变化。`Value` 现在实现 `PartialEq`。
  - `rutis-bridge` 的 `ChannelError` 新增变体 `Rejected`（对端在通道建立后拒绝本端的 id，WebSocket 关闭码 4003）：穷尽匹配它的代码要加一支。
  - Rust 一侧在握手里声明 `value-*` 能力（两种格式都声明）。
  - 新增 `RuntimePlugin::emits`、`LocalRuntime::emits`、`Process::plugins`，以及上文的接入点与 `RuntimeInstances`、`Unavailable`。
  - `rutis` 没有变化，`rutis-loader` 没有不兼容的变化。
- **dylib**：dylib 插件要用 0.11.0 的 SDK 重新编译。
- **最低版本不变**：Rust 1.88，Node 22，Python 3.10，Bun 1.4，Go 1.24。

## 已知问题

- Bun 分不清"服务端证书不受信任"和其他 TLS 握手失败，Bun 拨出时 TLS 握手失败一律按认证失败处理，每 30 秒重试。
- Windows 上的 Node 拨出靠控制台把 Ctrl-C 一并发给子进程来停止，没有在 Windows 上实测。
