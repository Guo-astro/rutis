# rutis 0.11.0（草稿）

[English](0.11.0.en.md) · [0.10.0 发布说明](0.10.0.md)

> 草稿：随 0.11 的各个 PR 补充，发布前定稿（[发布流程](../release.md)）。

## 新增

- **跨语言值类型**（[#308](https://github.com/arcships/rutis/issues/308)、[#355](https://github.com/arcships/rutis/issues/355)、[#360](https://github.com/arcships/rutis/issues/360)，[设计](../design-value-types-2026-10-15.md)）：会话协议新增十种带标记的值：时间点（`instant`）、本地日期时间（`datetime`）、日期（`date`）、时刻（`time`）、二进制（`bytes`）、Map（`map`）、Set（`set`）、大整数（`bigint`）、Decimal（`decimal`）、UUID（`uuid`）。线上格式与能力见[协议设计](../design-protocol-plugins-2026-09-25.md) §6.1。每种值一个能力 `value-<标记>`，只发给声明了它的对端；对端没有声明时只让这次调用失败，会话继续，协议版本号不变。
  - Rust（`rutis-bridge`）：`session::Value` 新增十个变体，以及类型 `Instant`、`DateTime`、`Date`、`TimeOfDay`、`BigInt`、`Decimal`、`Uuid`（rutis-bridge 自己的小类型，不引入 chrono、num-bigint、uuid），生成代码用的 `Bytes`、`ValueMap`、`ValueSet`。`Value::json()` 遇到新值时报错（同引用）。宿主转发调用时按下游对端的能力再检查；`Process::emit` 的参数按运行时的能力检查；节点之间转发的事件（`NodeEvent`）带新值时拒绝。
  - Cordis 生成器：`Date` → `Instant`，`Uint8Array` → `Bytes`，`bigint` → `BigInt`，`Map<K, V>` → `ValueMap<K, V>`，`Set<T>` → `ValueSet<T>`（键限于字符串、数字、布尔、bigint）；`ArrayBuffer`、`Buffer`、`DataView` 仍不绑定。
  - Node、Bun、Python、Go：（待补，#308 阶段 3）

## 兼容

- **Rust API**：
  - `rutis-bridge` 的 `session::Value` 加了十个变体，并标 `#[non_exhaustive]`：穷尽匹配 `Value` 的代码要加一支 `_ =>`。以后再加变体不再是不兼容变化。`Value` 现在实现 `PartialEq`。
  - Rust 一侧在握手里声明 `value-*` 能力（两种格式都声明）。
- **线上**：帧的深度上限从 144 层改为 208 层（一层 `map` 在线上占三层 JSON）；值的嵌套上限仍是 64 层。
- 与 0.10 及更早的运行时之间，带新值的调用照旧失败（对端没有声明能力），其余调用不受影响。两端都升级到 0.11 才能传新值。
- **插件代码可能要改的地方**（随 #308 阶段 3 落地，[设计](../design-value-types-2026-10-15.md) §八）：
  - Python：`datetime`、`Decimal`、`UUID` 过去按对象引用传（对端拿到代理），现在按值传。
  - Go：结构体里的 `time.Time`、`[]byte`、超出 ±(2^53−1) 的整数过去经 `encoding/json` 变成字符串、base64 或不检查，现在按值类型编码，超界的报错。
  - Python：dict 里值为 `undefined` 的键过去被删掉，现在为 `null`，与其他语言一致。
  - 整数超出 ±(2^53−1) 过去报错，现在自动按大整数传，不用改写法；JS 收到它时是 `bigint`（范围内仍是 `number`）。
  - JS 收到的本地日期时间、日期、时刻、Decimal、UUID 是字符串；经 JS 原样转发时类型不保留；要以原类型发出或转发用 `rutis.datetime(…)`、`rutis.date(…)`、`rutis.time(…)`、`rutis.decimal(…)`、`rutis.uuid(…)`。
