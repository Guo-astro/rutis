# rutis 0.8.0

[English](0.8.0.en.md) · [迁移指南](../migration-0.7-to-0.8.md)

0.8.0 带来 Windows 原生支持和按实例管理插件，并把内核与 dylib 工具链并入发布列车：从这一版起，所有 rutis 包用同一个版本号。

## 发布包

以下包版本均为 **0.8.0**：

| 注册表 | 包 |
| --- | --- |
| crates.io | `rutis`（内核）、`rutis-bridge`、`rutis-loader`、`rutis-host`；dylib 工具链 `rutis-sdk`、`rutis-dylib`、`rutis-dylib-meta`、`rutis-dylib-launcher`（首次发布到 crates.io） |
| npm | `@arcships/rutis`、`@arcships/rutis-runtime`、`@arcships/rutis-host`，以及四个平台的 host 包 |
| PyPI | `rutis`、`rutis-host` |
| GitHub | Linux / macOS，x64 / arm64 的 `rutis-host` 二进制与 SHA-256 校验文件 |

内核没有代码变更，从 0.6.1 直接升到 0.8.0 只为与列车对齐。`rutis-cli` 仍独立发版。

## 内容

- **Windows 原生支持**（x64，MSVC）：嵌入 Rust 时，Node / Python 语言运行时、远程运行时和跨语言共享服务都可以在 Windows 上运行。本地运行时通过 loopback 地址和一次性 token 接收通道；运行时进程加入随宿主关闭的 Job Object，宿主无论怎样退出都不会留下子进程；退出原因照常报告为 `RuntimeState::Down`。`Process::launch` / `Process::mount` 兼容接口及用它生成的 Cordis 挂载绑定也用同样的方式启动运行时。`rutis-host` 命令同样支持 Windows：发布页的二进制、`npx @arcships/rutis-host`（`@arcships/rutis-host-win32-x64`）和 `uvx rutis-host`（Windows wheel）；它在 `.venv\Scripts\python.exe` 找项目的虚拟环境，没有时使用 `python`。
- **实例组**：loader 可以管理应用在运行中创建的实例里的插件，例如每个会话一套。组上设置 `instanced: true`，用 `create_instance` / `remove_instance` / `restart_instance` 管理；配置修改、`reload` 和 `restart` 会作用到每个副本，任何一个副本失败都会回滚。
- **实例内的服务名**：服务名可以属于某类实例，在每个实例里解析为该实例自己的 key。配置和插件代码（Rust、TypeScript、Python）只写名字；语言运行时和节点互联都按实例隔离。
- **修复**：
  - 本地进程启动后立刻退出时，发送端也会报出它的退出状态，不再只报 `Broken pipe`。
  - 本机其他进程连上 loopback 监听端口却不发数据，不会再拖慢运行时进程的启动。
  - Python 运行时现在会应用行的 `isolate`。
- **发布**：PyPI 上的两个包各用自己的发布环境发布。

## 兼容

Rust 侧有几处不兼容的公开 API 变化：`Resolved` 改为用 `Resolved::new` 构造；`EntryStatus` 新增 `Stopped`，`Handover` 新增 `Loopback`；`EntryStatus`、`EntryInfo`、`InstanceInfo`、`Handover`、`Resolved` 标为 `#[non_exhaustive]`，之后再加字段或变体就不算破坏性变更。dylib 插件需要用 0.8.0 的 SDK 重新编译。详见[迁移指南](../migration-0.7-to-0.8.md)。

协议版本不变：本地会话仍是协议 2，带 endpoint 身份的会话是协议 3。宿主与语言运行时应使用同一列车版本，实例服务需要 0.8 的运行时。Node 要求 24+，Python 要求 3.12+。

## 开始使用

```bash
npx @arcships/rutis-host@0.8.0 new greeter --lang node
uvx --from rutis-host==0.8.0 rutis-host new greeter-py --lang python
```
