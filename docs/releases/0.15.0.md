# rutis 0.15.0

[English](0.15.0.en.md) · [0.13.0 发布说明](0.13.0.md)

0.15.0 带来两门新语言和应用托管：用 Swift 写 macOS 插件，用 Kotlin 写插件；iOS 与 Android 应用把自己和设备能做的事作为普通的 rutis 插件提供给 rutis，应用只负责开始和停止连接。Rust 服务在类型上标注 `#[rutis::service]` 即对所有语言可用。0.14 没有单独发布，它的内容（Swift 与 Kotlin SDK、Go 运行时的 `restart`）都在这一版里。升级不用改代码，见 [迁移到 0.15](../migration-0.15.md)。

## 新增

- **Swift SDK 与 macOS 插件**（[#386](https://github.com/arcships/rutis/issues/386)、[#387](https://github.com/arcships/rutis/issues/387)，[写一个 Swift 插件](../guide/swift-plugin.md)）：插件编译成二进制，一个二进制是宿主里的一个运行时进程；`rutis.json` 的 `runtimes.swift` 与 `runtimes.go` 写法相同（`start`、`idle`、`restart`），默认在有行用到时才启动。`rutis-host new --lang swift`、`dev`、`check` 都支持 Swift。日历、提醒事项这类要系统授权的能力，授权提示归属插件二进制。
- **Kotlin SDK**（[#390](https://github.com/arcships/rutis/issues/390)）：插件 API、统一事件、值与测试工具与其他语言一致；KSP 处理器 `rutis-ksp` 在编译期生成方法表与代理，运行时不做反射。首次发布到 Maven Central。
- **应用托管：iOS 与 Android**（[#389](https://github.com/arcships/rutis/issues/389)、[#391](https://github.com/arcships/rutis/issues/391)，[Swift 应用](../guide/swift-app.md)、[Android 应用](../guide/kotlin-app.md)）：插件编译进应用，应用用 `RutisApp` 开始、停止连接并观察状态；rutis 按自己的配置加载、配置、卸载这些插件。连接两个方向都可以：应用连进 rutis 的监听（远程运行时的 `listen` 与 `instances`，每台设备一个实例），或应用监听、rutis 拨过去。远程运行时的 `language` 接受 `"swift"` 与 `"kotlin"` / `"kt"`。
- **示例插件**（[#388](https://github.com/arcships/rutis/issues/388)）：Android 的 `contacts`、`notify`、`device`（`kotlin/rutis/android-sample`），iOS 示例应用；授权提示与拒绝在模拟器上验证，指南里有真机清单。
- **Rust 服务标注 `#[rutis::service]`**（[#510](https://github.com/arcships/rutis/issues/510)，[在 Rust 应用里嵌入](../guide/rust-host.md#在类型上标注-rutisservice)）：在服务的 `impl` 上标注、照常提供，各语言的行就能按名字调用它，内置插件与 dylib 插件都一样，不再需要 `build.rs` 清单。宏在新 crate `rutis-macros` 里，由 `rutis` 重新导出，`Cargo.toml` 不用加依赖。另有 `rutis-host types`，从 crate 生成 TypeScript 声明。
- **Go 运行时的 `restart`**：`runtimes.go` 和 Node、Python、Bun 一样接受 `restart`（`"no"`、`"on-failure"`、`"exit"`）。
- **`rutis-host check` 检查二进制的插件 API**：Go、Swift 二进制的插件 API 低于 3（rutis 0.13 以前的 SDK 构建）时报错，提示重新构建。

## 修复

- 连进来的运行时没有声明就提供的服务，本实例里的其他行现在用得到（#506）。
- 事件顺序：运行时按帧的顺序接收 emit 的回复，宿主对 emit 总是回复普通值；Node 运行时在同步等待期间也按帧序开始 emit 方式的监听器调用（#511、#513、#520）。插件代码不变，0.13 的宿主和运行时照常相连。
- 应用托管的评审修复：Swift 与 Kotlin 的 `RutisApp` 开始与停止按调用顺序进行，监听有升级时限，写有时限且不阻塞读与心跳（#519、#521）；在监督开始前就结束的 Go / Swift 运行时照样按 `restart` 处理（#518）。

## 测试与质量

- **跨版本相遇恢复正常工作**（`bridge/cross-version-meetings`）：发布门的跨版本测试与 0.13.0 相遇，两边都声明 `events-v2`，插件互相调用、事件双向通过；早于 0.13 的版本仍在握手时被拒绝（`events/old-peer-refused`）。
- **要系统授权、要设备的测试改为本地运行**（#514）：macOS 授权提示、iOS 与 Android 模拟器上的测试不在 CI 里跑，由维护者在本机运行；CI 照常跑其余全部测试。
- 端口不再先占后放：子进程自己绑定 `:0` 并报告地址，修掉 Windows 上的偶发失败（#455）。

## 兼容

- **不用改代码**。`rutis.json` 的 `format` 仍是 1，旧文件照旧读取；插件 API 仍是 3，会话协议版本不变。0.13 与 0.15 的宿主、运行时、节点可以混用。
- `rutis-loader` 里 Go 运行时的类型成了泛型类型的别名（`GoResolver` = `BinaryResolver<Go>` 等），原来的写法照旧编译；`cargo semver-checks` 把其中三个报成删除，是误报。`session::Dispatch` 与 `peer::Handler` 各多一个有默认实现的方法。细节见 [迁移到 0.15](../migration-0.15.md)。
- 写运行时或测试工具的作者：emit 的回复要按帧序接收，事件期望文件多了几个键，见 [迁移到 0.15](../migration-0.15.md#事件)。
