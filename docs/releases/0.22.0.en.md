# rutis 0.22.0

[中文](0.22.0.md) · [0.21.0 release notes](0.21.0.en.md)

**Release prep: 0.22.0 is not released.** The version bump, the persisted samples, the changelog row and the parts of the release gate a local machine can run are ready in the release PR (2026-11-17). These notes still cover only what is merged; "Before the release" at the end lists what is still missing: the whole gate as a CI dry run, the two-machine network smoke and the issues that are still open. Do not read this as a release.

0.22 folds 0.23's formal coverage into this release: the session protocol has a current specification, 1368 rules are in the rule tracker, the 7 TLA+ model directories (17 modules, 220 configurations) and the 16 kernel shuttle models were reconciled and filled in for 0.22; event-listener close admission now publishes a permanent marker when a subtree closes, and `Entry::live` no longer walks the ancestor chain on every call. No API a plugin sees is removed or renamed, and the wire format is unchanged. On the behaviour side it fixes a set of close, withdrawal, heartbeat and unknown-field edges. Read [migrating to 0.22](../migration-0.22.en.md) before upgrading.

## Behaviour changes

| Where | Before | Now |
| --- | --- | --- |
| An accepted `emit` dispatch meets `cancel` | `cancel` removed it from the queue and no listener ran | It dispatches as usual; the caller has given the call up, so it discards the late reply, and the session is unaffected ([#1121](https://github.com/arcships/rutis/issues/1121), [#1129](https://github.com/arcships/rutis/pull/1129)) |
| The host calls a listener the runtime has just withdrawn itself | Node and Bun threw `BindingError: listener <id> of <name> is withdrawn`; the other runtimes failed once | The call answers with no result (each language's own empty value); `waterfall` calls `next` and returns its value. An unknown id, and a row the host itself withdrew, still answer `listener <id> of <name> is withdrawn` ([#1135](https://github.com/arcships/rutis/issues/1135), [#1138](https://github.com/arcships/rutis/issues/1138), [#1137](https://github.com/arcships/rutis/pull/1137), [#1189](https://github.com/arcships/rutis/pull/1189)) |
| `ctx.provide` after a row starts unloading | Python and Bun accepted it; the service stayed in the table with no row, and Python announced it to the host if the unload had not finished | Refused as in Rust, Go, Kotlin and Swift: Python `RuntimeError: row <row> is not active`, Bun `Error: row <row> is not active`; no withdrawal is registered and no `service` frame is sent ([#1143](https://github.com/arcships/rutis/issues/1143), [#1149](https://github.com/arcships/rutis/pull/1149), [#1189](https://github.com/arcships/rutis/pull/1189)) |
| When a listening side's heartbeat starts | At accept or connection construction; a slow old-lease cleanup closed the new connection with 1001 before hello | After hello is sent successfully; Go, Swift, Node, Bun and Kotlin agree, so a slow cleanup no longer closes the new connection by mistake ([#1102](https://github.com/arcships/rutis/issues/1102), [#1182](https://github.com/arcships/rutis/issues/1182), [#1181](https://github.com/arcships/rutis/pull/1181), [#1183](https://github.com/arcships/rutis/pull/1183)) |
| Kotlin and Swift receive a frame with an unknown field | Ignored silently | Refused for that call: `unknown field "x" in invoke`, `code` is `bad-frame`, `data` is `{op, fields}`; `hello` fails the handshake (`incompatible session: unknown field "x" in hello`); `release`/`cancel` still ignore it ([#635](https://github.com/arcships/rutis/issues/635), [#1156](https://github.com/arcships/rutis/pull/1156)) |
| `filter(predicate)` returns a Promise / thenable / coroutine | Truthy, so every listener passed | The dispatch fails: Node and Bun `TypeError: a filter predicate must answer with a boolean, not a Promise`; Python `TypeError: a filter predicate must return a boolean, not an awaitable`, and the coroutine is closed first ([#637](https://github.com/arcships/rutis/issues/637), [#1156](https://github.com/arcships/rutis/pull/1156)) |
| A received reference's `origin` entry is not `<endpoint>:<n>` or `s<n>/<endpoint>:<n>` | Rust treated it as an ordinary call id | The session ends with `invalid reference`, as in Node, Python and Go ([#637](https://github.com/arcships/rutis/issues/637), [#1156](https://github.com/arcships/rutis/pull/1156)) |
| An `isolate` label contains U+0001 | Accepted; it shared a namespace with the labels the loader makes for row-leased services | The configuration is refused: `isolate.<name> of "<id>" must not contain U+0001: it is reserved for the loader's row labels` ([#637](https://github.com/arcships/rutis/issues/637), [#1156](https://github.com/arcships/rutis/pull/1156)) |
| A node-imported service announcement `services.announce` | `row` was `null`, so the importing side did not know the provider's row | It carries the provider's row id; it is absent when there is no row. An old peer ignores the optional field; a new peer reading an old announcement gets `None` ([#1171](https://github.com/arcships/rutis/issues/1171), [#1173](https://github.com/arcships/rutis/pull/1173)) |
| The host receives a row's `rows.unload` before the same key's `rows.load` | The later load mounted the row and left an orphan with no unload | The later load is refused: `<key> was unloaded`. The tombstone is per session; unloading a mounted row leaves none, so the same key loads in a new session ([#1101](https://github.com/arcships/rutis/issues/1101), [#1185](https://github.com/arcships/rutis/pull/1185)) |
| Node and Bun decide whether a synchronous wait is a cycle | A synchronous call whose reply had been read still counted in the wait chain, so `SyncWaitCycle` was occasionally reported by mistake | Only unanswered synchronous calls count; a real cycle is still refused ([#639](https://github.com/arcships/rutis/issues/639), [#1178](https://github.com/arcships/rutis/pull/1178)) |
| The failure this end reads when the far end rejects with 4003 | `peer disconnected` (transport) | `endpoint mismatch: <reason>`; both directions of a channel pair now get the same close reason ([#1130](https://github.com/arcships/rutis/pull/1130)) |

Other fixes:

- **Python's first import of a plugin**: on Windows, when the directory mtime fell on the same tick, a new file could be missing from `FileFinder`'s cached listing and the import failed with `ModuleNotFoundError`. The first `import_module` now calls `importlib.invalidate_caches()` first; the reload path is unchanged ([#1139](https://github.com/arcships/rutis/issues/1139), [#1140](https://github.com/arcships/rutis/pull/1140)).
- **Kotlin app hosting and Node/Bun force-kill**: after `stop()` returns, the app no longer dials or binds; a takeover kills the old runtime after `RUTIS_SHUTDOWN_TIMEOUT + 2s`, not a hard-coded 5 seconds ([#1096](https://github.com/arcships/rutis/pull/1096)).
- **Go reading a token line on Windows**: `bufio` swallowed the greeting that followed it, so every test-tool case reported `peer disconnected`; it now reads to the end of the line byte by byte and leaves the greeting for the next read ([#1087](https://github.com/arcships/rutis/pull/1087)).
- **Late entries after a provider is withdrawn**: once an `events` provider is withdrawn, an entry registered in the window is no longer inserted back into the table ([#1096](https://github.com/arcships/rutis/pull/1096)).

## Verification and models

- **Current specification**: `docs/protocol-session.en.md` has 83 `SESS-*` rules. The shared malformed-frame matrix has 25 cases, with an entry point in Rust, Node, Bun, Python, Go, Swift and Kotlin. Swift's cases compile on macOS only and run in CI's `runtimes-swift` job.
- **Rule tracker**: 1825 rows (219 register, 54 handwritten, 1552 protocol). The 1368 current protocol rules were re-extracted against the 0.22 sources, with the statuses above. `node tools/formal-trace.mjs` reports 0 problems, and the tracker check runs in CI. The 219 register rows and the 10 handwritten `ECA` rows have not been re-extracted row by row (the `TRC` 44 rows and all six protocol partitions have).
- **TLA+**: 7 directories, 17 modules, 220 configurations, each with an `expected.txt`; in `event-close`'s 7 configurations, 4 mutations violate `ClosingImpliesMarked`, `CommittedStaysOut` (twice) and `CleanupOnce`, so the model is not vacuous. CI's `specs` job runs every configuration of every model on PRs that change `specs/**` and in the nightly full run.
- **Shuttle**: 16 kernel models, each run 1,000,000 iterations every night by `stress.yml`, and a failure prints a schedule that can be replayed. When `#1025`'s marker publish order is written wrong, the model fails immediately with `this node is closing while its lineage marker is clear`.
- **Trace and conformance**: the channel/frame validator has 23 cases; the wait-graph trace records the six operations in `waits.rs` and replays them against `RustSucc`, and breaking the same log must be reported. The lease suite has Python, Go and Bun columns; `sync_cycles` lacks Kotlin and `host_gone` lacks Swift and Kotlin (Swift plugins build on macOS only, and Kotlin needs JDK 17 plus `:rutis-conformance:fatJar`).
- **Properties, fuzzing, Miri, Kani**: 6 grant-rollback properties, 5 value/frame/bad-frame properties, and the listener-table model property; 4 fuzz targets actually run with no crash; Miri ran 30 fixed inputs (13 frames, one over-deep nesting, 9 framing seeds, 7 error graphs) with no UB. Kani's 6 harnesses do not converge, so there is no conclusion and it is not written as passing.
- **Release-check numbers**: `node tools/check-guarantees.mjs` reports 219 rows and 1226 markers with 0 problems; the register's 40 core commitments have 0 unverified (33 verified, 7 partly verified); the tracker has one more unverified core commitment, `ECA-7`, outside the register.

## Explicitly not guaranteed

- **The trust boundary is not in this release** ([#1040](https://github.com/arcships/rutis/issues/1040)): a runtime row can announce any service name host-wide, and the host has no per-row policy to confine or reject it. 0.22 adds no `rutis.json` field, global allowlist, service namespace or dynamic-name `isolate`.
- **Delivery after a subtree closes**: the design's "`Ctx::emit()` itself does not fail only because a subtree closed, and does not reach that subtree's live listeners" is still a proposal; the existing service-after-stop test explicitly leaves delivery after a stop uncommitted (`crates/rutis/src/events/api.rs:453-480`, `crates/rutis/tests/service_emits.rs:70-83`). This release fixes only "no new listener call starts after the commit, and accepted calls drain".
- **Replies after a cancel**: `SESS-61` is still explicitly not guaranteed and the implementations have not agreed. Rust does not reply to a queued call or an `await`; it does run an accepted `emit` dispatch and leaves the reply for the caller to discard; other languages decide by method and signal. Cancel-table cleanup and the cancel-reply rule are [#1099](https://github.com/arcships/rutis/issues/1099).
- **Unknown fields are not an extension mechanism**: `SESS-69` does not guarantee that a new optional field whose meaning does not change arrives silently at an old receiver; an old implementation fails that call under `SESS-66`. A new frame or a changed meaning needs a protocol version bump; a new capability is used only when declared.
- **The implementation-level close-admission rules**: `ECA-7` (the race between registration and the marker pass) is unverified; dedicated cases for a `Loading` owner, `once` not being consumed, remote entries and multi-generation reloads are still missing. Rules 3, 6, 7, 8 and 9 in design §3 still read "proposal, not verified".
- **Formal coverage is not at the release gate yet**: 536 protocol rules in the tracker are unverified; [#613](https://github.com/arcships/rutis/issues/613), [#622](https://github.com/arcships/rutis/issues/622), [#624](https://github.com/arcships/rutis/issues/624), [#630](https://github.com/arcships/rutis/issues/630), [#631](https://github.com/arcships/rutis/issues/631), [#634](https://github.com/arcships/rutis/issues/634), [#635](https://github.com/arcships/rutis/issues/635) and [#776](https://github.com/arcships/rutis/issues/776) are still open. Kani has no conclusion; the Swift/Kotlin trace columns, the shuttle models for the session layer, event host, runtime supervision and host reload, and the `interleave.rs` reference model ([#1190](https://github.com/arcships/rutis/pull/1190)) are not done.
- **Still-open protocol and implementation gaps**: the protocol signal for an asynchronous call that is sent and forgotten versus one awaited later ([#1098](https://github.com/arcships/rutis/issues/1098)), cancel-table cleanup and the reply after a cancel ([#1099](https://github.com/arcships/rutis/issues/1099)), and the wait-graph blind spot under a single host worker ([#1103](https://github.com/arcships/rutis/issues/1103)). The further performance work in #1125 does not block 0.22.

## What developers see

| Role | What they see |
| --- | --- |
| Plugin authors | No new plugin API. To change: a `filter` predicate answers synchronously; do not call `ctx.provide` after a row starts unloading; do not treat unknown fields on Kotlin or Swift as an extension. A listener you withdrew yourself answering with no result is a loosening and needs no change. Heartbeats, a service's `row`, `SyncWaitCycle`, Python imports and Kotlin app hosting need no change. |
| Host owners and deployers | No new configuration, `rutis.json` field or protocol version: session protocol 4, `format` 1, plugin API 3. The texts and fields that change: a 4003 rejection is `endpoint mismatch: <reason>`; a node-imported `rutis/service` event's `row` is the provider's row id; an `unload` that overtakes its `load` gets `<key> was unloaded`. An old runtime package keeps its old behaviour, and the session still comes up. |
| Rust host authors | No kernel public API is removed or renamed, and `crates/rutis/public-api.txt` is unchanged; `rutis-bridge` only gains tracing and test-support types and functions. Close admission is an internal marker and changes neither the `shutdown` result nor the event protocol. `InactiveEffect` is still `fiber disposed`. |
| Runtime authors and contributors | The current session specification is `docs/protocol-session.en.md`; unknown fields, the malformed-frame matrix, the heartbeat start, the withdrawal race, the `provide` refusal and a service's `row` follow it. ## Compatibility

- The session protocol is still 4 (`ENDPOINT_PROTOCOL` in `crates/rutis-bridge/src/session/mod.rs`), `rutis.json`'s `format` is still 1, and the plugin API is still 3; no capability or handshake requirement is added, and no required field is added to a wire frame.
- Old and new versions mix: an old runtime package keeps the old behaviour on its side (old Kotlin/Swift still ignore unknown fields, for example), and the session still comes up. `services.announce`'s `row` is optional: an old peer ignores it, and a new peer reading an old announcement gets `None`.
- No public Rust API is removed or renamed; the kernel's public API snapshot `crates/rutis/public-api.txt` is unchanged. `rutis-bridge` only gains tracing and test-support types and functions; nothing is removed or renamed.
- A dylib plugin is rebuilt with 0.22.0's SDK, as with every release.
- `rutis.json` and the dsh user layer have no format change: the persisted sample is in `tests/fixtures/persisted/0.22.0/`, copied from 0.21.0, and the expectations do not change; `cargo test -p rutis-host --test persisted` and `cargo test -p rutis-dsh --test persisted` pass. The rest of the gate's results are in the next section.

## Upgrading

Most plugins and hosts need no code change. Three behaviour changes can be met: `filter(predicate)` must answer synchronously; `ctx.provide` must not be called after a row starts unloading; and a listener you withdrew yourself no longer fails with `withdrawn`, it answers with no result. Kotlin and Swift also no longer ignore unknown fields, and an `isolate` label must not contain U+0001. See [migrating to 0.22](../migration-0.22.en.md) for each change.
