# rutis 0.17.0

[English](0.17.0.en.md) · [0.16.0 发布说明](0.16.0.md)

0.17.0 收敛 Rust 的公开 API：写插件只有一种写法，宿主用的东西放进 `rutis::host`，并附带迁移工具 `rutis-migrate`。另外新增插件定义：一个插件可以作为值交给另一种语言的服务，由对方挂载。TypeScript、Python、Go、Swift、Kotlin 的插件代码不用改。

## Rust API

（[#617](https://github.com/arcships/rutis/issues/617)、[#643](https://github.com/arcships/rutis/pull/643)）

- **一种插件写法。** `impl Plugin`：`type Deps` 写依赖，`async fn apply(&self, ctx, deps) -> rutis::Result`。不写 `BoxFuture`、生命周期和 `Effect`；清理用 `ctx.effect(|| async move { … })`。
- **一种错误类型 `rutis::Error`。** `?` 接住任何标准错误；`err.kind()` 返回 `Option<&host::ErrorKind>`；几方共同持有的错误是 `Arc<ErrorKind>`。打开 `anyhow` feature 可以和 anyhow 互转。
- **事件方法在 `Ctx` 上。** `ctx.on::<E>`、`on_sync`、`listen`、`emit`、`parallel`、`serial`、`waterfall(e).terminal(t)`、`bail`，闭包不用标注类型。waterfall 的 `Call<E>` 拥有所有权，可以存起来、移进别的任务；每多一个监听器的开销和 0.16 持平（[#644](https://github.com/arcships/rutis/pull/644)）。
- **分层。** `rutis` 根上只有插件作者要用的 10 个名字：`Ctx`、`Plugin`、`Deps`、`Event`、`Disposer`、`Error`、`Result`、`Definition`、`service`、`serde`。宿主用的在 `rutis::host`（`CtxHost`、`DynPlugin`、`Key<T>`、`ErrorKind`、诊断）；rutis 自己的 crate 之间用的在隐藏的 `rutis::internal`，不承诺稳定。公开面由快照锁住，CI 任务 `public-api` 检查。
- **rutis-loader** 根上 11 个名字，其余在 `runtime`、`peer`、`report`、`edit`、`resolve` 模块；`Builtins::register("x", P::new)` 直接收构造函数。**rutis-sdk** 写成 `export_plugin!(id: "x", build: P::new)`。
- **`build.rs` 的服务清单删除**（[#647](https://github.com/arcships/rutis/issues/647)、[#648](https://github.com/arcships/rutis/pull/648)）：`Exports::service` / `service_in` 和 `include_exports!` 删除。Rust 服务只用 `#[rutis::service]` 对外；改不了源码的类型，包一层自己的类型再标注。`Exports` 只写 TypeScript 声明，输出不变。
- **迁移工具 `rutis-migrate`**（首次发布）：`cargo install rutis-migrate`，`rutis-migrate 0.17 path/to/crate --write`。它改写能自动改的地方，改不了的留一行 `// TODO(rutis 0.17): …`。见[迁移到 0.17](../migration-0.17.md)。

## 插件定义

（[#642](https://github.com/arcships/rutis/issues/642)、[#646](https://github.com/arcships/rutis/pull/646)，[设计](../design-plugin-values-2026-10-25.md)）

- **插件可以作为值传给服务。** Node、Bun 里 `definePlugin` 的结果（Node 也认 Cordis 的对象、函数、类插件）可以作为参数或返回值交给别的语言的服务。收的一方拿到 `rutis::Definition`，用 `ctx.plugin(def.at(&ctx, config)?)` 挂载。挂出的每一份在交出它的运行时里运行，看到的是挂载位置的服务。Rust 插件也可以用 `Definition::new(ctx, build)` 造一个。
- **跟着来源结束。** 交出定义的那一行（或造它的 Rust 插件）停下时，先结束它挂出的每一份并等清理完，再运行它自己的清理；`def.ended()` 在那时完成，之后 `at` 失败。定义只能挂在来源所在的实例里或更里面。
- **登记交给服务自己。** 怎样保存、挑选收到的定义由提供服务的插件决定，和 Cordis 一样；rutis 不提供注册表。
- 这一版支持 Rust、Node、Bun。Python、Go 和 Swift、Kotlin 还不能交出或收下插件定义，在后续版本里补上。用法见[插件 API](../guide/plugin-api.md#插件定义)。

## 兼容

- 只有 Rust 插件和 Rust 宿主要改代码：先运行 `rutis-migrate`，再按[迁移到 0.17](../migration-0.17.md)改剩下的。dylib 插件用新的 SDK 重新构建。
- 其他语言的插件代码不变，`rutis.json` 的格式不变。
- 协议新增能力 `plugins`（引用种类 `plugin`），只在两端都声明时使用。0.17.0 与 0.16.0 的宿主和运行时照常连接，只是不能传插件定义。
- `rutis::Error` 抛给其他语言时仍叫 `CordisError`，生成的 TypeScript 类型名仍是 `CordisErrorThrown`。
- 保证 `bridge/exported-services` 随服务清单撤回，它的规则并入 `bridge/marked-services`；新增 `core/definitions`、`bridge/plugin-values`、`loader/plugin-value-copies`。
