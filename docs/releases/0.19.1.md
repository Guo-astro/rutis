# rutis 0.19.1

[English](0.19.1.en.md) · [0.19.0 发布说明](0.19.0.md)

0.19.1 修复 0.19.0 开发者体验评估（[#663](https://github.com/arcships/rutis/issues/663)）里文档写明却做不到的几处，并补上 Dim 升级到 0.19 要用的三个 Rust API。插件代码、`rutis.json` 都不用改；下面的「行为变化」一节列出所有看得到的不同。

## 宿主

- **`ready()` 之后的 `reconcile` 一定装载运行时的行**（[#934](https://github.com/arcships/rutis/issues/934)、[#945](https://github.com/arcships/rutis/pull/945)）。照 [做一个开放插件的宿主](../guide/open-host.md) 先等 `RuntimeHandle::ready()` 再 `reconcile` 时，Node 运行时的行偶尔在 `reconcile` 返回后仍是 `waiting for runtime <名字>`，宿主这时找不到它的服务。现在 `reconcile` 返回时每一行要么在运行，要么列在 `failures` 里；不调 `follow_row` 的宿主也一样。运行时重启后（`restart()`，新进程 `ready()` 之后）它的行马上自己重新装载，不用调 `Loader::reload`；加载器正在做别的操作（例如一个还没返回的 `reconcile`）时，等那个操作结束。这一点 0.19.0 就是这样，现在写进了指南第 3 节。
- **同步 waterfall 补回，写成 `ctx.waterfall(event).sync(terminal)`**（[#946](https://github.com/arcships/rutis/issues/946)、[#947](https://github.com/arcships/rutis/pull/947)）。0.19.0 删掉了 `waterfall_sync`，迁移指南给的替代（异步 `waterfall`、同步 `bail`）串不成同步的中间件链。现在同一个 `waterfall` 用 `.sync(终态)` 结尾，同步地跑完：`on_sync` 登记的监听器照常调 `next`；`on` 登记的异步监听器、别的进程里的监听器以 `AsyncListener` 失败（`listener of t/draft in row chat, in another process, is asynchronous and cannot run in a synchronous waterfall`）。终态要求 `Send`。0.17 / 0.18 的 `waterfall_sync(event, terminal)` 写成 `waterfall(event).sync(terminal)`，[迁移到 0.19](../migration-0.19.md) 的对照表已改。
- **`Loader::instance_rows(instance)`**（[#941](https://github.com/arcships/rutis/issues/941)、[#960](https://github.com/arcships/rutis/pull/960)）：一个实例里现在运行着的行，`(行 id, FiberView)`，含嵌套实例，不含实例自己那一组；按配置与创建顺序；实例删除或不存在时为空。每次按当前状态读，不为每一行生成配置与 Schema（以前只能用 `entries()` 取全部再筛）。
- **别的语言的插件定义在宿主自己的实例里挂副本**（[#948](https://github.com/arcships/rutis/issues/948)、[#961](https://github.com/arcships/rutis/pull/961)）。`Definition::at` 挂副本时按插件在树上的位置算它所在的实例，不再要求是 loader 的实例。宿主用 `ctx.plugin` 挂一个普通插件，在它里面 `ctx.mark_scope("session")`，名字照旧用 `ServiceCatalog::register_shared_instance` 声明属于哪个分组，副本就解析到这个实例里的服务。`mark_scope` 从 `rutis::internal` 转成 `Ctx` 的公开方法，名字与行为不变。loader 实例里的副本不变。

## rutis-host

（[#935](https://github.com/arcships/rutis/issues/935)、[#944](https://github.com/arcships/rutis/pull/944)）

- **`run` / `dev` 启动时按插件的 Schema 校验行的配置**，和 `check`、运行中重读一样。以前 `check` 拒绝的配置，`run` 照常启动，插件收到错的值；现在这一行启动时失败：`greeter: config: greeting should be a string, got 3`。
- **uv 项目里 `add` 装的 Python 插件不再被 `uv sync` 删掉**。Python 运行时的项目目录（`runtimes.py.project`，默认 `rutis.json` 所在目录）有 `pyproject.toml` 与 `uv.lock`、宿主用的是那里的 `.venv`、并且装有 uv 时，`add` / `upgrade` / `remove` 用 `uv add --dev` / `uv remove --dev`，插件记进 `pyproject.toml`。其他情况照旧用 `uv pip`。

## 测试工具

- **TypeScript：调用不返回的测试超时失败后，进程退出**（[#933](https://github.com/arcships/rutis/issues/933) 的一条、[#943](https://github.com/arcships/rutis/pull/943)）。在 `node --test` 下（`npm test`、模板、CI），`node:test` 的 `timeout` 让测试失败后，`npm test` 打印汇总并以 1 退出；以前进程一直不退出，CI 挂住。直接 `node 文件` 运行时照旧。

## 文档

- [做一个开放插件的宿主](../guide/open-host.md) 第 5 节的 TypeScript 测试例子原样通过：测试里的假服务直接返回结果，并写明为什么（[#932](https://github.com/arcships/rutis/issues/932)、[#942](https://github.com/arcships/rutis/pull/942)）。
- Swift 插件指南第一段装上 `rutis-host`（`swift test` 要用它）（[#931](https://github.com/arcships/rutis/pull/931)）。

## 行为变化

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| `ready()` 后 `reconcile` 返回时 | 运行时的行可能仍是 `waiting for runtime <名字>` | 在运行，或在 `failures` 里 |
| `rutis-host run` / `dev` 启动时配置不合 Schema | 照常运行 | 这一行失败：`<行>: config: …` |
| uv 项目里 `rutis-host add` / `upgrade` / `remove` Python 插件 | `uv pip install` / `uninstall` | `uv add --dev` / `uv remove --dev`，写进 `pyproject.toml` |
| TypeScript 测试：调用不返回、`node:test` 超时 | 进程不退出 | 打印汇总，以 1 退出 |
| `Definition::at` 在宿主自己标记的实例里 | `"tools" is a service inside "session" instances: put the row in the "session" group` | 挂上，副本用所在实例的服务 |

## 兼容

- 协议不变，与 0.19.0 照常连接。`rutis.json`、`rutis.dev.json` 的格式不变。
- 新增的公开 API：rutis 的 `Waterfall::sync`、`Ctx::mark_scope`（从 `rutis::internal::CtxInternal` 移来，`use` 了那个 trait 的代码照常编译）；rutis-loader 的 `Loader::instance_rows`。
- uv 项目里，用 0.19.0 的 `add` 装、还没跑过 `uv sync` 的插件，0.19.1 的 `remove` 会因为 `pyproject.toml` 里没有它而失败：先 `uv pip uninstall --python .venv/bin/python <包>`，再跑一次 `rutis-host remove <行>`：它说这个包已经不在，照常删掉 `installed` 里的记录和这一行。跑过 `uv sync` 的，插件已经被删掉，重新 `add` 即可。
