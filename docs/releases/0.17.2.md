# rutis 0.17.2

[English](0.17.2.en.md) · [0.17.1 发布说明](0.17.1.md)

0.17.2 修复正在用 rutis 的人碰到的问题，都来自开发者体验评估（[#663](https://github.com/arcships/rutis/issues/663)）。所有语言的插件代码都不用改，`rutis.json` 不用改。下面的「行为变化」一节列出了所有看得到的不同。

## 一个插件的问题只留在它自己那里

- **坏的值只让这次调用失败**（[#675](https://github.com/arcships/rutis/issues/675)、[#706](https://github.com/arcships/rutis/pull/706)）。不能跨进程的值（带方法的对象、类的实例传给 Rust 以外的语言）、超过 16 MiB 的消息，以前让整个运行时进程退出，同一运行时里的插件一起停下。现在发送前就拒绝，只有这一次调用失败，错误写明方法、第几个参数和原因：`argument 1 of py_taker.take: an object with methods cannot cross to py; pass plain data or a function instead`。返回值写 `the result of …`。
- **稀疏数组能传了**：`[1, , 3]` 的空位按 `undefined` 传，到对面是 `null` / `None`。以前它让会话结束。
- **TypeScript 抛出的不是 `Error` 的值经过 Go 时不再让会话结束**：TypeScript 调用方收到原来的值。
- **运行时进程退出时不冤枉别的插件**（[#682](https://github.com/arcships/rutis/issues/682)、[#707](https://github.com/arcships/rutis/pull/707)）。以前同一运行时里正在加载的插件会被报成 `failed to start`。现在报告写明是哪个运行时退出、怎样退出的（退出码或信号），它的行都等这个运行时，正在加载的也一样；失败的进行中调用同样写明。运行时自己打印的错误和调用栈照常出现在输出里。
- **同名提供只让那一行失败**。一个插件提供宿主已有的服务名时，只有它这一行失败；用宿主那个服务的插件照常运行，隔离的作用域里也一样。以前同一运行时里另一个无辜的插件也启动失败。
- **宿主退出时，它启动的运行时一定退出**，插件在忙循环里也一样。Node、Bun 运行时里有一个守护线程：和宿主的连接断开后，超过关闭时限 1 秒进程还在，就结束它；Python 运行时同样从读连接的线程开始计时。以前宿主退出后，忙着的 Node 运行时会留下来成为孤儿进程。
- **远程运行时重新连上后，它的行全部按新的描述重新解析**（[#701](https://github.com/arcships/rutis/issues/701)）。以前连着时解析过的行不重新解析：远程那边换了插件（例如多用了一个服务），宿主仍按旧的描述装它。本机运行时不变。

一个运行时没就绪（例如挂上调试器后一直不问候）时拖住其他运行时的行，这个问题放到 0.18 和运行状态一起做（[#678](https://github.com/arcships/rutis/issues/678)）。

## 等待时写明在等什么

（[#676](https://github.com/arcships/rutis/issues/676) 前半、[#704](https://github.com/arcships/rutis/pull/704)）

- `rutis-host` 的等待行写明缺哪个服务、为什么缺：`weather: waiting for lmm (no row provides it; did you mean llm?)`、`chat: waiting for llm (row model failed: …)`、`waiting for llm (row model's runtime py is down)`、两行互相 `inject` 时写明。
- 插件用了没写进 `inject` 的服务时，错误说明要加进 `inject`：`service tsvc is not available to this plugin, which does not declare it in inject: add 'tsvc' to its inject`（Node、Bun、Python、Go、Swift、Kotlin 和测试工具同一句）。拿得到的服务照旧给。
- Rust 嵌入：插件等的服务一直没有提供者、满 10 秒时，错误汇集收到一次 `ErrorKind::StillWaiting`，写明缺哪个服务；`root.report_waiting_after(None)` 关掉，`Some(时长)` 改时间。`rutis-host` 不用它（等待行已经写明）。远程链路断开超过 10 秒时，链路自己的插件也会报一次，用的是内部名字（`rutis-bridge/import#main`）；0.18 改为平台自己的等待只在状态里显示（[#678](https://github.com/arcships/rutis/issues/678)）。
- `rutis-host check` 对互相 `inject` 的环、同一作用域里几行提供同一个服务给出警告，退出码不变（0.18 改为报错）。唯一提供某服务的行被禁用时，警告指出那一行。

## `rutis-host dev`

（[#665](https://github.com/arcships/rutis/issues/665)、[#703](https://github.com/arcships/rutis/pull/703)）

- 只重新加载文件变了的那一行，并写明原因：`weather: reloaded (src/index.ts changed)`；用到它的行随它重启，也写明：`caller: restarted (weather reloaded)`。
- `rutis.dev.json` 改了在运行中生效，规则同 `run --watch-config`。
- 新代码导入不了（语法错误）时，这一行继续运行原来的版本：`weather: cannot reload: …; the previous version keeps running`。
- 运行时进程停了，这个运行时的行下一次变化时重新启动它，不再打印假的 `reloaded`。运行时每次结束都打印 `runtime …: down`。
- Go、Swift 项目只在自己的源码变化时重新构建。修好 Go 插件 `apply` 里的 panic 后，不再打印旧的失败。

## 写宿主的人

（[#666](https://github.com/arcships/rutis/issues/666)、[#704](https://github.com/arcships/rutis/pull/704)、[#705](https://github.com/arcships/rutis/pull/705)、[#703](https://github.com/arcships/rutis/pull/703)）

- 行用到 `py`、`bun`、`node`，`runtimes` 里没写时，按默认设置启用并提示一次。这样启用的运行时起不来时宿主不退出，只有它的行失败。
- Python 环境不存在、或环境里没装 `rutis` 时，错误给出创建环境、安装的确切命令。
- [rutis-host 指南](../guide/rutis-host.md)开头加了「快速上手」（一个 TypeScript 插件、一个 Python 插件），新增「宿主怎样装插件」一节。
- `rutis-host new` 生成的模板写出 `provides`，新项目直接通过 `check --strict`。
- npm 装的 `rutis-host`：启动器把 SIGUSR1 转发给 `rutis-host`（`ExecReload=/bin/kill -USR1 $MAINPID` 可用），不再打开 Node 的调试端口。

## 插件对 SDK 的依赖

（[#672](https://github.com/arcships/rutis/issues/672)、[#705](https://github.com/arcships/rutis/pull/705)）

- Python 插件只写下限：`rutis>=0.17`，不再写 `<0.18`。插件和 Python 运行时是宿主环境里的同一个 `rutis`，上限会让宿主升级不了。Python 的 `rutis` 在插件 API 版本不变时不删、不改插件导入的名字。
- npm、Bun 插件仍写 `^` 范围：插件带着自己的一份 SDK，几份可以并存。

## Rust 嵌入

（[#667](https://github.com/arcships/rutis/issues/667)、[#705](https://github.com/arcships/rutis/pull/705)）

- 文档写准 `view.await` 等的是什么：排给插件的事处理完就返回；依赖缺着时插件停在 `Pending`，没有运行。要等到它运行，看 `view.watch()` 的状态。
- 新增 `rutis_bridge::session::call_service(&ctx, name, method, args)`：在 Rust 里按名字调用任何服务（任何语言的行提供的、标注了 `#[rutis::service]` 的、手写的）。
- [rust-host 指南](../guide/rust-host.md)的例子都能编译，第一个例子能运行；加载器例子补全了 `Builtins`、`Chain` 和绝对路径。

## 修复

- 模板与指南的小错（[#668](https://github.com/arcships/rutis/issues/668)）：TypeScript 模板 `npm pack` 先构建；Python 模板的测试命令；Go 指南的测试与 `rutis.dev.json` 写完整；`rutis-host types` 进了命令表。

## 行为变化

升级后看得到的不同，都不需要改代码：

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| 内核 `FiberView::restart` / `update` | 插件停在失败状态、依赖又不在时，返回上一次装载的错误 | 返回成功，插件等待依赖（这次重启没有装载，也就没有失败） |
| 内核错误汇集 | 插件等的服务一直没有提供者时什么都不报 | 满 10 秒报一次 `StillWaiting`；`report_waiting_after(None)` 关掉 |
| 跨进程的坏值 | 运行时进程退出 | 只有这次调用失败；错误以 `argument N of 服务.方法:` 或 `the result of 服务.方法:` 开头 |
| `rutis_bridge::session::Error::Value` 的文字 | 以 `invalid binding value: ` 开头 | 没有这个前缀 |
| 稀疏数组 | 会话结束 | 空位按 `undefined` 传 |
| `use` 没写进 `inject` 的服务（拿不到时） | `service x is not available` | 加一句要写进 `inject` |
| `rutis-host` 等待行 | `waiting for its services` | 写明缺哪个服务和原因（说不出原因时照旧） |
| `rutis-host check` | — | 依赖环、同名提供、被禁用的唯一提供者给出警告；退出码不变 |
| `rutis-host`：行用到没声明的运行时 | 行失败：`no plugin named "py:llmbox"` | 按默认设置启用并提示 |
| `rutis-host dev` | 改一个文件，同语言的行都重新加载；`rutis.dev.json` 改了不生效 | 只重新加载那一行并写明原因；`rutis.dev.json` 生效；处理 SIGUSR1 |
| `dev` 下运行时里的行因别的原因重启 | 读文件现在的内容 | 用最后一次重新加载时的代码（`run` 不变） |
| Python 运行时重新导入出错 | 留下改了一半的模块 | 放回改之前的内容 |
| npm 启动器收到 SIGUSR1 | Node 打开调试端口 | 转发给 `rutis-host` |
| Python 插件模板 | `rutis>=0.17.x,<0.18` | `rutis>=0.17.x` |
| 运行时进程退出时正在加载的行 | 失败，报 `failed to start` | 等这个运行时；30 秒内运行时结束的消息都没传到这一行时才失败 |
| Node 运行时：宿主提供的服务名已被某一行占用 | 报错，用这个服务的行失败 | 等占用它的那一行的服务撤下后再登记 |
| Node、Bun 运行时进程 | — | 多一个守护线程：连接断开后超过关闭时限 1 秒仍在就结束进程，并在 stderr 写一行 |
| Python 运行时的关闭时限 | 从主线程看到连接断开时算 | 从读连接的线程看到断开时算；放弃时的提示多一句「或者插件让运行时一直在忙」 |
| 远程运行时重新连上 | 连着时解析过的行不重新解析 | 它的行全部重新解析 |
| rutis-bridge `RuntimePlugin` | 先提供 `Runtime` 服务，再把状态设为 `Ready` | 先设为 `Ready`，再提供服务（提供失败时回到 `Starting`） |

## 兼容

- 没有 API 删除或改名，`rutis.json`、`rutis.dev.json` 的格式不变，不需要迁移。
- 协议不变。0.17.2 与 0.17.1、0.17.0、0.16.0 照常连接。宿主在转发前检查值，所以旧运行时配新宿主时，坏的值同样只让这次调用失败；旧 Node 运行时发出的稀疏数组仍让会话结束。
- 新增的公开 API：rutis 的 `CtxHost::report_waiting_after`、`CtxHost::name_keys_with`、`KeyNamer`、`ErrorKind::StillWaiting`；rutis-bridge 的 `session::call_service`、`RuntimeHandle::starts`、`Sender::max_message`（有默认实现）、`Wire::no_caller`（有默认实现）；rutis-loader 的 `Loader::waits`、`Loader::waits_of`、`report::Wait`、`report::WaitReason`、`CheckReport` 的 `cycles` 与 `clashes`、`Requirement::like`、`Supply::OnlyDisabled`、`BinaryRuntimesHandle::states_started`。
