# rutis 0.17.0

[中文](0.17.0.md) · [0.16.0 release notes](0.16.0.en.md)

0.17.0 converges the public Rust API: a plugin is written one way, what hosts use moved to `rutis::host`, and a migration tool, `rutis-migrate`, comes with it. It also adds plugin definitions: a plugin can be handed as a value to a service in another language, which mounts it. TypeScript, Python, Go, Swift and Kotlin plugin code does not change.

## Rust API

([#617](https://github.com/arcships/rutis/issues/617), [#643](https://github.com/arcships/rutis/pull/643))

- **One way to write a plugin.** `impl Plugin`: `type Deps` names the dependencies, `async fn apply(&self, ctx, deps) -> rutis::Result`. No `BoxFuture`, lifetimes or `Effect`; cleanups are `ctx.effect(|| async move { … })`.
- **One error type, `rutis::Error`.** `?` takes any standard error; `err.kind()` returns `Option<&host::ErrorKind>`; an error several parties hold is `Arc<ErrorKind>`. The `anyhow` feature converts to and from anyhow.
- **Event methods are on `Ctx`.** `ctx.on::<E>`, `on_sync`, `listen`, `emit`, `parallel`, `serial`, `waterfall(e).terminal(t)`, `bail`, with closures that need no type annotations. A waterfall's `Call<E>` is owned, so it can be stored or moved into another task; each further listener costs what it did in 0.16 ([#644](https://github.com/arcships/rutis/pull/644)).
- **Layers.** The `rutis` root has only the 10 names plugin authors use: `Ctx`, `Plugin`, `Deps`, `Event`, `Disposer`, `Error`, `Result`, `Definition`, `service`, `serde`. What hosts use is in `rutis::host` (`CtxHost`, `DynPlugin`, `Key<T>`, `ErrorKind`, diagnostics); what rutis's own crates share is in the hidden `rutis::internal`, with no stability promise. A snapshot locks the public surface, checked by the CI job `public-api`.
- **rutis-loader** has 11 names at its root and the rest in the modules `runtime`, `peer`, `report`, `edit` and `resolve`; `Builtins::register("x", P::new)` takes the constructor. **rutis-sdk** is `export_plugin!(id: "x", build: P::new)`.
- **The `build.rs` service list is removed** ([#647](https://github.com/arcships/rutis/issues/647), [#648](https://github.com/arcships/rutis/pull/648)): `Exports::service` / `service_in` and `include_exports!` are gone. Rust services are exposed only with `#[rutis::service]`; a type whose source you cannot change is wrapped in a type of your own, which is marked. `Exports` only writes TypeScript declarations, with unchanged output.
- **The migration tool `rutis-migrate`** (first release): `cargo install rutis-migrate`, `rutis-migrate 0.17 path/to/crate --write`. It rewrites what it can and leaves a `// TODO(rutis 0.17): …` line where it cannot. See [migrating to 0.17](../migration-0.17.en.md).

## Plugin definitions

([#642](https://github.com/arcships/rutis/issues/642), [#646](https://github.com/arcships/rutis/pull/646), [design](../design-plugin-values-2026-10-25.en.md))

- **A plugin can be passed to a service as a value.** In Node and Bun, the result of `definePlugin` (in Node, Cordis object, function and class plugins too) can be an argument or return value of a service in another language. The receiver gets a `rutis::Definition` and mounts it with `ctx.plugin(def.at(&ctx, config)?)`. Each copy runs in the runtime that handed it over and sees the services where it is mounted. A Rust plugin can make one too, with `Definition::new(ctx, build)`.
- **It ends with its source.** When the row that handed the definition over (or the Rust plugin that made it) stops, every copy it mounted ends first and its cleanups finish, then the source's own cleanups run; `def.ended()` completes then, and `at` fails after that. A definition mounts only in its source's instance or further inside.
- **Keeping them is the service's business.** How received definitions are kept and chosen is up to the plugin that provides the service, as in Cordis; rutis has no registry for them.
- This release supports Rust, Node and Bun. Python, Go, Swift and Kotlin cannot hand over or receive plugin definitions yet; later releases add them. How to use them: [plugin API](../guide/plugin-api.en.md#plugin-definitions).

## Compatibility

- Only Rust plugins and Rust hosts change code: run `rutis-migrate` first, then fix the rest by [migrating to 0.17](../migration-0.17.en.md). Dylib plugins are rebuilt with the new SDK.
- Plugin code in the other languages and the `rutis.json` format are unchanged.
- The protocol adds the capability `plugins` (the reference kind `plugin`), used only when both ends declare it. 0.17.0 and 0.16.0 hosts and runtimes connect as before; they just cannot pass plugin definitions.
- `rutis::Error` is still thrown as `CordisError` in other languages, and the generated TypeScript type is still `CordisErrorThrown`.
- The guarantee `bridge/exported-services` is withdrawn with the service list, its rules merged into `bridge/marked-services`; `core/definitions`, `bridge/plugin-values` and `loader/plugin-value-copies` are new.
