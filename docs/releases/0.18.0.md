# rutis 0.18.0

[English](0.18.0.en.md) · [0.17.2 发布说明](0.17.2.md)

0.18.0 的主题是「出错时看得懂」（[#694](https://github.com/arcships/rutis/issues/694)，[诊断设计](../design-diagnostics-2026-10-26.md)）：出错时写明是哪一行、在做什么、在哪个文件哪一行，不出现 rutis 的内部名字；可以问正在运行的宿主它现在在做什么；配置按 Schema 校验并补默认值。这一版有不兼容的改动，升级前先看[迁移到 0.18](../migration-0.18.md)。

升级的顺序：先用 0.17.2 跑一遍 `rutis-host check`，它给出的告警在 0.18 里是错误；升级后再用 0.18 跑一遍 `rutis-host check`，它列出每一行不合格的配置。

## 不兼容的改动

每一条写了要改什么，细节和例子见[迁移到 0.18](../migration-0.18.md)。

- **出错文字变了，改按错误码判断**（[#677](https://github.com/arcships/rutis/issues/677)、[#711](https://github.com/arcships/rutis/pull/711)、[#737](https://github.com/arcships/rutis/pull/737)）。错误类型名不变（`BindingError`、`AggregateError`、`SyncWaitCycle` 等），文字只写开发者写过的东西：行名、服务名、方法名、第几个参数、文件和行号。rutis 自己的 `BindingError` 带错误码：`not-declared`、`unavailable`、`no-method`、`bad-argument`、`bad-value`、`peer-gone`、`bad-config`，细节在 `data`。
  - 要改的：按文字匹配错误的代码改为看错误码（JavaScript、Python 的 `error.code`，Go `*rutis.RemoteError` 的 `Code`，Swift、Kotlin 的 `code`，Rust 的 `session::Error::code()`）；解析 `rutis-host` 打印的错误的脚本按新格式改。
  - Node、Bun：收到的跨语言错误，`error.stack` 是调用方自己的堆栈，对面的堆栈由 rutis 打印。
  - Python：导入插件模块出错时抛出新的 `LoadError`；`str(SyncWaitCycle)` 只是消息。
  - Kotlin：没写进 `inject`、服务不在、宿主断开时，抛出新的 `NotDeclaredException`、`UnavailableException`、`HostGoneException`。它们是原来那几个类型的子类，接住原来类型的代码照常工作。
- **Rust 宿主读插件的错误要换写法**（[#677](https://github.com/arcships/rutis/issues/677)）。插件的错误不再是字符串：用 `rutis_bridge::thrown(&error)` 读出结构，用 `rutis_bridge::report::report(&error)` 打印。`rutis_bridge::session::Error` 新增分支 `Binding { code, message, data }`，逐个分支 `match` 的代码要加上这一支。`ErrorKind::PluginFailed` 显示时没有 `plugin failed: ` 前缀。
- **Rust 嵌入默认把错误写到标准错误**（[#678](https://github.com/arcships/rutis/issues/678)、[#741](https://github.com/arcships/rutis/pull/741)）。以前没人等的插件启动失败、运行时进程结束，只在没人读的返回值里；现在默认的错误汇集把它们写出来，每行以插件、行或运行时的名字开头，不再以 `[rutis]` 开头。新增 `ErrorKind::StartFailed`、`RuntimeDown`、`NotServedByName`；`DisposeWaitError::TimedOut` 多了字段 `stuck`。
  - 要改的：不想要这些输出时换掉汇集；按 `[rutis]` 匹配标准错误的脚本要改；列出全部字段解构 `TimedOut` 的代码加上 `..`。
- **Rust 嵌入：`reconcile` 不再等还在启动的运行时**（[#743](https://github.com/arcships/rutis/pull/743)）。一个运行时卡住时，其他行照常启动，它的行先等这个运行时。要和以前一样拿到完整的报告，先等运行时的 `ready()`，再调用 `reconcile`。
- **`rutis-host` 的状态行写到标准错误，`dev` 里插件的每一行带行名**（[#746](https://github.com/arcships/rutis/pull/746)）。`weather: running`、`runtime py: down (…)`、`rutis-host: listening on …` 等以前写到标准输出。`dev` 下插件的输出前面加 `[weather] `。
  - 要改的：从标准输出读状态行的脚本改读标准错误；按整行比较插件输出的脚本，在 `dev` 下加 `--no-prefix-output`。`run` 默认不加前缀，`--prefix-output` 打开。
- **`rutis-host check`：依赖环和同名提供改为报错**（[#676](https://github.com/arcships/rutis/issues/676)、[#725](https://github.com/arcships/rutis/pull/725)）。0.17.2 里只是告警，现在以 1 退出。
  - 要改的：几行互相 `inject` 时，去掉不需要的服务，或把共同的部分拆成第三行；几行提供同一个服务时只留一行，或用 `isolate` 隔开。
- **两个条目接受同一个 token 时启动即报错**（[#702](https://github.com/arcships/rutis/issues/702)、[#726](https://github.com/arcships/rutis/issues/726)、[#724](https://github.com/arcships/rutis/pull/724)、[#756](https://github.com/arcships/rutis/pull/756)）。同一个监听器上的任意两个条目，或不同监听器上的两个监听节点行（被禁用的行也算），会接受同一个 token 时，`run`、`check`、重新读配置都在启动前报错。这样的配置在 0.17 里本来就有一边连不上。
  - 要改的：按提示给其中一个设单独的 `RUTIS_TOKEN_<名字>`，对端也出示这个新 token。
- **没处理的错误只算到产生它的那一行**（[#688](https://github.com/arcships/rutis/issues/688)、[#729](https://github.com/arcships/rutis/pull/729)）。Node、Bun 插件没处理的 promise 拒绝不再让运行时进程退出：追得到来源时那一行失败，追不到时写一行 `an unhandled error from an unknown row`。Python 任务里没人取的异常以前只记一行日志，现在让这一行失败。
  - 要改的：Python 里自己启动的任务要处理或取走它的异常；Node、Bun 里靠「运行时退出、宿主重启运行时」来恢复的项目，改为在插件里处理错误，确实要结束进程时显式调用 `process.exit`。
- **带方法的对象可以传给任何语言**（[#687](https://github.com/arcships/rutis/issues/687)、[#738](https://github.com/arcships/rutis/pull/738)、[#751](https://github.com/arcships/rutis/pull/751)、[#753](https://github.com/arcships/rutis/pull/753)，[设计](../design-object-refs-2026-10-27.md)）。以前只能传给 Rust，传给别的语言时这次调用失败；现在按引用传，对方拿到代理，方法调用的是原对象。
  - 要改的：以前在失败后改传数据的代码不会再走到 `catch`，对方要数据就直接传数据。两端都要升级到 0.18：0.18 之前的运行时不收对象，这次调用以 `bad-value` 失败并写明要升级。
  - Go、Swift、Kotlin 里参数是数据类型时，收到对象以 `bad-argument` 失败。Kotlin 里类型为 `Any?` 的参数可能收到新的 `RemoteObject`。自己实现 Swift `RutisProxy` 的代码要加上 `rutisClient`。
  - 数组、对象等值里面的 `undefined` 一律变成 `null`（Python 收到 `None`）。以前作为参数的数组里的 `undefined` 会保留下来。
- **配置按 Schema 校验并补默认值**（[#669](https://github.com/arcships/rutis/issues/669)，[设计](../design-config-schema-2026-10-27.md)；[#727](https://github.com/arcships/rutis/pull/727)、[#740](https://github.com/arcships/rutis/pull/740)、[#742](https://github.com/arcships/rutis/pull/742)、[#747](https://github.com/arcships/rutis/pull/747)、[#748](https://github.com/arcships/rutis/pull/748)、[#750](https://github.com/arcships/rutis/pull/750)）。插件 API 指南早就写着宿主按 Schema 校验配置，这一版才做到。Rust 的行、Node、Bun、Python、Swift、Kotlin 在 `apply` 之前补上 Schema 里的默认值；不合格时这一行失败，错误码 `bad-config`，宿主打印 `weather: config: city should be a string, got 42`，每个问题一行。多出来的键只告警，`check --strict` 下是错误。
  - 要改的：以前写错也能运行的配置（类型不对、缺 `required` 的字段、`additionalProperties: false` 下多出来的键）现在让这一行失败，测试工具里也一样；按 `rutis-host check` 的输出改配置或 Schema。判断「配置里有没有这个键」的代码现在会看到默认值。
  - Node、Bun：`definePlugin` 的 `config` 传 Standard Schema 对象时立即报错（这样的 Schema 以前从没生效）。
  - Swift：带字面量初始值的 `var` 字段不再必填，没写时用初始值。
  - Rust：loader 的行的配置错误文字从 `config validation failed: [...]` 变为 `config: …`。
  - Go 先补默认值、校验再解码，生成的 Schema 不再有 `required`（[#752](https://github.com/arcships/rutis/pull/752)）。
  - 配置的文档、Python 与 Go 指南、《迁移到 0.18》的配置一节、模板的默认值只写在 Schema 里（[#754](https://github.com/arcships/rutis/pull/754)）。

## 新功能

- **`rutis-host status`**（[#678](https://github.com/arcships/rutis/issues/678)、[#739](https://github.com/arcships/rutis/pull/739)）：在另一个终端里问正在运行的 `run` 或 `dev` 现在在做什么：每一行的状态与原因、每个服务由谁提供、各运行时、还没返回的调用和已经等了多久。启动卡住时也能问。Windows 上不提供。Rust 嵌入用 `Loader::status()` 拿到同一份快照。
- **出错时写明在哪里**（[#677](https://github.com/arcships/rutis/issues/677)）：`run`、`dev` 打印的失败先说失败在哪一步，下面写出错的行、插件语言给出的文件和行号，跨语言时再写调用方的位置。跨进程的堆栈只有插件自己的帧。
- **`rutis-host dev --debug`**（[#679](https://github.com/arcships/rutis/issues/679)、[#728](https://github.com/arcships/rutis/pull/728)）：Python 停在 `breakpoint()`（pdb），Node、Bun 打开检查器端口，Go 在 Delve 下运行；`dev` 先打印怎样连上。各语言指南加了「调试」一节。Swift 暂不支持。
- **同步阻塞提示**（[#746](https://github.com/arcships/rutis/pull/746)）：Node、Bun、Python 的服务方法同步占住运行时满 5 秒时，打印一次是哪一行的哪个方法，并提示改成异步。只提示，不打断方法。
- **Rust 嵌入看得懂**（[#741](https://github.com/arcships/rutis/pull/741)）：`root.diagnostics()` 可以直接打印（一项一行，用名字）；`shutdown_with_timeout` 到时写明还没结束的插件，以及卡住的清理在哪个文件哪一行注册。
- **一个运行时没就绪不拖住其他运行时的行**（[#743](https://github.com/arcships/rutis/pull/743)）：例如一个运行时挂着调试器、一直不问候时，别的运行时的行照常启动。
- **Rust 插件写错时的编译错误说人话**（[#677](https://github.com/arcships/rutis/issues/677)）：参数不能跨语言、错误类型没有 `Display`、服务类型不是 `Send + Sync` 等，第一行写明哪里不对、怎么改。
- **`rutis-host check` 检查每一行的配置**（[#727](https://github.com/arcships/rutis/pull/727)）：不合格时写明路径和原因，以 1 退出；Schema 要运行时才知道的行写 `config not checked`。
- **开发者体验检查进发布门**（[#690](https://github.com/arcships/rutis/issues/690)、[#744](https://github.com/arcships/rutis/pull/744)、[#758](https://github.com/arcships/rutis/pull/758)）：每种语言写插件、组装插件、宿主持有者三类场景，以及 14 种故障在各语言的验收，发布门和每晚都跑，不通过不发布（[故障验收汇总](../faults.md)）。

## 修复

- 等运行时状态时不再漏掉「看过之后、开始等之前」的变化（[#759](https://github.com/arcships/rutis/pull/759)）。以前负载高时，运行时恰好在这个间隙里就绪，会被当成启动失败；`rutis-host` 的重启监督也去掉了每 500 毫秒再看一次的绕行。
- 运行时主动连进来的连接在它的行还在加载时断开，这个实例立即结束（[#779](https://github.com/arcships/rutis/pull/779)）。以前要等满 30 秒才结束，这期间同一个连接的后续处理被拖住。
- 依赖的安全更新（[#755](https://github.com/arcships/rutis/pull/755)）：rustls 0.23.46、rustls-webpki 0.103.16、webpki-roots 1.0.11、tokio 1.54.1。影响本仓库构建的 `rutis-host` 二进制（含 npm、PyPI 里的那份）；把 crate 当库用的项目按自己的锁文件取版本。
- 带方法的对象在会话之间转发时，调用链上的编号换成对方的（[#760](https://github.com/arcships/rutis/pull/760)）。以前主机处理一个会话的调用时创建的 future 发给另一个会话、或会话等待 future 时再调用别的会话的对象，对方会把原样的编号当成自己的调用。
- Kotlin 的 `HostGoneException` 移到公开的 `arcships.rutis`，和 `NotDeclaredException`、`UnavailableException` 放在一起（[#761](https://github.com/arcships/rutis/pull/761)）。以前它在内部包 `arcships.rutis.internal.peer` 里；从那里导入的代码改成从 `arcships.rutis` 导入。

## 兼容

- `rutis.json`、`rutis.dev.json` 的格式不变。配置的内容可能因为 Schema 校验而不再通过，见上面「配置按 Schema 校验并补默认值」。
- 协议新增能力 `objects`（带方法的对象），两端都声明才用；错误节点多两个可选字段 `site`、`rethrown`，旧的一端忽略它们。协议版本不变，0.18.0 与 0.17.2 照常连接，只是不能把对象传给旧的一端。
- 0.17.2 的宿主不认得 0.18 运行时收对象：它下面的运行时之间传对象，照旧以 0.17.2 的文字失败；升级宿主。
- dylib 插件照每次发布一样用 0.18 的 SDK 重新构建。
- 错误类型名不变；`rutis::Error` 抛给其他语言时仍叫 `CordisError`。
