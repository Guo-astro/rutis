# rutis 0.16.0

[English](0.16.0.en.md) · [0.15.1 发布说明](0.15.1.md)

0.16.0 保留 0.15.1 引入的平总线，删掉那个版本为了保持 patch 兼容而留下的转接层。0.15.1 之后已经就绪的修复也一并发布。

## 事件

- **一条平总线。** 一个 root 总线上同名事件的所有监听器都收到，无论在哪个实例、运行时或相连的节点；作用域只是过滤用的描述，不是送达规则。这是 0.15.1 的行为，没有变化。
- **删掉 0.15.1 的兼容层。** `Dispatch::scope`、`scope_contains`、各 SDK 的 `inScope` / `within` / `events.Within`、Node 的 `h.at(scope)` 与 Python 的 `Bus.emitter(scope)` 删除。见[迁移到 0.16](../migration-0.16.md)。
- 节点连接仍只见到它的 `export` / `import` 名单承载的名字；引进的条目不再转发。

## 修复

- **带 `#[cfg]` 的 `#[rutis::service]` 方法**只在包含它的构建里检查，错误跟随方法与 impl 的 cfg（[#591](https://github.com/arcships/rutis/pull/591)）。
- **导出里的泛型别名实参**在书写处解析，经 `pub type` 声明的 `Result<Thing>` 能找到 `Thing`（[#598](https://github.com/arcships/rutis/pull/598)）。
- **`rutis-host dev` 的编译型项目**在只有 Python/TypeScript 行源码变化时也会重新加载；Go/Swift 源码变化照旧重新构建（[#588](https://github.com/arcships/rutis/pull/588)）。
- **`Ctx::is_shutting_down()`** 直接读 root 的关闭标志，不构建诊断快照；loader 创建实例使用它（[#608](https://github.com/arcships/rutis/pull/608)）。

## 兼容

- 事件线上格式不变。0.15.1 与 0.16.0 的宿主和运行时可以连接，但仍在 0.15.1 的一端会继续按自己的作用域过滤；要让各处都按平总线送达，所有端都要升级。
- 调用了已删除作用域辅助函数的 Rust/SDK 用户需要迁移；`ListenerInfo::scope` 与 `Ctx::scope()` 保留。
- `events/scope` 与 `events/hub-scope` 保持撤回；当前保证是 `events/flat` 与 `events/hub-flat`。
