# rutis 0.10.0

[English](0.10.0.en.md) · [0.9.1 发布说明](0.9.1.md)

0.10.0 是一个质量版本：按[第二步质量方案](../design-quality-step2-2026-10-11.md)补上跨进程、跨平台的测试，并修复这些测试找出的缺陷。新增的功能只有三项：`rutis.json` 的格式版本、`rutis-host run` 打印 link 状态和监听地址，以及运行时输出按整行转写。其余都是修复。有几处行为改为明确报错，见下文的"兼容"。

## 发布包

以下包版本均为 **0.10.0**：

| 注册表 | 包 |
| --- | --- |
| crates.io | `rutis`（内核）、`rutis-bridge`、`rutis-loader`、`rutis-host`；dylib 工具链 `rutis-sdk`、`rutis-dylib`、`rutis-dylib-meta`、`rutis-dylib-launcher` |
| npm | `@arcships/rutis`、`@arcships/rutis-runtime`、`@arcships/rutis-bun`、`@arcships/rutis-host`，以及五个平台的 host 包 |

| Go | `github.com/arcships/rutis/go/rutis`（tag `go/rutis/v0.10.0`） |
| GitHub | Linux / macOS（x64 / arm64）和 Windows（x64）的 `rutis-host` 二进制与 SHA-256 校验文件 |

`rutis-cli` 仍独立发版。

## 新增

- **`rutis.json` 的格式版本**（[#207](https://github.com/arcships/rutis/issues/207)）：顶层 `"format": 1`。可以省略，省略时按 1 读，所以以前的文件不用改。文件的格式比 rutis-host 支持的新时，rutis-host 在读其他字段之前就拒绝，并提示升级 rutis-host。`rutis-host new` 生成的文件会写上它。0.8.0 起每个已发布版本的 `rutis.json` 都存了样本，测试保证它们仍按当时的含义读出。dsh 的 `cordis.patch.yml` 是 Cordis 的配置格式，不加版本。
- **`rutis-host run` 打印 link 状态和监听地址**（[#321](https://github.com/arcships/rutis/issues/321)）：启动时，每个监听器打印一行实际绑定的地址：`rutis-host: listening on <名字> <地址>`。节点行的 link 状态变化时各打印一行：`link connected`、`link down (<原因>); retrying in …`、`link refused: auth-rejected (<原因>)`、`link stopped: incompatible (<原因>)`。token 被拒、证书不受信任和对端没启动，现在能从输出上分开。输出里不出现 token。
- **运行时的输出按整行转写**（[#332](https://github.com/arcships/rutis/issues/332)）：Node、Bun、Python、Go 运行时写到 stdout、stderr 的每一行，原样、整行地出现在 rutis-host 的同一个流上，不再和 rutis-host 自己的行拼在一起。插件把一行分几次写也一样。运行时现在看到的 stdout、stderr 是管道，不是终端；按是否终端决定颜色的库会按非终端输出。Rust 侧新增 `Stdio::Lines`，库的默认仍是 `Inherit`。
- **协议版本不匹配时说明升级哪一端**（[#293](https://github.com/arcships/rutis/issues/293)）：五种实现（Rust、Node、Bun、Python、Go）的握手和 WebSocket 子协议拒绝都会写出该升级哪一端、升级哪个包。错误类别仍是 `incompatible`。

## 修复

**值跨进程**

- 值的嵌套深度上限为 64 层（[#279](https://github.com/arcships/rutis/issues/279)）。以前接收端超过 serde_json 的递归上限时会结束整个会话，同一会话上的其他调用全部失败。现在由发送值的一方在发出前检查，过深只让这一次调用失败，会话继续。
- 浮点数进入 Rust 一侧时按位不变（[#290](https://github.com/arcships/rutis/issues/290)）。以前可能差一两个 ULP。
- Node 24 及以上版本的 `JSON.parse` 会把带转义的对象键读成别的键（[#302](https://github.com/arcships/rutis/issues/302)）。Node 运行时现在绕开了这个问题，插件收到的值不再被悄悄改掉。
- Go 运行时收到含非法 UTF-8 的帧时结束会话（[#294](https://github.com/arcships/rutis/issues/294)），与其他运行时一致。以前它会把非法字节换成 U+FFFD 后照常处理。
- Python 发送超出 ±(2^53−1) 的整数时，这次调用显式失败（[#356](https://github.com/arcships/rutis/issues/356)）。以前不检查：超过 2^64 的整数经 Rust 转发后会悄悄变成浮点数，超过 2^53 的整数在 JS、Go 一侧也不精确。这个上限和 JS、Go 一致。

**会话与链路**

- 调用链经 link 跨进程时，不再把别的进程的调用当成本进程的（[#325](https://github.com/arcships/rutis/issues/325)）。会话标签改为跨进程唯一，线上格式不变。
- 客户端证书无效时，监听方先发出告警再关闭连接（[#300](https://github.com/arcships/rutis/issues/300)）。拨号方在 Windows 上也能得到 `AuthRejected`，不再是连接被重置。
- macOS 上，运行时进程偶尔会在启动时被系统中止（SIGKILL）（[#287](https://github.com/arcships/rutis/issues/287)）。原因是 fork 时另一个线程正在初始化 libnotify。现在在第一次 fork 之前先完成这一步。这个问题在 macOS 26、27 上出现。

**Cordis 插件的边界规则**（[#281](https://github.com/arcships/rutis/issues/281)、[#282](https://github.com/arcships/rutis/issues/282)）

- Cordis 一侧对转发到 rutis 的事件做同步 `bail` 时，现在明确报错，提示改用 `serial`。以前会静默得到一个 Promise。
- `waterfall` 经过 rutis 一侧时，rutis 的一组监听器作为一个异步环节执行，链会继续到 Cordis 一侧后面的监听器。
- 挂载的 `events` / `emits` 里列出 `internal/*` 事件时，挂载失败，并在启动进程之前报错。

**内核与 loader**

- 失败的插件只在依赖真正变化时重试（[#327](https://github.com/arcships/rutis/issues/327)）。以前同一组依赖的重复通知会让它多装载一次，可能因此停在 Loading。
- 同一个 key 下的注入和监听列表在条目变少后收缩容量（[#291](https://github.com/arcships/rutis/issues/291)）。
- Go 运行时：调用方放弃等待的重启也会做完，不会出现两个同名进程（[#307](https://github.com/arcships/rutis/issues/307)）。刚替换的二进制读清单失败时会重读，Linux 上的 ETXTBSY 会重试（[#306](https://github.com/arcships/rutis/issues/306)）。
- `rutis-host` 等运行时真正放行各行之后才宣布启动完成（[#314](https://github.com/arcships/rutis/issues/314)）。
- 宿主被强制结束（`kill -9`）后，运行时也会退出（[#353](https://github.com/arcships/rutis/issues/353)）。以前在 Unix 上，插件只要留着一个定时器，Node 运行时就一直运行；清理一直不返回时，Node、Bun、Python 运行时也会卡住。现在四种运行时在会话断开后，在截止时间内卸载各行，然后退出。截止时间是 `rutis-host` 的 `--shutdown-timeout`，经环境变量 `RUTIS_SHUTDOWN_TIMEOUT` 传给运行时，默认 10 秒。超时就放弃剩下的清理，退出码为 1。

**Python**

- 在 CPython 3.13.6 上，`listen("wss://…")` 直接拒绝启动（[#304](https://github.com/arcships/rutis/issues/304)）。原因是这个补丁版本的 SSL 回归（[python/cpython#137583](https://github.com/python/cpython/issues/137583)），在它上面每个 TLS 连接都会挂住。请使用 3.13.7 或更新的版本。`ws://` 不受影响。

## 测试与质量

本版本的大部分工作在测试上，没有直接的用户可见变化，这里只列范围：

- 端到端场景：真实的 `rutis-host` 进程配合各语言的探针插件，覆盖插件开发循环、跨语言组合与运行时崩溃、实现迁移、两个独立进程之间的节点、安装后即可运行。Linux、macOS、Windows 都跑。
- 一致性套件：增加了 Windows 列和 loopback 列。故障注入接入会话与链路。增加了负向 TLS 测试，以及跨语言值往返和引用释放计数的属性测试。
- 测试工具（`@arcships/rutis/testing`、`rutis.testing`）和真实运行时对同一份期望文件比对（[#206](https://github.com/arcships/rutis/issues/206)）。
- 内核保证补齐：事件顺序、生命周期与回收。去掉了依赖真实时钟的断言，随机测试带种子。
- [保证登记表](../guarantees.md)：登记 rutis 的核心承诺与契约行为，以及验证它们的测试。0.10 作为基线发布，从 0.11 起每次发布前核对。

## 兼容

- **协议版本不变**：本地会话仍是协议 2，带 endpoint 身份的会话是协议 3，`PLUGIN_API` 仍是 1。0.9 和 0.10 的宿主与运行时可以混用。只有两个都是 0.9 的进程之间，仍有 #325 的问题。
- **`rutis.json`**：0.10 的 `rutis-host new` 生成的文件带 `"format": 1`。0.9 的 rutis-host 不认识这个字段，会报 unknown field。要用 0.9 读这个文件，删掉这一行即可。
- **改为明确报错的行为**：
  - Cordis 对转发到 rutis 的事件做同步 `bail` 时抛错（后续支持见 [#358](https://github.com/arcships/rutis/issues/358)）。
  - 挂载列出 `internal/*` 时失败（后续支持见 [#359](https://github.com/arcships/rutis/issues/359)）。
  - 嵌套超过 64 层的值不能跨进程。
  - 在 CPython 3.13.6 上不能启动 `wss://` 监听。
  - Python 插件不能再发送超出 ±(2^53−1) 的整数，例如 `time.time_ns()` 得到的纳秒时间戳。请改成字符串或毫秒。
- **测试工具更严格**：`@arcships/rutis/testing` 和 `rutis.testing` 现在与真实运行时一致，拒绝不能跨进程的值。例如 Node 的 `Date`、`Map`、`Set`、`Uint8Array`，Python 的 `set`、`bytes`。抛出的错误跨边界后只保留名字和消息。以前在测试工具里能通过、在真实运行时里会失败的插件测试，现在会在测试工具里失败。这些类型会在后续版本支持，见 [#308](https://github.com/arcships/rutis/issues/308)、[#360](https://github.com/arcships/rutis/issues/360)。
- **Rust API**：
  - `rutis-bridge` 的 `LinkState::Stopped` 增加字段 `failure`。
  - `rutis-bridge` 的 `Stdio` 增加变体 `Lines`（这个枚举本来就标了 `#[non_exhaustive]`）。
  - 新增 `session::MAX_DEPTH`，以及 `write_line` 和 `output_ended`。
  - `rutis-host` 库的 `HostConfig` 增加字段 `format`。
  - `rutis-host` 库的 `status::follow` 多了一个参数。
  - 新增 `Host::start_with` 和 `Embedding`，用于嵌入方注册内置插件。
  - `rutis` 与 `rutis-loader` 没有不兼容的变化。
- **运行时进程**：会话断开、清理超过截止时间时，运行时以 1 退出（Go 运行时以前在 5 秒后以 0 退出）。
- **dylib**：dylib 插件要用 0.10.0 的 SDK 重新编译。
- **最低版本不变**：Rust 1.88，Node 22，Python 3.10，Bun 1.4，Go 1.24。

## 已知问题

- 各语言之间还有三处值的不一致（[#355](https://github.com/arcships/rutis/issues/355)）：
  - Python 的 `datetime`、`Decimal`、`UUID` 按对象引用传，对端拿到的是代理，不是数据；
  - Go 结构体字段里的 `time.Time`、`[]byte` 和大整数不经过检查；
  - Python dict 里值为 undefined 的键被删掉，其他语言变成 `null`。

  这三处会和日期、二进制值的支持（[#308](https://github.com/arcships/rutis/issues/308)）一起在 0.11 处理。
