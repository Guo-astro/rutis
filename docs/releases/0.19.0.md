# rutis 0.19.0

[English](0.19.0.en.md) · [0.18.0 发布说明](0.18.0.md)

0.19.0 面向宿主持有者（[#694](https://github.com/arcships/rutis/issues/694)）：可以从命令行调用正在运行的宿主里的服务、用 `rutis-host add` 装插件、让插件经服务 `loader` 增删行并写回 `rutis.json`；远程运行时、设备与节点都改成连接行（`rutis-host/dial`、`rutis-host/listen`），背后是一个会话插件（[远程连接：只留一个会话插件](../design-remote-session-2026-10-28.md)）；平台删掉没有使用方的接口（[平台清理](../design-platform-cleanup-2026-10-28.md)）。这一版有不兼容的改动，而且**宿主与各语言运行时、SDK 要一起升级**：0.19 在握手时拒绝 0.18 及更早的一端。升级前先看[迁移到 0.19](../migration-0.19.md)。

升级的顺序：宿主、各语言运行时、SDK 一起升到 0.19；用旧 SDK 构建的 Go、Swift 二进制用 0.19 的 SDK 重新构建；然后用 0.19 跑一遍 `rutis-host check`，它列出不再认识的字段和插件名。

## 不兼容的改动

每一条写了要改什么，细节和例子见[迁移到 0.19](../migration-0.19.md)。

- **会话协议升到 4，宿主与运行时、SDK 要一起升级**（[#695](https://github.com/arcships/rutis/issues/695)、[#849](https://github.com/arcships/rutis/pull/849)；[#814](https://github.com/arcships/rutis/pull/814)、[#815](https://github.com/arcships/rutis/pull/815)、[#817](https://github.com/arcships/rutis/pull/817)、[#818](https://github.com/arcships/rutis/pull/818)、[#824](https://github.com/arcships/rutis/pull/824)、[#826](https://github.com/arcships/rutis/pull/826)）。会话只留 endpoint 格式，本端总要报自己的 id。0.19 在握手时拒绝 0.18 及更早的宿主、运行时、节点和 SDK，并写明升级哪一端，例如 `incompatible session: the far end speaks protocol 2, this side 4: upgrade the far end`、`this endpoint speaks rutis.4, the dialer offered rutis.3: upgrade the dialer`。0.18 的宿主起 0.19 的本机运行时，运行时在握手之前停下：`a local channel needs --id <endpoint>: fd:3; a host older than rutis 0.19 started this runtime: upgrade the host`。
  - 要改的：宿主、Node、Bun、Python、Go、Swift、Kotlin 一起升到 0.19；Go、Swift 二进制用 0.19 的 SDK 重新构建。
  - 自己启动运行时进程的：本机通道（`fd:3`、socket 路径、`tcp:`）也要带 `--id <名字>`；Node、Bun 运行时的 `--format` 删除；`package.json` 的 `rutisProtocol` 为 4；WebSocket 子协议为 `rutis.4`；Go 的 `advanced.ServeConn(conn, defs...)` 改为 `advanced.ServeConn(conn, id, defs...)`。
- **远程运行时与设备改用连接行**（[#695](https://github.com/arcships/rutis/issues/695)、[#870](https://github.com/arcships/rutis/pull/870)、[#872](https://github.com/arcships/rutis/pull/872)）。`runtimes.remote` 删除，不做转换；远程运行时写一行 `rutis-host/dial`（rutis 去连）或 `rutis-host/listen`（对面连进来），运行在对面的插件写 `<连接行>:<插件>`：

  ```json
  { "id": "gpu", "name": "rutis-host/dial", "config": { "address": "wss://gpu.example.com:7443/rutis" } },
  { "id": "embedder", "name": "gpu:embedder" }
  ```

  - 写了 `runtimes.remote` 的 rutis.json 按 0.18 的规则报不认识的字段，没有专门的提示：`rutis-host: rutis.json: unknown field `remote`, expected one of …`。
  - 行 id 是连接的名字：运行时的 `--id`、token 的名字（`RUTIS_TOKEN_<行 id>`）、输出的前缀都用它。以前由运行时连进来、rutis 决定它跑什么插件的，改为运行时监听、rutis 用 `rutis-host/dial` 去连。
  - 多台设备（以前的 `listen` + `instances` 与 `instanced` 分组）：一行 `rutis-host/listen`；设备上的 Kotlin、Swift 应用自己装插件，配置写进 `RutisApp(configs: …)`，连上后报出它提供的服务，注册为 `<设备 id>:<插件>`。宿主上「每台设备一份」的行（例如 `py:coach`）不再支持：放到设备上，或由宿主上的一个插件在 `rutis/service` 事件里经 `loader` 为每台设备加一行（例子见 [Swift 应用](../guide/swift-app.md#每台设备各算一份)）。
  - `rutis-host/listen` 上同一个 id 的新连接顶替旧的：旧连接的远程插件先全部卸载，再以关闭码 4002 关闭旧连接。
  - 缺插件时只是这一行失败（[#696](https://github.com/arcships/rutis/issues/696)、[#768](https://github.com/arcships/rutis/pull/768)），对面下次连上时重新检查：`embedder: unresolved: entry "embedder" rejected: runtime gpu: this connection does not contain plugin embedder`。用 Rust 嵌入、按 `LoaderError::NotFound` 判断这种情况的，改为 `rutis_loader::report::Unavailable::is(&error)`。
- **节点改用连接行**（[#695](https://github.com/arcships/rutis/issues/695)、[#883](https://github.com/arcships/rutis/pull/883)）。`rutis-bridge/peer` 行与 `peer:<对端>/<插件>` 行删除，不做转换；节点一端写 `rutis-host/dial`，另一端写 `rutis-host/listen`（[连接节点](../guide/nodes.md)）。还写着 `rutis-bridge/peer` 的行以不认识的插件名失败：`office (rutis-bridge/peer): no plugin named "rutis-bridge/peer"`。
  - `export`、`import`、`host`、`rows`、`peer`、`require`、`declare`、`transport`、`identity` 都不再写：服务两边都全局可见，事件是一条总线，对面的 id 来自握手。同名服务按内核规则后注册的被拒：`office:weather: weather is provided here by row weather: not registered from office`。不给对面看的服务，在提供它的行上用 `isolate`。
  - 在别的节点上运行插件：以前 `host: true` + `rows: true` + 行 `peer:office/scanner`，现在写行 `office:scanner`，对面不用打开什么。
  - **给出 token 等于允许对方在本节点运行它能解析的任何插件**：只连可信的节点。经一条连接收到的服务会经别的连接继续到达第三个节点（以前只走一跳）。
  - Cordis 应用作为节点的 `@arcships/rutis-runtime/bridge`（`Link`、`Export`、`Import`、`Host`、`Events`）删除：Cordis 应用接 rutis，用 Node 运行时跑它的插件。
- **宿主一侧只认 `RUTIS_TOKEN_<名字>`**（[#822](https://github.com/arcships/rutis/pull/822)）。不再退回公共的 `RUTIS_TOKEN`；运行时一侧的 `RUTIS_TOKEN` 不变。`<名字>` 是连接行的 id，大写，`-` 写作 `_`。
  - 要改的：只设了 `RUTIS_TOKEN` 的宿主改为每个连接行各设一个。没改时，`rutis-host/listen` 的行失败：`phone: set RUTIS_TOKEN_PHONE: the token the far ends present when they connect`；`rutis-host/dial` 的行被对面拒绝，每 30 秒重试：`office: disconnected (auth-rejected: …); retrying in 30s`。
- **连接的输出变了**。连接状态行以连接行的 id 开头，只用 `connected`、`disconnected`，原因写在括号里（以前是 `runtime <名>: link …` 与 `<行 id>: link connected` / `link down` 等）：

  ```text
  gpu: connected
  gpu: disconnected (gpu.example.com:7443: Connection refused); retrying in 2.1s
  gpu: disconnected (incompatible: this endpoint speaks rutis.3, the dialer offered rutis.4: upgrade this endpoint (PyPI rutis)); stopped
  phone: connected phone-1
  phone: disconnected phone-1 (replaced by a new connection)
  ```

  `rutis-host status` 的 `connections:` 一节每个连接行一行：dial 行写 `connected` / `disconnected`，listen 行写连着的 id（没有时 `none connected`）。读 `run` 输出的脚本按新格式改。
- **Go、Swift 的行名只留语言前缀**（[#876](https://github.com/arcships/rutis/pull/876)）。`go-<二进制>:<插件>`、`swift-<二进制>:<插件>` 删除，写 `go:<插件>`、`swift:<插件>`；`rutis.json` 里还有旧写法时，读文件就报错并给出新写法。两个二进制有同名插件时这一行失败、写出两个文件名。
- **Go、Swift、Kotlin 的测试工具在真实宿主下运行插件**（[#875](https://github.com/arcships/rutis/pull/875)、[#878](https://github.com/arcships/rutis/pull/878)、[#881](https://github.com/arcships/rutis/pull/881)、[#882](https://github.com/arcships/rutis/pull/882)、[#885](https://github.com/arcships/rutis/pull/885)）。`rutistest`、`RutisTest` 与 Kotlin 的测试工具把被测插件作为 `rutis-host test` 的一行运行：要 `PATH` 上有 `rutis-host`，或在 `RUTIS_HOST` 里给出它的路径。
  - 测试工具不再有作用域：Go 的 `InScope`、`InChain`、`Loaded.Scope`、`RuntimeName`，Swift 的 `RutisTest.scope(_:groups:)`、`scope:`、`runtimeName:`，Kotlin 的 `load(scope:)`、`RutisTest.scope(...)`、`load(runtime:)`、`Loaded.provided` 删除。装载失败的文字是宿主为这一行写的那一行，例如 `weather: config: city is required`。
  - Kotlin 的测试工具是单独的构件 `io.github.arcships:rutis-testing`，并要 `kspTest("io.github.arcships:rutis-ksp:<版本>")`。Swift 的 `loaded.reported` 要 `await` 读。
  - 配置的校验与补默认值只在宿主里做，SDK 只解码。应用（`RutisApp`）自己装的插件不经宿主校验：缺的键用类型里写的默认值，缺必填或类型不对时以 `config: <键> is required` 一类的文字失败。
  - **事件一律经宿主分发**，监听器全在同一个进程里时也一样：Go 会话结束后 `ctx.Emit` 以 `the host disconnected` 失败；Kotlin 在 Android 主线程上的同步 `bail` 总是被拒绝。
  <!-- 待核对：Node、Bun、Python 的 CL30（叶子只剩叶子）还没合并；合并后它们的测试工具也走 rutis-host test，这一条要补上这三种语言与它们的改法。 -->
- **Python 最低 3.12**（[#860](https://github.com/arcships/rutis/pull/860)）。3.10、3.11 不再支持。
- **SDK 根上只留写插件常用的名字**（[#692](https://github.com/arcships/rutis/issues/692)；[#762](https://github.com/arcships/rutis/pull/762)、[#763](https://github.com/arcships/rutis/pull/763)、[#769](https://github.com/arcships/rutis/pull/769)、[#775](https://github.com/arcships/rutis/pull/775)、[#777](https://github.com/arcships/rutis/pull/777)、[#778](https://github.com/arcships/rutis/pull/778)；旧名删除 [#819](https://github.com/arcships/rutis/pull/819)、[#821](https://github.com/arcships/rutis/pull/821)、[#835](https://github.com/arcships/rutis/pull/835)、[#827](https://github.com/arcships/rutis/pull/827)、[#829](https://github.com/arcships/rutis/pull/829)）。其余的名字移到 advanced：`@arcships/rutis/advanced`、`rutis.advanced`、`github.com/arcships/rutis/go/rutis/advanced`、`Rutis.Advanced`、`arcships.rutis.advanced`；宏与 KSP 生成的代码用的在 `Rutis._Generated`、`arcships.rutis.generated`。旧位置删除，用到时编译或导入报找不到。
  - 要改的：只有导入，按迁移指南的表改。`definePlugin` / `define_plugin` / `Define` / `Rutis.define`、`ctx` 上的方法不变；插件 API 版本不变。
  - Kotlin：`rutis-ksp` 要与 SDK 同一版本；预先编译好的 Kotlin 插件库用 0.19 的 SDK 重新编译。
  - Python：插件和运行时共用宿主环境里的 `rutis`，要与宿主一起升级。
- **Rust：连接、会话与本机运行时的 API**（[#833](https://github.com/arcships/rutis/pull/833)、[#843](https://github.com/arcships/rutis/pull/843)、[#834](https://github.com/arcships/rutis/pull/834)、[#849](https://github.com/arcships/rutis/pull/849)、[#870](https://github.com/arcships/rutis/pull/870)、[#872](https://github.com/arcships/rutis/pull/872)、[#880](https://github.com/arcships/rutis/pull/880)、[#883](https://github.com/arcships/rutis/pull/883)）。本机的语言运行时也和远程的一样，是一个会话的对面。对照表见迁移指南「Rust 嵌入」，主要的：
  - `Transport`、`Dial`、`transport_key` 与各 `*Plugin`/`*Transport` 删除，`websocket::dial`、`websocket::listen`、`pipe::spawn`、`memory::pair` 直接给出 `Channel`；自建连接写一个连接插件，调 `Session::new(channel)`（或先 `Session::handshake(&ctx, channel).await`）。
  - `LinkPlugin`、`PeerPlugin`、`ExportPlugin`、`ImportPlugin`、`HostPlugin`、`AccessPointPlugin`、`Identity`、`Admission`、`Registration` 一族与 rutis-loader 的 feature `peer` 删除。
  - `LocalRuntime` 与 `RuntimePlugin` 删除：本机运行时用 `rutis_host::connect::SpawnPlugin::new(名字, launcher, anchor)`（插件 `rutis-host/spawn`），`launcher` 是 `rutis_bridge::runtime::Launcher::node(&包)` 等；运行时状态在 `RuntimeStates`。`RuntimeResolver` 换成所有运行时共用的 `rutis_loader::runtime::SessionResolver`；Rust 不再解析 npm 名，由 Node 运行时做。
  - `Closer::replaced()` / `rejected(r)` / `close(&str)` 改为 `close(Close::…)`；`ChannelInfo` 删除；`Connection::open(channel, dispatch, endpoint)`；`session::PROTOCOL`、`Format`、`LinkConfig` 删除，`ENDPOINT_PROTOCOL` 为 4；`Embedding.transports`、`Embedding.identity` 删除；自己挂 `Session` 的嵌入要在根上 `provide(rutis_bridge::LocalId(id))`。
  - `rutis_host::control::serve` 在 `Loader` 之后多一个参数 `Report`，用 `Host::status_report()` 得到。
- **平台清理：删掉没有使用方的 Rust API**（[#694](https://github.com/arcships/rutis/issues/694)；[#832](https://github.com/arcships/rutis/pull/832)、[#845](https://github.com/arcships/rutis/pull/845)、[#848](https://github.com/arcships/rutis/pull/848)、[#840](https://github.com/arcships/rutis/pull/840)、[#837](https://github.com/arcships/rutis/pull/837)、[#839](https://github.com/arcships/rutis/pull/839)、[#836](https://github.com/arcships/rutis/pull/836)、[#838](https://github.com/arcships/rutis/pull/838)、[#841](https://github.com/arcships/rutis/pull/841)、[#820](https://github.com/arcships/rutis/pull/820)、[#880](https://github.com/arcships/rutis/pull/880)）。不做兼容，删掉的是编译错误，对照表见迁移指南「平台清理」。主要的：
  - 内核：`ctx.plugin_from` → 实现 `PluginFactory` 后 `ctx.plugin_with`；`waterfall_sync` → `waterfall` 或同步 `bail`；服务拦截器、`check()` 门控、`FiberView::effects()`、`EventBus::observe_dispatch`、`take_cleanup_errors()`、feature `anyhow` 删除；配置校验在 `rutis::config::check(schema, config)`。
  - 调用时限与服务名单（`call_limit`、`kill_on_timeout`、`allowed_services`，错误码 `timeout`）删除：调用方自己限时，能用哪些服务由宿主决定。
  - loader：`set_overlay` / `overlays()` 删除；`waiting_for` → `waits`；`locate` → `row`；`schema_of` → `resolve(name).await?.schema`；`ServiceCatalog::share_by_name()`、`share_registered_only()` 删除；`status::RowState` → `report::EntryStatus`，`report::RowState` 改名 `RowEventState`；Go、Swift 的 `Go*`/`Swift*` 类型合成 `runtime::binary::*<Go|Swift>`；加载器不再重启崩溃的 Go/Swift 运行时（`backoff`、`RestartPolicy`、`supervise` 删除），重启策略在 rutis-host 的 `runtimes.<key>.restart`。
  - 生成器从 rutis-bridge 搬到新 crate **`rutis-types`**（[#844](https://github.com/arcships/rutis/pull/844)）：`rutis_bridge::build::Exports` → `rutis_types::Exports`，build-dependency 从 `rutis-bridge = { features = ["exports"] }` 改为 `rutis-types`，写法不变。rutis 以外名叫 `Error` 的错误类型，生成类型按模块命名（`IoErrorThrown`、`AnyhowErrorThrown`，[#862](https://github.com/arcships/rutis/pull/862)）。
  - `rutis_bridge::cordis::build::rutis_plugin`、`cordis::server` 删除（Cordis 宿主挂 Rust 插件的方向不再支持，[#836](https://github.com/arcships/rutis/pull/836)）。
  <!-- 待核对：CL18（#887，loader 的 internal 收掉）、CL6（*_key → Key + *_at）、CL12a/CL12b、CL11b 合并后，把它们删改的公开名字补进这一条。 -->
- **线上错误名 `CordisError` 改为 `Error`**（[#825](https://github.com/arcships/rutis/pull/825)）。`rutis::Error` 抛给其他语言时叫 `Error`，生成类型 `CordisErrorThrown` 改为 `ErrorThrown`。按 `CordisError` 这个名字判断的代码要改。
- **工具**：`rutis-dev` 删除，开发时用 `rutis-host dev`（[#820](https://github.com/arcships/rutis/pull/820)）；`rutis-migrate` 不再发布，0.17 的迁移仍可用 `cargo install rutis-migrate --version 0.18.0`（[#816](https://github.com/arcships/rutis/pull/816)）；`rutis-host go add` 删除，用 `rutis-host add <模块>@<版本>`（[#851](https://github.com/arcships/rutis/pull/851)）。
- **测试工具拒绝插件提供宿主已有的服务名**（[#684](https://github.com/arcships/rutis/issues/684)、[#810](https://github.com/arcships/rutis/pull/810)）。Node、Bun（`@arcships/rutis/testing`）与 Python（`rutis.testing`）里，插件 `ctx.provide` 一个 `services` 里已有的名字时失败：`PluginTestError: wordcount: notes is already provided by the host`，与真实宿主一致。以前测试里能过、到宿主上才失败的插件，现在在测试里就失败。
- **服务名 `loader` 被占用**（[#185](https://github.com/arcships/rutis/issues/185)、[#842](https://github.com/arcships/rutis/pull/842)）。用 `LoaderPlugin` 的宿主（包括 rutis-host）提供一个名叫 `loader` 的服务；自己也提供 `loader` 的行以同名错误失败（`service loader is already provided by …: row <行> cannot provide it too`），给它的服务改名。
- **Go 插件**：0.18 之前构建的二进制要用 0.18 及以后的 SDK 重新构建（`required` 的例外删除）。

## 新功能

- **`rutis-host call`**（[#670](https://github.com/arcships/rutis/issues/670)、[#772](https://github.com/arcships/rutis/pull/772)、[#804](https://github.com/arcships/rutis/pull/804)）：`rutis-host call [--config <rutis.json | 目录>] <服务>.<方法> [参数…]`，在另一个终端里调用正在运行的 `run` 或 `dev` 里的服务，结果打印成 JSON。参数逐个按 JSON 读。走 `status` 用的那个只有本用户能用的 socket。Windows 上不提供。
- **装插件**（[#691](https://github.com/arcships/rutis/issues/691)、[#805](https://github.com/arcships/rutis/pull/805)、[#850](https://github.com/arcships/rutis/pull/850)）：`rutis-host add <引用>`（`npm:`、`pypi:`、Go 模块路径、本地目录、`.tgz`、`.whl`、二进制）装好插件和运行时缺的东西，写上行和 `installed` 字段；写文件前先检查新行，解析不了时以 1 退出、文件不动。`rutis-host remove`、`rutis-host upgrade` 按记录的来源删除、升级。不用知道插件是什么语言写的。
- **插件经服务 `loader` 增删行，`run` 写回 `rutis.json`**（[#185](https://github.com/arcships/rutis/issues/185)、[#842](https://github.com/arcships/rutis/pull/842)、[#852](https://github.com/arcships/rutis/pull/852)、[#857](https://github.com/arcships/rutis/pull/857)）：任何语言的插件 `inject: ["loader"]` 后可用 `create`、`reload`、`remove`、`status`，与 Cordis 的 `ctx.loader` 一样；失败时抛出 `Error`，`data` 里是 `{row}`。`run` 把加、删的行写回 `rutis.json`，只改 `rows`，其他字段与键的顺序不变；写不了文件时行照样加上，错误写明 `<行>: added, but rutis.json could not be written: <原因>`。`dev` 不写文件：`create`、`remove` 得到 `this host keeps no editable configuration, so rows cannot be added or removed`。见 [用 `loader` 管理插件](../guide/plugin-api.md#用-loader-管理插件)。
- **任何语言写连接插件**（[#870](https://github.com/arcships/rutis/pull/870)）：会话插件 `rutis-bridge/session` 提供服务 `sessions`，`sessions.open(far)` 把一条自己建的连接接成会话；Rust 用 `Session::new(channel)`。rutis-host 自带 `rutis-host/spawn`、`rutis-host/dial`、`rutis-host/listen`。
- **`rutis-host test`**（[#875](https://github.com/arcships/rutis/pull/875)、[#878](https://github.com/arcships/rutis/pull/878)）：`rutis-host test <插件> -- <运行时命令…> <项目>` 或 `rutis-host test <插件> --channel <通道>`，给各 SDK 的测试工具用：起一个没有用户行的宿主，在真实的运行时里加载驱动测试的插件，服务 `rutis-host/test`（`load`、`update`、`unload`、`reported`）让它在这个运行时里加载被测插件。插件作者不用自己运行它。见 [在测试里运行插件](../guide/rutis-host.md#在测试里运行插件rutis-host-test)。
- **每个子命令认 `--help` / `-h`**（[#856](https://github.com/arcships/rutis/pull/856)）：`rutis-host <命令> --help` 打印这个命令的用法后以 0 退出，不做别的事。以前 `run --help` 把 `--help` 当成配置文件路径，`add --help` 把它当成插件名。
- **`rutis-host dev` 打印服务行**（[#794](https://github.com/arcships/rutis/pull/794)、[#847](https://github.com/arcships/rutis/pull/847)、[#871](https://github.com/arcships/rutis/pull/871)）：所有行都已运行、等待或失败后打印一次 `rutis-host dev: services: forecast (weather), llm (llm)`，之后服务变化时再打印。
- **测试工具听事件**（[#770](https://github.com/arcships/rutis/pull/770)）：TypeScript / Bun 与 Python 的测试工具加 `on(name, listener)`，插件发出的与测试自己发出的事件都收到，规则与 Go 的 `loaded.On` 相同。
- **生成 Python 类型**（[#684](https://github.com/arcships/rutis/issues/684)、[#798](https://github.com/arcships/rutis/pull/798)、[#810](https://github.com/arcships/rutis/pull/810)）：`rutis-host types --python <文件>`，`rutis_types::Exports` 的 `.python(path)`、`.declared_python(path, python)`。从 `#[rutis::service]` 生成 `typing.Protocol`、`TypedDict` 等，配合 pyright 在写 Python 插件时查出调用宿主服务的错误。
- **指南按层重写**（[#671](https://github.com/arcships/rutis/issues/671)；[#854](https://github.com/arcships/rutis/pull/854)、[#858](https://github.com/arcships/rutis/pull/858)、[#861](https://github.com/arcships/rutis/pull/861)、[#863](https://github.com/arcships/rutis/pull/863)、[#864](https://github.com/arcships/rutis/pull/864)、[#866](https://github.com/arcships/rutis/pull/866)、[#867](https://github.com/arcships/rutis/pull/867)、[#868](https://github.com/arcships/rutis/pull/868)、[#869](https://github.com/arcships/rutis/pull/869)）：六种语言的插件指南按同一条八步短路径写，进阶内容收进《插件 API》；《rutis-host》开头面向组装插件的人；新指南《做一个开放插件的宿主》。发布的 crate 的文档注释改成英文，rutis-loader 的公开路径整理过（[#764](https://github.com/arcships/rutis/pull/764)）。

## 修复

- 行的 `rutis/row` 跟随改为每个 `Loader` 一个监听器（[#806](https://github.com/arcships/rutis/issues/806)、[#808](https://github.com/arcships/rutis/pull/808)，感谢 @yyhhyyyyyy）。以前每行在根上注册一个监听器，行多时每次状态变化都要跑一遍所有行的回调，并让排队中的投递占住大量内存。
- `LoaderPlugin` 重启后，行按原来的启用状态重新加载（[#812](https://github.com/arcships/rutis/issues/812)、[#828](https://github.com/arcships/rutis/pull/828)）。以前所有行都变成禁用，还写进了可编辑层。
- `rutis-host dev` 在运行时晚于行就绪才提供服务时，照实再打印服务行（[#847](https://github.com/arcships/rutis/pull/847)）。
- 运行时经宿主发出的 `emit`，过滤器失败时报成 `FilterFailed`，与内核自己的同类失败一样，宿主的错误接收方能认出是哪一行（[#879](https://github.com/arcships/rutis/pull/879)）。打印的文字不变。

## 兼容

- 与 0.18 及更早的版本不能互连：握手时拒绝并写明升级哪一端（协议 4 对 3）。跨版本相遇只在不含不兼容改动的相邻版本之间成立。
- `rutis.json` 的 `format` 仍是 1，本机运行时 `runtimes.node` / `py` / `go` / `swift` / `bun` 的写法不变。这一版是 rutis.json 跨版本可读的第一个例外：写了 `runtimes.remote` 的文件 0.19 不再读；写了节点行 `rutis-bridge/peer` 的文件读得出，但这些行以不认识的插件名失败。0.8–0.18 的持久化样本删掉了这些写法。
- 插件 API 版本（`PLUGIN_API`）不变：用 0.18 的 SDK 写的插件，导入改好后在 0.19 的运行时上运行；Go、Swift 二进制因为协议升级要重新构建。
- dylib 插件照每次发布一样用 0.19 的 SDK 重新构建。
- Swift：`.package(url: "https://github.com/arcships/rutis", from: "0.18.0")` 会解析到 0.19；还没准备好升级的应用写 `.upToNextMinor(from: "0.18.0")`。
