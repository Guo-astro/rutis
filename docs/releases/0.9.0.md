# rutis 0.9.0

[English](0.9.0.en.md) · [迁移指南](../migration-0.8-to-0.9.md)

0.9.0 新增 Bun 和 Go 两种插件运行时，宿主会拒绝跨运行时形成环的同步调用，`rutis-host check` 能发现没有提供方的服务，停止流程和本地通道也更可靠。Python 的最低版本降到 3.10，Node 降到 22。

## 发布包

以下包版本均为 **0.9.0**：

| 注册表 | 包 |
| --- | --- |
| crates.io | `rutis`（内核）、`rutis-bridge`、`rutis-loader`、`rutis-host`；dylib 工具链 `rutis-sdk`、`rutis-dylib`、`rutis-dylib-meta`、`rutis-dylib-launcher` |
| npm | `@arcships/rutis`、`@arcships/rutis-runtime`、`@arcships/rutis-bun`（首次发布）、`@arcships/rutis-host`，以及五个平台的 host 包 |
| PyPI | `rutis`、`rutis-host` |
| Go | `github.com/arcships/rutis/go/rutis`（首次发布，tag `go/rutis/v0.9.0`） |
| GitHub | Linux / macOS（x64 / arm64）和 Windows（x64）的 `rutis-host` 二进制与 SHA-256 校验文件 |

`rutis-cli` 仍独立发版。

## 内容

- **Bun 运行时**（`@arcships/rutis-bun`，Bun 1.4+）：JavaScript / TypeScript 插件可以跑在 Bun 上，插件代码仍用 `@arcships/rutis`。宿主配置 `runtimes.bun`，`rutis-host new --lang bun` 生成项目，`rutis-host dev` 认得 Bun 项目并热重载；Rust 侧是 `Launcher::bun` / `LocalRuntime::bun`（feature `bun`）和 loader 的 `bun:<模块>` 行。同步调用可重入。插件有语法错误时报出 `文件:行:列`。远程监听和 Windows 留待后续版本。
- **Go 运行时**（`go/rutis`，Go 1.24+）：Go 插件编译成二进制，一个二进制是一个运行时，只依赖标准库。`Define` / `Plugin[C]` / `Serve` 写插件，配置结构体生成 JSON Schema，`--rutis-manifest` 打印清单，`rutistest` 用来测试。宿主配置 `runtimes.go`（`dir` / `binaries` / `start` / `idle`），运行时有行用到时启动、空闲后停止；`rutis-host new --lang go`、`rutis-host go add <模块>@<版本>`；`dev` 构建 Go 项目并只重启 Go 运行时。Rust 侧是 `Launcher::go` / `LocalRuntime::go` 和 loader 的 `GoResolver` / `GoRuntimes`（feature `go`）。
- **跨运行时同步调用的环**：宿主转发同步调用前检查等待关系，会成环（例如 Python → Node → Python 互相同步等待）时返回 `SyncWaitCycle`，不再死锁。Node、Python、Bun 运行时声明 `sync-wait` 能力；嵌套调用的 origin 带会话标签，Python → Node → Python 的嵌套调用现在能完成。
- **`rutis-host check`**：不运行插件，检查每行注入的服务有没有行提供，没有时退出码为 1（提供方在别的节点上时只提示）。被禁用的行不再解析。Rust 侧是 `Loader::check`。同时打印每个运行时的实现、引擎和 Go 二进制。
- **停止与信号**：`run` / `dev` 处理 SIGINT / SIGTERM / SIGHUP（Windows 上是 Ctrl-C / Ctrl-Break / 关闭控制台），卸载各行后退出；`--shutdown-timeout <秒>`（或 `RUTIS_SHUTDOWN_TIMEOUT`，默认 10）限定清理时间，没清理完时退出码为 2。运行时进程放在自己的进程组里，终端的 Ctrl-C 只发给宿主。
- **运行时进程的标准流**：`Launcher` / `LocalRuntime` 的 `stdin` / `stdout` / `stderr` 可以分别设为 `Stdio::Null` 或 `Stdio::Inherit`，例如让读终端的插件拿到 stdin。
- **插件自己 dispose**：Node 行里的插件卸载自己时，宿主收到 `SelfDisposed`，这一行转为禁用（实例里的副本是 `Stopped`），不再一直显示为运行中。新增 `rows.ended` 消息和 `Process::on_row_ended`。
- **本地通道**：单条消息上限 16 MiB（Rust 与各语言运行时一致），超过时关闭通道；流在消息中间结束时都算失败。
- **配置**：以相对路径给出 `rutis.json` 时，`./plugin.mjs` 这样的行现在相对配置文件解析；`rows` 里的未知字段会警告；监听器只给 `cert` 或只给 `key` 时报错，不再悄悄不用 TLS；运行时名字必须唯一。
- **Python**（最低版本 3.10）：3.10 / 3.11 上自己实现 eager start，行为与 3.12+ 的原生实现一致。插件方法第一步执行中到达的取消不再被忽略；WebSocket 监听在 `accept()` 失败时以失败结束；`python -m rutis` 出错时打印异常并以 1 退出；websockets 低于 17 时 `Listener.close()` 无效的问题已修复。可选依赖 `network` 要求 websockets 15+。
- **其他修复**：
  - 子进程只继承 fd 0–3，修复 macOS 上并发启动运行时偶发的 Broken pipe 和卡住。
  - 进程结束后会报出它的退出状态，包括关闭了通道却 10 秒未退出的进程，以及发送失败时进程是怎么结束的。
  - 协议版本不匹配时两端都稳定得到 `Handshake::Incompatible`。
  - root 的 `dispose()` 与 `Ctx::shutdown()` 同时调用时，`dispose()` 不再偶尔返回 `Closed`。
  - Go 运行时崩溃后状态为 `Down`，不再停在 "Starting"。

## 兼容

- **宿主与语言运行时要一起升到 0.9**：协议版本没变（本地会话仍是协议 2，带 endpoint 身份的会话是协议 3），PLUGIN_API 仍是 1，但 0.9 宿主转发的调用来源带会话标签，0.8 的运行时不认识，会结束会话。
- **Rust API**：`rutis-bridge` 的 `Launcher`、`Spawn` 标为 `#[non_exhaustive]`，`RowSchema` 新增字段 `version`；`rutis` 与 `rutis-loader` 没有不兼容的变化。dylib 插件要用 0.9.0 的 SDK 重新编译。
- **`rutis-host`**：`check` 在服务没有提供方时失败；新增退出码 2。
- **最低版本**：Rust 1.88（原来 1.85），Node 22（原来 24），Python 3.10（原来 3.12），Bun 1.4，Go 1.24。

## 开始使用

```bash
npx @arcships/rutis-host@0.9.0 new greeter --lang node
npx @arcships/rutis-host@0.9.0 new greeter-bun --lang bun
npx @arcships/rutis-host@0.9.0 new greeter-go --lang go
uvx --from rutis-host==0.9.0 rutis-host new greeter-py --lang python
```
