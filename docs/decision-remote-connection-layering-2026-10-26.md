# 决策记录：远程连接分层——远程插件层与连接插件解耦（2026-10-26）

[English](decision-remote-connection-layering-2026-10-26.en.md)

本文记录一次从"梳理远程连接逻辑"开始、最后定为两层的讨论，保留过程和理由。设计见 [远程连接分层](design-remote-connection-layering-2026-10-26.md)，issue [#695](https://github.com/arcships/rutis/issues/695)。

## 一、起点

梳理 0.17.1 的远程连接代码，发现外部的东西有四种方式接进 rutis：本机运行时、rutis 去连的远程运行时（link 行 + `runtime`）、连进 rutis 的远程运行时（接入点）、另一台 rutis（节点互联）。

中间两种是同一样东西，只是连接方向不同，在 rutis 里却走两条代码：服务的可见范围不同（全局 / 只在分组内），远端缺插件的报错不同（整行失败 / 只这条连接失败），输出不同（只有 link 行 / 什么都不打印），配置写法不同（两处且不核对 / 一处）。

## 二、讨论经过

1. **连接方向不该改变插件怎么用。** 第一次讲解用了内部名词和多张表，没讲清楚；换成一个场景（GPU 机器上的一个插件，两种接法，用起来不一样）才讲清。结论：连接方式应与插件的生命周期、配置生效解耦。
2. **"一台还是多台"是真实区别，但应由配置决定。** 现在是按方向决定的：连进来就当多台，rutis 去连就当一台。
3. **宿主持有者要能自建连接。** 中继、接外部认证服务、整个换协议。逐层看：传输已经能换（`Transport`）；认证能换但只认 token 和证书、不能等待外部应答；连接管理写死成 link 和接入点两种；会话协议不换（所有语言 SDK 的共同约定）。
4. **连接本身是插件。** link 和接入点在代码里本来就是插件，但产出不统一：link 提供服务，接入点在代码里直接调用 loader，用户插件做不到后者。
5. **连接配置不该暴露。** 曾提议把连接插件写成配置里的一行，被否决：写配置的人只关心跑哪些插件、在哪个运行时，不关心怎么连；连接插件由宿主挂载。
6. **定为两层。** 远程插件层负责远程才需要维护的发现、绑定和生命周期；连接插件专心解决连接。两层之间只交接一条连接。

## 三、决定

- 两层：远程插件层（发现、绑定、生命周期、握手），rutis 统一一份；连接插件（拨出或监听、认证、重连、传输），可替换、可以有多个。
- 交接：运行时名、连接 id、消息通道；连上交出，断开收回。连接插件依赖远程插件层提供的"连接登记处"，不实现 rutis 协议。
- 一台还是多台由 `instances` 决定；同 id 顶替归远程插件层。
- 配置只写运行时名、插件和内置连接的地址；`runtimes.remote` 一条写全，不再需要 link 行。
- 运行时侧不变；旧配置继续接受。
- 排期 0.19（宿主持有者）：自建连接是宿主持有者的扩展点；改动会改变远程行为，必须在 0.20 形式化覆盖之前完成，规则不用覆盖两遍。

## 四、没有采用的做法

| 做法 | 不采用的原因 |
| --- | --- |
| 只修两种接法的差异，不分层 | 差异会消失，但宿主仍然无法自建连接；连接侧继续做插件管理的事，下一种接法又会再写一份 |
| 连接插件写成配置里的一行，运行时声明引用它 | 把连接细节暴露给写配置的人；换连接方式要改配置 |
| 每条连接提供一个按连接 id 命名的服务，loader 观察服务出现 | id 由对方自报，会占用应用的服务键；还需要一套观察服务出现的新机制。改为远程插件层提供登记处，连接插件依赖它，是普通的依赖关系 |
| 连接插件自己完成 rutis 握手，交出会话 | 每个连接插件都要实现协议版本与能力核对，规则会分叉；改为只交消息通道，握手统一在远程插件层 |
| 允许替换会话协议 | 它是 Python、Node、Bun、Go、Swift、Kotlin 各个 SDK 共同遵守的约定；要对接别的协议，在边界上写翻译插件 |
| 同时把本机运行时与节点互联纳入 | 本机运行时有自己的拉起与兼容协议，节点互联的 link 已经是提供服务的模式；放进来会扩大范围，各自另议 |

## 五、影响

- 远程运行时的规则只剩一份，连接方向不再影响插件的行为。
- 宿主持有者获得一个窄的扩展点：写一个连接插件，交出消息通道。
- 不兼容：Rust API 移除接入点、`RuntimeAccessPlugin`、`RuntimePlugin::remote` 等；`rutis-host` 输出前缀和若干出错方式改变。配《迁移到 0.19》。
- 旧设计中运行时接入的连接部分标为已取代，其余部分保留，对照见设计稿 §十一。
