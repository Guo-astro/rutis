## 1. The problem

A host owner builds deskmate ([evaluation report](https://github.com/arcships/rutis/issues/663#issuecomment-6411076725)): a Rust host that provides, with `#[rutis::service]`, `notes` (`put(key, value: String)`, `get(key) -> Option<String>`) and `tools` (`register(name, description, handler)`, where `handler` is `Fn(String) -> BoxFuture<Result<String, ToolError>>`), for third parties to write plugins in TypeScript or Python. Stuck in three places:

1. **No Python types**; the host hand-wrote a Protocol.
2. **Tests pass, the host fails**: passing a number to `notes.put`, a handler returning `undefined`, a `handler` that is not a function, a plugin also providing `notes`. The host hand-wrote about 160 lines of strict fakes (one in TS, one in Python).
3. **The declarations show rutis**: the header `Generated by rutis-bridge (build::Exports) …`, the error interface `RustError`.

## 2. What the real host reports, and who finds it

| Case | Real host (today) | After this design, where the plugin author sees it |
| --- | --- | --- |
| Wrong argument type or count | `bad-argument` | TypeScript: `tsc`; Python: `pyright` (this design generates the Python types) |
| An argument that should be a function is not | `bad-value` | same |
| A handler's result has the wrong type | serde decoding fails when the host calls it | same |
| Calling a method the host does not have | `no-method` | same |
| The plugin `ctx.provide`s a name the host provides | refused (as Cordis's `service "notes" has been registered`) | the test tool (H4): it refuses `provide` of a name already in `services` |

Type checking finds the first four. TypeScript has declarations already; Python lacks types, so they are generated. The fifth is the test tool itself disagreeing with the real host (and with Cordis); it is fixed directly.

## 3. Decisions

| # | Decision | Section |
| --- | --- | --- |
| H1 | From the inference the TypeScript uses, the generator writes one more thing: a Python types module. `Exports` gains `.python(file)`; `rutis-host types` gains `--python <file>`. Without the new option the output is byte for byte as today | 4 |
| H2 | Python types: services are `Protocol`s, structs `TypedDict`s, enums of names only `Literal`s; Python 3.10 is supported; `.declared_python(path, py)` matches the existing `.declared` | 4.2 |
| H4 | The test tool refuses a plugin's `provide` of a name already in `services`, as the real host and Cordis do | 5 |

(H3, H5 and H6 are removed; see "Out of scope".)

## 4. What is generated

### 4.1 How

```sh
rutis-host types . -o types/deskmate.d.ts --python types/deskmate.py
```

In `build.rs` likewise: `Exports::new().typescript(…).python(…)`. `.generate()` needs at least one output.

### 4.2 Python types

One to one with the existing TypeScript: `Option<T>` → `T | None`; `Vec<T>`, `HashMap<String, T>`, tuples → `list`, `dict[str, T]`, `tuple`; integers / floats → `int` / `float`; `serde_json::Value` → `Any`; optional fields go into a `total=False` base class (3.10 has no `NotRequired`); enums with data are a `Union` of `TypedDict`s; callback parameters are `Callable[[A], R | Awaitable[R]]`; `rutis::Definition` is `rutis.Plugin`; error codes are `Literal[…]`, and the error interface is an alias of `rutis.RemoteError`.

Plugin authors write `notes: Notes = ctx.use("notes")`, checked by the editor or pyright; without the annotation it runs the same (`ctx.use` takes no type parameter, so there is no `Services` table). A `.declared` type without a Python version is written as `Any` with a warning; the evaluation's host used `.declared` for a transparent wrapper type, so `.declared_python` is needed. The test of `examples/marked-services` checks that the generated `.py` is current and passes `pyright --strict`, as it does today for the `.d.ts` with `tsc --strict`.

## 5. The test tool

- `provide` of a name already in `services` is refused: `PluginTestError: wordcount: notes is already provided by the host` (H4, by default, in both the Node and the Python test tool).
- The fakes are still plain objects in `services`; the test tool does not check calls to them. `tsc` / `pyright` check their types.

## 6. What developers see

**Host owner**

```text
$ rutis-host types . --python types/deskmate.py
warning: notes::Text has no Python type: declare it with .declared_python (written as Any)
```

**Plugin author**

| What they wrote | What they see |
| --- | --- |
| TypeScript: `await notes.put('k', 42)`, then `tsc` | `error TS2345: Argument of type 'number' is not assignable to parameter of type 'string'.` |
| Python: `await notes.put("k", 42)`, then `pyright` | `error: Argument of type "Literal[42]" cannot be assigned to parameter "value" of type "str" in function "put"` |
| The plugin `ctx.provide('notes', …)`, the test gives `services: { notes }` | `PluginTestError: wordcount: notes is already provided by the host` |

## 7. Compatibility

- Without the new option, the output of `rutis-host types` and `Exports` is byte for byte unchanged.
- The one change in behaviour is H4: a test that gives `notes` while the plugin also provides `notes` passed before and fails now — in the real host it always failed. It goes in the release notes, not in "Migrating to 0.19".
- The protocol, the kernel, the loader and the language runtimes do not change.
