## 3. Fields and status

| Field | Meaning | Written by |
| --- | --- | --- |
| id | see §2 | script (register rows), hand (trace rows), issue (protocol rows) |
| current source | the specification, design or user document and section in force; register rows name `guarantees.md §<section>` plus the register's own source column | script |
| plain-language promise | what a user observes: success, failure, scope and recovery; register rows use the register's content column verbatim | script / hand |
| level | core commitment, contractual behaviour, explicit non-guarantee (quality standard §3) | script / hand |
| scope | the implementations (Rust, Node, Bun, Python, Go, Swift, Kotlin), transport and platform | **to fill**: the register does not record it, so all 219 register rows say `未登记`; trace rows say what the document says; protocol rows carry the issue's **participants** (`跨进程`, `进程内并发`, `纯逻辑`, `外部`), not an implementation matrix |
| evidence | model, test, trace, property/fuzz, black-box or timing evidence, as a path, test name or line range | script (register's verification column verbatim) / hand; protocol rows use the issue's `现有形式化` column |
| mutation or counterexample | a bug the verification caught, or an injected error | **to fill**: register rows say `未登记`; protocol rows say `未登记` (the issue has no such column), and a row raised by an upgrade writes its mutation in `upgrade.mutation` of `tools/formal-trace-semantic.mjs`; the mutations §4 of the trace contract describes are on their rows |
| status | `已验证`, `部分验证`, `未验证`, `明确不保证`; `已撤回` and `不单独计数` are not counted | script (register rows; protocol rows from the [re-check](recheck-0.22.md)) / hand |
| gap | the next issue; an uncovered rule is never written as passing | register rows start from the register's notes column; protocol rows combine the issue, the note and the reason a `已覆盖` row was downgraded |

Explicit non-guarantees follow the register's convention (as `core/D15` does): level and status are both `明确不保证`, and they are not counted as unverified. The 9 rows from §1 of the trace contract are registered this way, and so is `TRC-GREET-3`, because no implementation has an entry point for required capabilities (#1111). A model passing marks only the model; a rule is `已验证` only with implementation evidence. A trace row is `部分验证` only when a named test asserts a point of it; source code or comments alone leave it `未验证`.

**Protocol rows (`rules/protocol-*.md`).** The files keep the issue's ten columns and status words; the script maps them to the nine columns at read time, downwards only:

| Issue status | Table status | Rule |
| --- | --- | --- |
| 已覆盖 | 已验证 / 部分验证 | `已验证` only when `手段` names an implementation check (`K`, `PT`, `FZ`, `TV`, `SH`, `KANI`, `测试`), `现有形式化` names something, and every file it names resolves in the current tree. TLA/model-only, no named evidence, or a missing file is `部分验证` |
| 部分 | 部分验证 | never raised because the issue says "partial" |
| 未覆盖 | 未验证 / 明确不保证 | the 6 rules whose text itself says "明确不保证" become `明确不保证`; the rest are `未验证` |
| 不适用 | 明确不保证 / 不单独计数 | the 35 whose note says "明确不保证" become `明确不保证`; the other 214 are tests only, formalization cannot reach them, and become `不单独计数` with the reason in the gap |
| 明确不保证 | 明确不保证 | level and status agree |
| 未登记 | 未验证 | the gap says "未登记（测试里用了、登记表没有）" |
| 已取代 | 已撤回 | the row is kept, not counted |

Nine-column alignment: id=`编号`; current source=`来源`; promise=`规则`; level=`明确不保证` or `契约行为` (the issue has no level column, so nothing is claimed as a core commitment); scope=`参与方`; evidence=`现有形式化`; mutation=`未登记`; status=the mapping above, then the re-check; gap=`归属 issue` + `备注` + the downgrade reason. The `对应` column stays in the protocol file as the cross-reference to a guarantee-register id and is not one of the nine.

**Re-check layer (2026-11-11, evidence-backed upgrades added 2026-11-17).** The issue mapping is the ceiling, not the final status. Every protocol row also passes the four checks of the [re-check page](recheck-0.22.md) §1: the source still exists, a current anchor (a `SESS-*` id) where the session specification covers it, the named evidence resolves, and the register did not withdraw the row. It moves down, except for an `upgrade` whose target is `verified`, whose source is `unverified` or `partial`, and which names resolving evidence and a mutation: mechanisms 0.19 / 0.22 removed (compat, `events-v2`, `sync-wait`, node `export` / `import`, `Registration`, the access point, `Revocations`, `PeerRows`, `peer:` rows, `runtimes.remote`, `Transport`, `ChannelInfo`) and rows the register withdrew become `已撤回`; a row whose current source is a historical design and has no current anchor is no longer `已验证`. Row text is not rewritten; `rules/protocol-*.md` keeps the issue's ten columns verbatim.

**Language.** The register-driven rows are generated from the Chinese register; the hand-written columns are Chinese only. The `TRC` rows have an English per-row re-extraction in [recheck-0.22.en.md](recheck-0.22.en.md). The English register (`docs/guarantees.en.md`) carries the same ids, so the rows line up; the English rows of the protocol partitions are still a gap (#634). Counts are printed by the script and kept in [the Chinese README](README.md) §4: 1825 rows, 219 register, 54 hand-written, 1552 protocol. The "264 rows" in plan §1/§5 is the count before the protocol list went in; the script output is authoritative.

## 4. Maintenance

- **After changing the register or adding a test**: `node tools/formal-trace.mjs --write`, then `--check`. `--write` rewrites the automatic columns, keeps the manual ones by id, refreshes the index and the re-check page; it does not touch `rules/protocol-*.md`.
- **Changing the protocol list**: export the table from the matching #634 comment again, keeping the ten columns, ids and notes; do not hand-edit the status in the export. `--check` verifies the ten columns, the id form, the per-section totals (156/9, 218/0, 253/9, 246/104, 264/45, 231/17; 1368/184 in total), the issue status vocabulary, duplicate ids and evidence paths.
- **Changing a current source or a re-check verdict**: edit `SOURCES`, `ANCHORS`, `SUPERSEDED` or `UNMAPPED` in `tools/formal-trace-recheck.mjs`, then `--write`. `--check` verifies the anchors exist in `docs/protocol-session.md`, the superseded ids are protocol rows, each `by` file exists, and the page matches the generator.
- **Changing a re-extracted `TRC` row**: change `rules/trace-contract.md` and the entry with the same id in `tools/formal-trace-semantic.mjs` (English rule, English gap, source section, anchors), then `--write`. `--check` verifies that the ids match one to one, that every anchor is in `docs/protocol-session.md` and named in the row's 现行来源, that every source section exists in its document, that a row without anchors gives a reason, and that the Chinese §5 table and the English page are generated.
- **Changing a re-extracted `registry-1` or `registry-2` row**: edit `SEMANTIC_REGISTRY` or `SEMANTIC_REGISTRY_2` in `tools/formal-trace-semantic.mjs`; do not edit `rules/protocol-registry-1.md` or `rules/protocol-registry-2.md`, which are the issue exports. Each entry gives the source section, the register anchor, the evidence, the status and a reason in both languages, then `--write`. `--check` verifies that the 165 and 218 rows match one to one, that each anchor is a row of `guarantees.md` under the named section, that every evidence path exists and every named test is defined in it, that the status equals the re-checked status, that a row without anchors gives a reason, and that both generated pages agree.
- **Changing a re-extracted `session` row**: edit `SEMANTIC_SESSION` in `tools/formal-trace-semantic.mjs`; do not edit `rules/protocol-session.md`, which is the issue export. Each entry gives the source section, the anchor (a `SESS-*` id or a register row), the evidence, the status and a reason in both languages; a rule no current document states says `0.22 无此条` (with `sourceEn`) and carries no anchor. Then `--write`. `--check` verifies that the 350 rows match one to one, that every `SESS-*` id is in the specification, that every register anchor sits under the named register section, that every source section exists in its document, that every evidence path exists and every named test is defined in it, that the status equals the re-checked status, that a row without anchors or without a current source gives a reason, and that both generated pages agree.
- **Changing a re-extracted `events` row**: edit `SEMANTIC_EVENTS` in `tools/formal-trace-semantic.mjs`; do not edit `rules/protocol-events.md`, which is the issue export. Each entry gives the source section, the anchor (`EVP` / `EVD` section or decision number, a `SESS-*` id, a register row), the evidence, the status and a reason in both languages; a rule no current document states says `0.22 无此条` (with `sourceEn`) and carries no anchor. Then `--write`. `--check` verifies that the 262 rows match one to one, that every `EVP` / `EVD` anchor exists in its document (a heading, a chapter sub-heading such as `§三.1`, or a decision list item such as `§15.28`), that every `SESS-*` id is in the specification, that every register anchor exists, that every source section exists in its document, that every evidence path exists and every named test is defined in it (`.tla` by invariant name, `.json` by case name), that the status equals the re-checked status, that a row without anchors or without a current source gives a reason, and that both generated pages agree.
- **Changing a re-extracted `runtime` row**: edit `SEMANTIC_RUNTIME` in `tools/formal-trace-semantic.mjs`; do not edit `rules/protocol-runtime.md`, which is the issue export. Each entry gives the source section, the anchor (a register row or a `SESS-*` id), the evidence, the status and a reason in both languages; a row with no current source says `0.22 has no such rule` and carries `sourceEn` and no anchor. - **Adding a `TRC`/`ECA` row**: write it in `rules/` with the same columns; `--check` verifies the id form, the status vocabulary and the evidence paths.
