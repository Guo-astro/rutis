## 一、现象

宿主持有者做了 deskmate（[评估报告](https://github.com/arcships/rutis/issues/663#issuecomment-6411076725)）：Rust 宿主用 `#[rutis::service]` 提供 `notes`（`put(key, value: String)`、`get(key) -> Option<String>`）和 `tools`（`register(name, description, handler)`，`handler` 是 `Fn(String) -> BoxFuture<Result<String, ToolError>>`），交给第三方用 TypeScript 或 Python 写插件。卡在三处：

1. **Python 没有类型**，宿主手写了 Protocol。
2. **测试通过，装进宿主却失败**：给 `notes.put` 传数字、处理函数返回 `undefined`、`handler` 不是函数、插件自己也提供 `notes`。宿主手写了约 160 行严格假服务（TS、Python 各一份）。
3. **声明里露出 rutis**：文件头 `Generated by rutis-bridge (build::Exports) …`，错误接口叫 `RustError`。

## 二、真实宿主已经报什么，谁来查

| 情况 | 真实宿主（现在） | 本稿之后，插件作者在哪里看到 |
| --- | --- | --- |
| 参数类型或个数不对 | `bad-argument` | TypeScript：`tsc`；Python：`pyright`（本稿生成 Python 类型） |
| 该是函数的参数不是函数 | `bad-value` | 同上 |
| 处理函数的结果类型不对 | 宿主调用它时 serde 解码失败 | 同上 |
| 调用宿主没有的方法 | `no-method` | 同上 |
| 插件 `ctx.provide` 宿主已经提供的名字 | 拒绝（与 Cordis 的 `service "notes" has been registered` 相同） | 测试工具（H4）：对 `services` 里已有的名字拒绝 `provide` |

前四项由类型检查查出，TypeScript 已有声明，Python 缺的是类型，所以生成 Python 类型。第五项是测试工具本身和真实宿主（以及 Cordis）不一致，直接修。

## 三、决策

| # | 决策 | 章节 |
| --- | --- | --- |
| H1 | 生成器从 TypeScript 用的同一份推导结果多写一样：Python 类型模块。`Exports`（0.19 起在 `rutis-types`，见[平台清理](design-platform-cleanup-2026-10-28.md) §八）加 `.python(file)`；`rutis-host types` 加 `--python <file>`。不给新选项时输出与现在逐字相同 | 四 |

| H4 | 测试工具对 `services` 里已有的名字拒绝插件的 `provide`，与真实宿主和 Cordis 一致 | 五 |

（H3、H5、H6 已删，见"范围外"。）

## 四、生成什么

### 4.1 怎样生成

```sh
rutis-host types . -o types/deskmate.d.ts --python types/deskmate.py
```

`build.rs` 里同样是 `rutis_types::Exports::new().typescript(…).python(…)`（构建依赖 `rutis-types`；0.18 是 `rutis_bridge::build::Exports`）。`.generate()` 至少要有一种输出。

### 4.2 Python 类型

与现有 TypeScript 一一对应：`Option<T>` → `T | None`；`Vec<T>`、`HashMap<String, T>`、元组 → `list`、`dict[str, T]`、`tuple`；整数 / 浮点 → `int` / `float`；`serde_json::Value` → `Any`；可省略的字段放进 `total=False` 的父类（3.10 没有 `NotRequired`）；带数据的枚举是 `TypedDict` 的 `Union`；回调参数是 `Callable[[A], R | Awaitable[R]]`；`rutis::Definition` 是 `rutis.Plugin`；错误码是 `Literal[…]`，错误接口是 `rutis.RemoteError` 的别名。

插件作者写 `notes: Notes = ctx.use("notes")`，由编辑器或 pyright 检查，不写也照样运行（`ctx.use` 不带类型参数，所以不生成 `Services` 总表）。`.declared` 的类型没有 Python 版本时写 `Any` 并警告；评估里的宿主为透明包装类型用了 `.declared`，所以需要 `.declared_python`。示例 `examples/marked-services` 的测试检查生成的 `.py` 是最新的并通过 `pyright --strict`，与现有的 `.d.ts` + `tsc --strict` 一样。

## 五、测试工具

- `provide` 的名字已在 `services` 里时拒绝：`PluginTestError: wordcount: notes is already provided by the host`（H4，默认就做，Node 与 Python 两个测试工具都做）。
- 假服务仍是 `services` 里的普通对象，测试工具不检查对它的调用；调用的类型由 `tsc` / `pyright` 查。

## 六、开发者看到什么

**宿主持有者**

```text
$ rutis-host types . --python types/deskmate.py
warning: notes::Text has no Python type: declare it with .declared_python (written as Any)
```

**插件作者**

| 写了什么 | 看到的文字 |
| --- | --- |
| TypeScript：`await notes.put('k', 42)`，运行 `tsc` | `error TS2345: Argument of type 'number' is not assignable to parameter of type 'string'.` |
| Python：`await notes.put("k", 42)`，运行 `pyright` | `error: Argument of type "Literal[42]" cannot be assigned to parameter "value" of type "str" in function "put"` |
| 插件 `ctx.provide('notes', …)`，测试给了 `services: { notes }` | `PluginTestError: wordcount: notes is already provided by the host` |

## 七、兼容

- 不给新选项时，`rutis-host types` 与 `Exports` 的输出逐字不变。
- 唯一的行为变化是 H4：测试给了 `notes`、插件又提供 `notes`，以前测试通过，现在失败——装进真实宿主本来就失败。写进更新说明，不进《迁移到 0.19》。
- 协议、内核、loader、各语言运行时不变。
